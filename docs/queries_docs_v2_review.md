# 자연어 평가셋 v2 — 검토용 초안

기존 v1 키워드 평가셋은 그대로 유지했다. 이 문서는 새 질문 **40개**와 무응답 검토
질문 **8개**를 읽기 쉽게 펼친 스냅샷이다. **새 검색 실험은 실행하지 않았다.**
모든 질문의 사람 검수 상태는 `pending`이다.

## 구성과 검토 기준

- 표현 변경 12개: 문서 제목·고시 번호 대신 사용자의 표현으로 정보 요청.
- 상황 설명 22개: 신청자·수출자·기업이 실제 조건을 확인하는 질문.
- 복수 근거 6개: 서로 다른 사실을 두 개 확인해야 답할 수 있는 질문.
- 별도 무응답 8개: 모집/신청 안내만으로 실제 결과·현재 예산·개별 판정을 답할 수 없는 경우.

자연스러운 업종·제도 용어와 필요한 연도는 남겼다. 키워드를 무조건 지우면 질문이
모호해질 수 있기 때문이다. 실제 사용자의 말투인지, 단서가 부족해 여러 제도에 해당하는지,
정답 문서가 빠졌는지, 참고 답안의 내용까지 인용으로 뒷받침되는지를 검토해 달라.

정답/근거의 원본은 [queries_docs_v2.jsonl](../data/queries_docs_v2.jsonl)이다.
아래 체크는 검토 메모이며 JSONL을 자동 수정하지 않는다. 실험에 반영할 수정은 JSONL에
적용하거나 해당 qid와 수정안을 알려 주면 된다. 인용은 읽기 쉽게 HTML·공백을 정리했으며
기계 검증에는 JSONL에 보존된 원문 그대로를 사용한다.

## 실험 실행

파일과 인용만 검증하기(OpenSearch/Ollama 호출 및 검색 없음):

```bash
cd /Users/jeongbin/git/searchEngine
.venv/bin/search-compare data/queries_docs_v2.jsonl \
  --corpus data/generated/docs-v1/docs.jsonl --validate-only
```

검토 후 세 방식 비교:

```bash
.venv/bin/search-compare data/queries_docs_v2.jsonl \
  --corpus data/generated/docs-v1/docs.jsonl \
  --alias search-docs-only --repeats 3 --as-of 2026-09-16 \
  --out data/generated/docs-v2/comparison.json
```

검색 경로·인덱스·후보 설정은 기존 실험과 같다. 실험 결과는 새 경로에 쓰므로 v1 결과를
덮어쓰지 않는다. CLI는 JSONL의 SHA-256과 코드·코퍼스 체크섬을 기록한다.
`--validate-only`는 정답과 인용의 파일 일치만 검사하며 실제 클러스터 일치는 검사하지 않는다.

## 지표 해석

- 기존 `recall_at_k`: 정답으로 표시한 물리 부모 파일 중 찾은 비율.
- `group_recall_at_k`: 같은 시행령의 다른 포맷 등 대체 가능한 파일 그룹을 하나로 보고
  찾은 비율. 동일 그룹의 여러 복사본을 찾아도 추가 점수를 주지 않는다.
- `evidence_recall_at_k`: 답에 필요한 사실 그룹 중 실제 반환 청크가 뒷받침한 비율.
  겹침 청크나 같은 내용의 다른 포맷은 대체 근거로 인정한다.
- `evidence_all_at_k`: 답에 필요한 모든 사실의 근거를 확보한 질문의 비율.
- JSON의 `categories`에서 질문 유형별 결과를 확인한다. 단일 합계만으로 비교하지 않는다.

현재 검색은 부모 문서마다 대표 청크 하나만 반환한다. 한 문서에서 서로 다른 두 청크가
필요한 질문은 문서 Recall이 높아도 근거 Recall이 낮을 수 있다. 이 지표는 **최종 반환
청크** 기준이며 원래 BM25/벡터 후보 전체의 청크 Recall이나 생성 답변의 사실성 평가는 아니다.
정답이 사람이 전체 코퍼스에서 완전 판정된 것은 아니므로 모든 Recall은 현재 표시된
정답 범위 기준이다. 새 실험 전에 사용자가 문서/근거 누락을 검토하는 것이 중요하다.

AI가 원문 근거를 작성한 개발용 초안이며, 독립된 운영 승인 평가셋은 아니다. v1 결과는
이미 알고 있었으므로 v2를 블라인드 평가셋이라고 부르지 않는다. 검토 완료 후 질문과 정답을
동결하고 검색/모델을 바꾸며 실험한다. 결과를 보고 정답을 고치면 점수가 오염될 수 있으므로,
필요한 정답 수정은 별도 버전으로 기록한다. JSONL 수정 후 manifest의 체크섬도 갱신해야 한다.
