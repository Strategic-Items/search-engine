# 미사용 메타데이터 활용 검토 — 2026-10-06

## 확인 범위와 집계

최신 파서 JSONL과 현재 OpenSearch 별칭을 직접 읽었다. 필드가 존재하는지만 세지 않고 null·빈 문자열·빈 목록·빈 객체를 제외했다. 문서 수는 parent_id로 중복 제거하고, 문서 안 어느 청크에라도 값이 있으면 포함했다. 0번 행 번호 등 숫자 0은 유효한 값으로 센다. 검색 성능 비교 실험은 하지 않았다.

| 자료 | 최신 파서 문서 / 청크 | 현재 검색 문서 / 청크 |
|---|---:|---:|
| 법령·고시 | 100 / 4,633 | search-law: 50 / 2,160 |
| 행정·업무 | 20 / 183 | search-admin: 20 / 183 |
| 민원FAQ | 19 / 187 | 해당 카테고리의 운영 별칭 없음 |
| 통합 core | 이번 파서 집계 대상 아님 | search-documents: 612 / 3,956 |
| docs-only | 이번 파서 집계 대상 아님 | search-docs-only: 52 / 1,198 |

현재 법령 인덱스의 50문서는 모두 최신 파서 100문서에 포함되어 있다. 추가 50문서는 현재 search-law에 없다. 파서 100문서 전체는 gate=passed 90문서 / failed 10문서다. 추가 자료의 포함 여부는 데이터 선택·품질 기준에 따라 결정해야 한다. 이번 확인에서는 재색인하거나 검색 동작을 바꾸지 않았다.

부모 상속값을 단순 합산할 때 번호의 커버리지는 12→29문서, 기관은 20→36문서, 상태는 21→38문서로 늘어난다. 이는 판본 검증 전의 잠재 커버리지다. 바로 직접 속성으로 덮어쓰면 안 되며 직접값과 상속값·상속 근거를 구분해야 한다.

## 이미 사용하지만 연결이 불완전한 superseded_by

superseded_by 자체는 미사용 필드가 아니다. BM25의 대체되지 않은 문서 +4, 새 판 추가, 답변 머리말에 사용한다. 문제는 데이터 형식과 추론 신뢰도다.

- 현재 법령 인덱스: 11문서 / 871청크에 값이 있다.
- 2문서는 실제 parent_id를 가리킨다.
- 9문서는 parent_id가 아니라 고시·대통령령 번호를 가리킨다. `_current_editions`는 parent_id에 대한 terms 조회만 하므로 이 9문서는 현재 코드로 새 판을 추가할 수 없다.
- 그 9문서의 번호 중 8문서는 현재 인덱스에서 대상 문서가 1개이고, 1문서는 대상 문서가 2개다. 번호를 ID로 변환할 때 중복 후보와 판본을 확인해야 한다.
- 11문서의 관계 추출 근거는 모두 inferred:same_title이다. 관계가 기록되었다고 해서 확정된 폐지·대체 사실로 표시해서는 안 된다.
- 최신 파서 100문서: 대체 관계 22문서, ID 대상 6문서, 번호 대상 16문서. 최신 자료와 현재 인덱스에서는 관계의 다음 판이 달라진 사례도 있어 옛 인덱스의 관계만 유지하면 최신판에 도달하지 못할 수 있다.

따라서 이 항목은 가산점을 새로 붙이는 실험보다, 원본 관계와 검색용 resolved parent ID를 분리하고 관계 근거·모호성을 보존하는 정리가 먼저다.

## 우선순위가 낮거나 현재 데이터가 부족한 후보

- effective_to: 법령·행정·FAQ에서 0문서. 종료일 필터 코드는 이미 있으므로 필터 추가보다 데이터 확보가 필요하다.
- revision_date: 법령 현재 10문서 / 최신 파서 18문서. 다른 문서끼리 최신 날짜만으로 순위를 올리는 것은 질문 관련성과 별개다. 같은 규정·판본 묶음 안에서만 후보로 검토한다.
- issuer: 법령 현재 20문서, 행정 2문서. 기관이 명시된 질문에서 제한적인 우대는 가능하나 기본 전역 가산점으로는 추천하지 않는다.
- codes_exact / code_norm: 법령·행정·FAQ에서는 원본 code가 0문서라 곧바로 사용할 수 없다. 통합 core에는 codes_exact가 268/612문서에 있고 조문 번호도 포함되어 있다. core의 식별자 질문에는 별도 실험 가치가 있으나 법령 카테고리 데이터와 혼동하면 안 된다.
- content_hash: 값은 있어도 청킹과 파일 형식 차이로 같은 문서의 해시가 달라질 수 있다. 이를 추가하는 것만으로 문서 사본 정리를 대체하지 않는다.
- gate: 검색 법령 1/50문서와 행정 1/20문서가 failed로 보존되어 있다. 파서 품질 실패가 모든 질문에 쓸 수 없는 문서라는 뜻인지는 실패 사유를 확인해야 한다. 일괄 제거보다 근거 품질 점검과 표시부터 검토한다.

## 권장 작업 순서

1. 최신 파서와 현재 검색 인덱스의 선택 범위를 확인하고 대체 관계를 실제 문서 ID로 해소한다. 추론 관계는 별도로 표시한다.
2. 표·대비표 질문에서 table_id와 article을 이용한 근거 보완을 먼저 비교한다. 문서 검색 순위와 답변 근거 회수를 분리해 평가한다.
3. 질문에 명시된 번호·유형·판본에 한해 조건부 우대를 시험한다. 값 없는 문서를 자동으로 제외하지 않는다.
4. 페이지와 속성 추출 근거를 응답·원문 검토 화면에 노출한다.

순위 우대는 문서를 제거하는 필터와 구분해야 한다. OpenSearch의 function_score는 반환 대상 자체보다 관련도 점수를 바꾸는 기능이다: https://docs.opensearch.org/latest/query-dsl/compound/function-score/
