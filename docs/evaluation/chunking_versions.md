# 청킹 버전 기록

청킹 **단계**(한 번의 변경과 측정)는 [성능 이력의 청킹 단계](performance_history.md#청킹-단계)에, 이 문서는 그 안의 코드 **버전**별 숫자를 둔다.
v0 -> v1이 [청킹 1단계](chunking-stages/stage-01-move-chunking-to-search-engine.md)다.

청커나 정책을 바꿀 때마다 한 줄씩 남긴다. 각 버전의 JSON은 `chunking_versions/v<N>.json`, 만드는 법은
`scripts/chunking/record_chunking_version.py`. 정답 청크 반환은 서비스 인덱스의 공식 라벨(청크 ID)을 각 청킹의 청크로 옮기고 필수 구절을 담은 청크를 더하는 규칙을 모든 버전에 똑같이 적용해 센 값이고
(`scripts/chunking/eval_category_chunking.py --reference`; 글이 80% 이상 겹치는 같은 문서의 청크를 같은 근거로 본다; 기준 인덱스에도 같은 규칙), **서비스 컷오프**는 기록 시점의 서비스 설정, 0.95는 이전 기준이다.
법령 150문항 중 평가 대상 149문항(정답 근거가 불완전한 053 제외) 기준이고 149는 질문 수다.
v0과 v1은 같은 청커가 아니다(규칙 74개 시기 vs 파서 #129의 규칙 20개 삭제 뒤). 차이의 원인을 단계별로 나눈 것과 라벨 방식의 경위는
[설계 문서](../design/chunking_ownership_move.md#v0--v1-비교의-상황과-경위-2026-10-08)에 있다.

| 버전 | 날짜 | 요약 | 법령 청크 | 법령 정답 청크 반환 (서비스 / 0.95) |
|---|---|---|---:|---|
| v0 | 2026-10-08 | 서비스 인덱스 search-law — 파서 규칙 74개 시기의 청킹(기준) | 6,288 | 145 / 140 (/149) |
| v1 | 2026-10-08 | 검색엔진 이식 청커 — 파서 #129 규칙 20개 삭제 뒤, 번들 마크다운 입력 | 6,503 | 139 / 137 (/149) |
| v2 | 2026-10-08 | v1에서 표 칸 줄바꿈 <br>을 공백으로 잇는다 | 6,503 | 142 / 138 (/149) |
| v5 | 2026-10-12 | 제목 메타데이터와 짧은 절 경계 보존 | 6,517 | 143 / 141 (/149) |

## v1 — 검색엔진 이식 청커 — 파서 #129 규칙 20개 삭제 뒤, 번들 마크다운 입력 (2026-10-08)

파서 청커를 `search_engine/chunking`으로 이식(삭제 20개 반영, `ChunkPolicy` 기본값 = 파서 값). 입력은 번들 `text.markdown`에서 되살린 원소·표다. 같은 코드를 파서의 원래 원소·표 자료에 쓰면 파서 슬림판 청크와 189문서 모두 같고, 검색 결과도 슬림판(원소 입력)과 합계가 같다. 정답 청크는 v0과 같은 규칙으로 정했다. 서비스 컷오프 0.7에서 v0 대비 -6(145 -> 139), v1만 반환한 질문은 없다. 놓친 6개: 검색이 놓친 것 033·120·130, 필수 구절이 한 청크에 더는 모이지 않아 정답 라벨이 사라진 것 103·128·143. 103·128은 디스크의 옛 docs.jsonl 코퍼스에서도 사라지므로 청커가 아니라 서비스 인덱스와 번들의 코퍼스 내용 차이에서 온다. 청커 규칙 삭제 탓으로 보이는 것은 033·120·130·143이며 별표·표 서식 질문 중심이고 파서 #129가 예고한 증상이다. 컷오프 0.95에서는 v0 대비 -3(140 -> 137), 058이 새로 반환된다.
