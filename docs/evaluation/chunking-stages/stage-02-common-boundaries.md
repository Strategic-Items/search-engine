# 청킹 2단계: 제목 메타데이터와 짧은 절 경계 보존 (2026-10-12)

긴 문단의 첫 청크에 붙인 제목의 페이지와 원소 종류가 빠지던 문제를 고치고, 짧은 본문이 다음 독립 절의 제목 경로를 물려받지 않도록 했다. 문서별 표현을 추가하지 않고 기존 제목 수준과 이미 인식한 부속 경계를 사용한다. 청커 버전은 v5다(v3·v4의 기존 보관 실험을 덮어쓰지 않는다).

현재 설정에서 수정 전 v2와 수정 후 v5를 각각 새 실험 인덱스에 색인해 비교했다. 법령 149문항·행정 30문항의 정답 근거 반환, 정답 문서 적중, 필수 구절 반환은 모두 동일했다. 이번 평가에서 검색 정확도 향상은 없었고, 관측된 퇴행도 없었다. 서비스 별칭에는 적용하지 않았다.

## 변경

- 긴 문단을 나눌 때 첫 조각에 포함한 제목까지 `page_start`·`page_end`·`element_types`에 반영한다. 뒤 조각에는 본문의 페이지와 종류만 기록한다.
- 현재 절에 본문이 있으면, 같은 수준 또는 상위 제목을 만날 때 길이와 관계없이 절을 닫는다. 이미 인식된 부칙·붙임 등 독립 부속 경계에서도 본문을 먼저 닫는다.
- 제목만 연속되는 경우와 하위 제목 앞의 짧은 소개문은 기존처럼 연결한다. 제목만 있는 문서 끝을 처리하는 변경은 포함하지 않았다. 표 처리와 FAQ 판별 규칙도 변경하지 않았다.

## 전후 예시

### 짧은 문서 머리말과 첫 조문

실제 법령 코퍼스의 「대외무역법」 사례다. 이전에는 법 제목·시행일과 제21조 본문이 한 청크에 들어가면서, 청크 경로 전체가 제21조로 지정됐다.

```text
수정 전 — 청크 0
경로: 제21조 (전략물자의 고시 및 수출허가 등)
본문: [대외무역법] / 2007. 4. 4. 시행 / 제21조 ... / ① 산업자원부장관은 ...
```

수정 후에는 짧은 머리말을 먼저 닫고, 첫 조문은 별도 청크로 시작한다. 그래서 법 제목이 제21조의 경로를 물려받지 않는다.

```text
수정 후 — 청크 0
경로: [대외무역법]
본문: [대외무역법] / 2007. 4. 4. 시행

수정 후 — 청크 1
경로: 제21조 (전략물자의 고시 및 수출허가 등)
본문: 제21조 ... / ① 산업자원부장관은 ...
```

### 긴 문단 첫 조각의 페이지·원소 종류

아래는 경계 조건 테스트를 단순화한 예다. 이전에는 청크 본문에 앞 제목을 포함하면서도 메타데이터는 긴 문단만 가리켰다. 수정 후 첫 조각은 제목과 본문을 모두 반영한다.

| 상태 | 본문 | 페이지 | 원소 종류 |
|---|---|---|---|
| 수정 전 첫 청크 | `제목 + 긴 문단 첫 조각` | `3~3` | `paragraph` |
| 수정 후 첫 청크 | `제목 + 긴 문단 첫 조각` | `1~3` | `heading, paragraph` |
| 수정 후 다음 청크 | `긴 문단 다음 조각` | `3~3` | `paragraph` |

짧은 제1조 본문 뒤에 제2조가 나오는 최소 예에서는, 수정 전 한 청크에 두 조문 본문이 이어지고 경로가 제2조로 바뀔 수 있었다. 수정 후에는 제1조와 제2조가 각각 자기 경로를 가진 청크로 분리된다.

## 측정 조건

| 항목 | 조건 |
|---|---|
| 입력 | 같은 TextBundle의 법령·고시 150문서와 행정·업무 20문서 |
| 기준선 | 수정 직전에 현재 v2 코드로 다시 생성한 코퍼스 |
| 질문 | 기존 법령 150문항 중 평가 대상 149문항, 기존 행정 30문항 |
| 검색 | `eval_category_chunking.py`의 hybrid(SPLADE+dense), 청크 우선 검색, 기준일 2026-10-07 |
| 부가 처리 | LLM 필터·답변 가능성 판정·리랭커·질문 재작성 없음 |
| 인코딩 | 같은 현재 모델·설정, SPLADE 문서 최대 512토큰. 모델 및 입력이 일치하는 보관 dense 임베딩은 재사용하고, SPLADE는 현재 설정으로 다시 계산 |
| 컷오프 | 서비스 설정 0.7 및 0.95 |
| 정답 근거 | 서비스의 공식 청크 라벨을 본문 겹침으로 이전하고 필수 구절 근거를 더하는 기존 규칙을 두 팔에 동일 적용 |
| 실험 별칭 | `exp-chk-common-v5-{law,admin}-{before,after}` |

예전 v2 기록의 검색 점수와 이번 기준선 점수는 직접 비교하지 않는다. 이번 비교는 두 코퍼스를 현재 설정으로 다시 색인·평가한 상대 비교다. 변경 대상인 제목 메타데이터를 실제로 수정하는 코퍼스 사례는 이번 데이터에서 따로 확인되지 않았으며, 해당 동작은 경계 조건 테스트로 검증했다.

## 검색 결과

각 수치는 해당 조건에서 성공한 질문 수다.

| 데이터 | 컷오프 | 정답 근거 전 → 후 | 정답 문서 전 → 후 | 필수 구절 전 → 후 | 평균 반환 청크 전 → 후 |
|---|---|---|---|---|---|
| 법령 /149 | 0.7 | 143 → 143 | 146 → 146 | 140 → 140 | 7.97 → 7.97 |
| 법령 /149 | 0.95 | 141 → 141 | 146 → 146 | 137 → 137 | 3.42 → 3.42 |
| 행정 /30 | 0.7 | 30 → 30 | 30 → 30 | 30 → 30 | 9.30 → 9.30 |
| 행정 /30 | 0.95 | 28 → 28 | 30 → 30 | 27 → 27 | 3.50 → 3.50 |

두 컷오프 모두 개선·퇴행 문항 0개이며, 질문별 집계 지표도 동일했다. 1위 문서는 법령 149/149·행정 30/30에서 같았다. 근거 라벨을 이전하지 못한 법령 질문은 두 팔 모두 1개, 행정은 모두 0개다. 청크 번호는 재분할로 바뀔 수 있으므로 반환 청크 ID 자체가 동일하다는 뜻은 아니다.

### MRR

수정 전후의 순위도 확인하기 위해 MRR을 별도 계산했다. 문서 MRR@5는 반환된 상위 5개 문서 중 첫 정답 문서의 역순위 평균이다. 청크 MRR은 정답 청크 그룹과 처음 일치하는 반환 청크의 역순위 평균이며, 실제 반환된 청크 창에서 계산했다.

| 데이터 | 컷오프 | 문서 MRR@5 전 → 후 | 청크 MRR 전 → 후 |
|---|---|---|---|
| 법령 /149 | 0.7 | 0.900895 → 0.900895 | 0.826025 → 0.826025 |
| 법령 /149 | 0.95 | 0.900895 → 0.900895 | 0.827852 → 0.827852 |
| 행정 /30 | 0.7 | 0.933333 → 0.933333 | 0.736429 → 0.736429 |
| 행정 /30 | 0.95 | 0.933333 → 0.933333 | 0.752778 → 0.752778 |

네 조건 모두 MRR 차이는 0이다. 원시 결과는 `data/generated/chunking-common-v5/mrr.json`에 있다.

## 구조와 처리 시간

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 법령 청크 | 6,503 | 6,517 |
| 행정 청크 | 183 | 183 |
| 법령 30자 미만 청크 | 170 | 188 |
| 행정 30자 미만 청크 | 12 | 12 |
| 170문서 청킹 시간 중앙값 | 0.5801초 | 0.5800초 |

법령 11문서의 본문·제목·경로 구성이 바뀌었고 행정은 동일하다. 공백과 마크다운 제목 기호를 제외한 본문 글자 순서는 행정 전체에서 같았다. 법령의 차이는 두 표지뿐이다: `[별표 4]`는 본문에서 경로로 이동했고, 이전에 사라졌던 `부칙` 표지는 원본에서 복원되어 본문에 나타났다. 이 두 표지를 제외한 본문 내용·순서는 보존됐다.

처리 시간은 번들을 미리 읽고 같은 프로세스에서 수정 전·후 순서를 번갈아 6회씩 실행한 값이다. 파일 읽기·임베딩·색인·검색 시간은 포함하지 않으며, 속도가 향상됐다는 주장으로 사용하지 않는다.

## 검증과 한계

`python -m pytest tests/chunking -q`: 123개 통과. 새 테스트는 제목과 긴 문단의 페이지·종류, 짧은 본문 뒤의 같은 수준/상위 절, 독립 붙임 경계, 하위 제목 연결을 확인한다.

짧은 청크는 늘었다. 이 평가에서는 지표가 유지됐지만, 이번 변경으로 새로 분리된 짧은 절을 직접 묻는 별도 홀드아웃 평가를 추가하지는 않았다. 따라서 이번 결과만으로 다른 문서군의 성능을 보장하지 않는다. 서비스 인덱스에 연결하는 작업은 이번 범위에 포함하지 않았다.

## 산출물과 재현

- `data/generated/chunking-common-v5/`: 전후 법령·행정 코퍼스, 평가 결과·로그, 질문별 비교, 구조 비교, 시간 측정, 설정·SHA-256 manifest와 코드 패치.
- `data/chunking_artifacts/v5/`: 수정 후 법령 색인의 dense·SPLADE 포함 보관본과 코퍼스. 기존 v3·v4 보관본은 유지했다.
- [청킹 버전 기록](../chunking_versions.md): v5의 정책·코퍼스 통계·검색 결과.

```bash
.venv/bin/python -m pytest tests/chunking -q
.venv/bin/python scripts/chunking/eval_category_chunking.py \
  --queries data/queries_law150_v1.jsonl --reference search-law \
  --arm before=exp-chk-common-v5-law-before --arm after=exp-chk-common-v5-law-after \
  --out data/generated/chunking-common-v5/eval_law.json
.venv/bin/python scripts/chunking/eval_category_chunking.py \
  --queries data/queries_admin_v1.jsonl --reference search-admin \
  --arm before=exp-chk-common-v5-admin-before --arm after=exp-chk-common-v5-admin-after \
  --out data/generated/chunking-common-v5/eval_admin.json
```

검색 설정·모델 및 기준 라벨이 바뀌면 재평가 숫자도 바뀔 수 있다. 이번 설정은 산출물의 `settings.json`에 기록했다.
