# 청킹 1단계: 청킹을 파서에서 검색엔진으로 옮기고, 옮기기 전과 카테고리 검색을 비교 (2026-10-08)

청킹을 파서(`unstructured-doc-parser_ver2`)에서 검색엔진으로 옮기는 첫 단계다. 파서의 청커를 `search_engine/chunking/`으로 이식하고, 파서가 넘기는 TextBundle의 마크다운에서 원소·표를 되살려 같은 규칙으로 청킹하는 경로를 만들었다. 이 경로로 만든 법령·고시 코퍼스를 별도 인덱스에 올려 서비스 검색 경로(hybrid)로 옮기기 전과 같은 질문에 돌렸다.

**상태: 색인에는 아직 연결하지 않았다.** 서비스 `search-law`·`search-admin`과 검색 설정은 이 단계에서 바꾸지 않았다(읽기 전용 기준). 청킹 코드와 평가 도구, 버전 기록만 추가했다.

이 문서는 청킹 단계의 첫 기록이다. 검색엔진 단계(1~45)와 번호를 따로 센다: [검색엔진 단계](../performance_history.md#검색엔진-단계), [청킹 단계](../performance_history.md#청킹-단계). 단계는 "한 번의 변경과 측정"이고, 코드 버전(`CHUNKER_VERSION`)별 숫자는 [청킹 버전 기록](../chunking_versions.md)에 있다. 이 단계는 v0 → v1이다.

## 판단

- **이식은 정확하다.** 파서가 원본에서 만든 원래 원소·표 자료를 이식한 청커에 넣으면 번들 189문서 모두 파서의 청크와 글자까지 같다.
- **번들 마크다운만으로는 PDF 28개 중 13개가 어긋난다.** 표 칸 안 줄바꿈, 내보내지 않은 그림 자리, 목록 항목과 문단의 구분, 표 머리글 표시가 마크다운에 안 담긴다. 그런데 이 차이는 법령 149문항의 검색 결과에는 영향이 없었다(아래). 파서의 출력 계약 초안(`structure.json`)이 이 정보를 싣는 방향이다.
- **옮기기 전보다 법령 검색의 정답 청크 반환이 6개 줄었다**(컷오프 0.7에서 145 → 139, 0.95에서 140 → 137). 원인은 이식이 아니라 두 가지다: 파서 #129의 규칙 20개 삭제, 서비스 인덱스와 번들의 코퍼스 내용 차이.
- **이 비교는 같은 청커끼리가 아니다.** v0은 규칙 74개 시기의 청킹이고 v1은 규칙 20개를 삭제한 뒤의 코드를 옮긴 것이다. 규칙 삭제만의 효과는 아래 단계별 분해로 본다.
- **다음 측정:** 파서의 `structure.json`이 나오면 마크다운 대신 그 입력으로 같은 비교를 한다. "옮김" 22개 정책 값(청크 크기 등)은 측정 없이 바꾸지 않았고, 측정 후보로 남겼다.

## 측정 조건

| 항목 | 조건 |
|---|---|
| 코퍼스 | 법령·고시 150문서. v0 = 서비스 인덱스 `search-law-v20261008061513-3ba81c` 6,288청크, v1 = 번들 마크다운에서 이식 청커로 만든 6,503청크(별도 인덱스) |
| 질문 | `data/queries_law150_v1.jsonl` 150문항 중 정답 근거가 불완전한 053을 뺀 149문항. 149는 질문 수이고 채점은 청크 단위다 |
| 방식 | 서비스 검색 경로 hybrid(SPLADE 설정 C + dense, 청크 RRF k=60), 청크 최대 10·문서 5·문서당 6, LLM 필터·판정·리랭커·질문 재작성 없음. 기준일 2026-10-07 |
| 컷오프 | 서비스 설정 0.7과 이전 기준 0.95를 함께 냈다. 컷오프를 건 수치만 쓴다 |
| 색인 | 같은 인덱서·모델(dense: bge-m3-ko, 제목 경로 입력 / SPLADE: 설정 C)로 만든 별도 인덱스 `exp-chk-law-*`. 서비스 별칭은 건드리지 않았다 |
| 정답 청크 | 청킹이 바뀌면 청크 ID가 달라진다. 공식 정답 청크와 글이 80% 이상 겹치는 같은 문서의 청크에 필수 구절을 모두 담은 청크를 더한다. **기준 인덱스를 포함한 모든 청킹에 같은 규칙을 적용했다** |

## 결과

각 칸은 정답 청크를 반환한 질문 수(/149)다.

| | 청크 | 컷오프 0.7 | 컷오프 0.95 | 정답 문서 적중 (0.7) | 평균 반환 청크 (0.7) | 라벨을 잃은 질문 |
|---|---:|---:|---:|---:|---:|---:|
| v0 서비스 인덱스 (규칙 74개 시기) | 6,288 | 145 | 140 | 148 | 7.91 | 0 |
| 디스크의 옛 `docs.jsonl`로 만든 인덱스 | 6,272 | 142 | 140 | 148 | 7.97 | 2 |
| 파서 슬림판(규칙 20개 삭제 뒤, 원본 원소 입력) | 6,526 | 139 | 137 | 147 | 7.85 | 3 |
| **v1 이식 청커 (번들 마크다운 입력)** | 6,503 | 139 | 137 | 147 | 7.84 | 3 |

### 차이를 단계별로 나누면 (컷오프 0.7)

| 단계 | 건수 | 앞 단계에서만 반환 | 뒤 단계에서만 반환 |
|---|---|---|---|
| v0 서비스 인덱스 → 옛 `docs.jsonl` 인덱스 (코퍼스 내용 차이) | 145 → 142 | 058, 103, 120, 128 | 125 |
| 옛 `docs.jsonl` → 파서 슬림판 (**규칙 삭제만**) | 142 → 139 | 033, 125, 130, 143 | 058 |
| 파서 슬림판 → 이식 청커 (**이식·마크다운 입력만**) | 139 → 139 | 없음 | 없음 |

- 이식과 마크다운 입력은 한 질문도 바꾸지 않았다.
- 규칙 삭제로 사라진 033·125·130·143은 별표·표 서식 질문이고, 파서 #129가 예고한 증상(과태료 별표 행 조각, 서식 행 조각화)과 맞는다.
- 103·128은 옛 `docs.jsonl` 코퍼스에서도 정답 라벨이 청크에서 사라진다. 서비스 인덱스(6,288청크)와 디스크 코퍼스(6,272청크)는 내용이 다르다.
- 컷오프 0.95에서는 v0 140, v1 137이고 058이 새로 반환된다.

### 이식 정확성 (번들 189문서, 파서의 청크와 글자 단위 대조)

| 포맷 | 문서 | 원래 원소·표 자료 → 이식 청커 | 번들 마크다운 → 이식 청커 |
|---|---:|---:|---:|
| hwp5 / hwpx / hwpml | 161 | 161 | 161 |
| pdf | 28 | 28 | 15 |

행정·업무(20문서·30문항)는 기존·슬림판·이식 청커가 모두 30/30(컷오프 0.95는 27/30)으로 같았다. 이후 법령만 보기로 해서 버전 기록에서는 뺐다.

## 한계

- **정답 청크 재정의가 공식 라벨과 완전히 같지 않다.** 수치는 버전끼리 같은 규칙으로 잰 상대 비교로만 읽는다. 라벨과 무관한 "필수 구절 반환"도 함께 기록했다(v0 143, v1 136, 컷오프 0.7).
- **v0 145는 별도 확인의 146과 125번 하나가 다르다.** 125의 둘째 근거(과태료 금액의 단위 헤더 청크)를 이 하네스는 반환하지 못한다. 탐색기 쪽 라벨 검토 반영 여부의 차이로 보이나 확인하지 않았다.
- 정답 청크 규칙은 두 번 바뀌었다. 필수 구절로 인덱스마다 새로 정한 첫 방식(v0 138, v1 135)과, 기준만 공식 ID를 쓴 둘째 방식(v0 145, v1 135)은 버전 사이에 라벨 방식 차이가 섞여 폐기했다.
- 서비스 설정이 측정 중 바뀌었다(같은 브랜치의 다른 세션 커밋 `6b84c64` 컷오프 0.7·식별자 가산점·제목 경로 기본값, `c0dd2e4` 최신 판 우대 0.97). v0·v1 측정은 모두 이 설정 위에서 했다.
- 번들 마크다운 입력의 PDF 13개 차이는 이 질문들에서 드러나지 않았을 뿐, 다른 질문에서는 영향이 있을 수 있다.

## 재현

```bash
# 이식 정확성 (파서 저장소와 PDF 파싱이 되는 파이썬이 필요하다)
PYTHONPATH=<파서>/src <파이썬> scripts/compare_parser_chunker.py --parser-root ../unstructured-doc-parser_ver2
# v1 코퍼스 → 별도 인덱스 → 서비스 인덱스와 같은 질문·같은 라벨 규칙으로 비교 → 버전 기록
scripts/chunking/run_version.sh 1 "<요약>" "<무엇을 왜>"
```

단계별 분해의 "파서 슬림판" 인덱스와 "옛 `docs.jsonl`" 인덱스는 저장소 밖(스크래치)에서 만들었다. 같은 평가 하네스(`scripts/chunking/eval_category_chunking.py --reference search-law`)로 잰다. 배경과 경위는 [설계 문서](../../design/chunking_ownership_move.md#v0--v1-비교의-상황과-경위-2026-10-08)에 있다.
