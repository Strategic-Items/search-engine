# 현재 판단과 다음 측정

> **수치의 범위.** 별도 표기가 없으면 아래 수치는 docs만 읽는 인덱스(`search-docs-only`)와 docs v2
> 질의 기준이며 22~24단계까지의 측정이다. 운영 기본값(`core,docs`)으로 합치거나 새 데이터를 섞은
> 조건의 수치는 맨 아래 「현재 상태와 다음 작업」과 25·26·28단계에 있다. 코드에 반영된 단계와
> 아닌 단계는 [applied](stages/applied/)·[not-applied](stages/not-applied/) 폴더로 나뉜다.

- **채점 단위는 청크다**([23단계](stages/applied/stage-23-chunk-is-the-scoring-unit.md)). 답변에 쓰이는 단위가 청크이므로 근거 청크 지표가 주 지표이고
  문서 지표는 진단용이다. 22단계 저장 순위를 청크 기준으로 다시 재도 하이브리드 우위는
  유지된다: 근거 Recall@5 **96.3%**(dense 90.4%, BM25 87.8%), 모든 근거@5 94.8%,
  근거 MRR@5 0.8135. 문서 지표로만 보면 P@1이 하이브리드·dense 모두 94.1%로 동률이라
  둘을 가르지 못했는데, 청크 기준에서는 5.9p 차가 난다.
- **풀링 판정으로 근거 Precision의 하한을 걷어냈다.** 세 방식이 @5에서 반환한 청크의
  합집합 1,215쌍(135질의)을 전부 판정했다(`data/generated/docs-v2/pooled-judgments/`).
  라벨 기준 P@5는 BM25 47.8% / dense 53.6% / 하이브리드 50.6%로, positive-only 라벨의
  25% 안팎보다 **약 2배** 높다. "컨텍스트의 3/4이 쓸모없다"는 읽기는 틀렸다.
  **순서도 뒤집힌다** — 하한으로는 dense > BM25 > 하이브리드였는데 이는 문서를 적게
  반환할수록 정밀도가 오르는 컷오프 효과였고, 판정 라벨로는 dense > 하이브리드 > BM25,
  **nDCG@5에서는 하이브리드가 앞선다**(0.8951). 하이브리드 기본값은 이 자로도 선다.
- **그 판정자는 LLM judge다.** 블라인드로 했고 사람 라벨 193개 중 192개(99.5%)와
  일치하지만, **0점을 준 760건에는 대조할 사람 라벨이 없다.** 무관 판정의 정확도는
  재지 않았으므로 절대값을 사람 판정과 동급으로 다루면 안 된다.
- **v1은 문서 채점으로 남는다**(23단계). `data/queries_v1.jsonl`에는 근거 라벨이 없고
  붙이지 않기로 했다. v1은 어휘 검색이 담당하는 정확 일치 조회가 살아 있는지 보는
  회귀 세트로 쓰고, **방식 선택은 근거 라벨이 있는 v2에서만 한다.** 아래 「HSK 코드
  정확 일치」의 v1 재측정도 그만큼 좁혀 읽는다 — v1이 답할 수 있는 것은 dense가 정확
  일치에서 얼마나 잃는가이지, 어느 방식이 더 나은 근거를 싣는가가 아니다.
- **SPLADE는 채택하지 않았고 후보로만 남는다**([24단계](stages/not-applied/stage-24-splade-against-current-retrievers.md)).
  같은 135문항의 문서 단위 비교에서 P@1 95.6%로 BM25 90.4%, BGE-M3 sparse 90.4%,
  dense와 hybrid 94.1%를 앞섰다. dense와 RRF로 합치면 현재 BM25+dense보다 P@1이
  94.8% → 97.8%, MRR이 0.9704 → 0.9815로 오르지만 Hit@5는 99.3% → 98.5%, 반환분
  정밀도는 92.7% → 92.2%로 내려간다. 청크끼리 직접 합친 상위 5개에서는 근거 Recall이
  91.1% → 94.1%, 모든 근거가 89.6% → 92.6%로 오르지만 첫 근거 순위는 1.32 → 1.43으로
  나빠진다. 기존 판정표에 있는 청크만 같은 분모 규칙으로 비교하면 풀링 Precision은
  53.0% → 61.1%, 직접 답 Precision은 31.4% → 38.1%다. 새 청크의 판정 커버리지가
  81.2%뿐이라 선택 편향 가능성이 있고 온라인 지연도 아직 재지 않았다. 운영 기본값은
  BM25+dense hybrid를 유지한다.
  [31.4절](stages/applied/stage-31-chunk-precision.md)이 같은 SPLADE+dense를 현재 95% 전달 창(문서 5개·문서당
  청크 6개·최고 dense 점수의 95%)에서 다시 비교했더니 청크 Recall이 94.44% → 94.07%(−0.37p), 청크
  Precision 하한이 42.45% → 42.39%로, 24단계의 상위 5청크 이득은 그 창에서 나타나지 않았고 청크 1위
  정확도만 72.59% → 74.81%(+2.22p)였다. 저장된 SPLADE 출력으로 한 오프라인 실험이며 운영 설정은
  바꾸지 않았다.

- 현재 운영 경로끼리의 자연어 평가(v2)에서는 **하이브리드가 모든 품질 지표에서 가장 좋다**(22단계:
  P@1 94.1%, Hit@5 99.3%, MRR@5 0.9630 대 dense 단독 94.1% / 94.1% / 0.9407).
  6~17단계가 "dense 단독이 가장 좋다", "섞는다는 것 자체가 손해"라고 적은 것은 융합
  결과에 걸린 컷오프가 밀집 검색기만 찾은 문서를 전부 버리고 있었기 때문이다. 그
  결함을 고치자 순서가 뒤집혔다. 2~5단계의 "BM25가 가장 정확하다"는 `nomic-embed-text`
  색인의 결론이며 6단계에서 이미 뒤집혔다. 이 순서는 docs만 읽을 때의 결과이고, 새 데이터
  전체 규모(84,413청크)의 문서 1위 적중은 현행 하이브리드 0.754, dense만 0.696, BM25만 0.435다.
  규모를 맞춘 70부모에서는 dense만(0.870)이 하이브리드(0.841)를 앞서므로, 하이브리드의 우위는
  규모가 커질 때 나타난다([26단계](stages/not-applied/stage-26-holdout-overfitting-check.md), `title^3` 설정 기준).
- 새 문서 추가나 기본 청킹 전략 변경 없이 파서만 다시 실행해도 검색 성능은 거의 바뀌지
  않는다(3단계).
- 문서 탐색과 청크 선택은 서로 독립적으로 움직인다. 4단계는 청크 선택만 고쳤고 문서
  지표는 소수점까지 그대로였다.
- 질의 재작성(5단계)은 6단계 이후 최선 구성에서 얻는 것이 없다. 기본값 꺼짐을 유지한다.
- **운영 기본 모드는 `hybrid` 그대로이고, 21단계 이후로는 그것을 지지하는 측정이 있다.**
  docs v2 한 세트에서 정한 값이지만 26단계가 새 데이터(holdout 69문항)에서도 확인했다.
  식별자 조회는 9단계가 v2에 공고번호·조문번호 15문항을 더했다(`identifier_number` 6,
  `identifier_article` 4, `identifier_mixed` 5). 25단계 측정에서 `identifier_number`와
  `identifier_mixed`는 전부 첫 결과로 적중하고, `identifier_article`은 4문항 중 1문항만
  첫 결과로 적중한다(정답 근거가 정확함은 확인했다. 25단계 4절). 근거 Recall@5로 보면 세 유형
  모두 hybrid가 1.000이다(27.1절 유형별 표).
- **아직 안 잰 것은 HSK 코드 정확 일치다.** v2에는 HSK 코드 질문이 없고, 키워드 성향의 v1
  세트(HSK 18문항 포함)를 현재 임베딩(`BGE-m3-ko`)으로 다시 잰 기록을 찾지 못했다
  ([v1 기준선](baseline_v1.md)은 2026-09-15의 옛 색인이다). 정확 일치 조회에서 dense가 어휘
  검색을 얼마나 잃는지 확인하기 전에는 기본 모드를 바꾸면 안 된다.
- 근거 지표가 올랐다는 것은 답에 필요한 청크가 프롬프트에 들어갔다는 뜻이지, 생성된
  답변이 정확해졌다는 측정은 아니다. 답변 사실성은 아직 측정하지 않았다. 19단계가 이
  구분에 사례를 하나 더했다 — 근거 회수는 `@3`이 `@6`보다 높은데 판정 정확도는 더
  나빴다. **근거 회수와 답변 품질은 같은 것이 아니다.**
- **무응답 판정(18단계)·문서 내 재정렬(19단계)·청크 관련도 필터(31단계)는 모두 기본값
  꺼짐이다**(필터는 로컬 `.env`에서만 켜 두었다). 필터는 Recall 손실 없이 청크 Precision을
  25.1% → 37.8%로 올렸지만, 병렬 6개 실행의 추가 지연 p50이 15.33초이고 무응답 판정자와 함께 켠
  효과는 재지 않았다([31단계](stages/applied/stage-31-chunk-precision.md)). 재정렬은
  검색에 두 번째 모델을 붙이고, 20단계 이후로는 그것이 사는 것이 없다. 판정자의 거짓
  거절은 18단계의 14.8%에서 21단계 기준 **3.7%**까지 내려왔지만(폴라리티 규칙 + 융합
  컷오프 수정), 여전히 검색 경로에 chat 모델을 넣고 약 2초를 쓴다. 켤 근거가 서기
  전에는 꺼 둔다.
- **판정자의 남은 거짓 거절은 정보 부족이 아니라 판정과 근거의 분열이다.** 프롬프트에
  "근거를 서술하면서 false를 내지 말라"는 일관성 요구 한 줄만 더해도 거짓 거절이 8건에서
  3건이 된다([판정자 프롬프트 스윕](metrics/judge_prompt_sweep.md)). **채택하지 않았다** —
  홀드아웃 없이 135문항을 보면서 고른 값이다.
- **무응답 포착 22/26은 프롬프트로 움직이지 않는다.** 다섯 조건이 놓친 네 건이 완전히
  동일했다(`neg-005`·`014`·`016`·`024`). 거짓 거절과 무응답 포착은 서로 다른 것에 매여
  있으며, 판정자 프롬프트를 더 손봐도 포착 쪽은 오르지 않을 것으로 본다. 이 층을 건드리려면
  **무응답 세트를 먼저 키워야 한다.**
- **22단계는 판정자 쪽에 빚이 있다.** 같은 판정자 프롬프트에서 거짓 거절이 5건에서
  7건이 됐다(`065`·`072` 추가). 두 건 모두 **gold는 문맥에 있었으므로** 검색이 잃어서
  난 거절이 아니고, 같은 조건에서 gold 미검색은 3건에서 1건으로 줄었다. 그래도 반복
  실행으로 실재하는 퇴행인지 가리기 전에는 **판정자를 켜는 판단에 22단계를 유리하게
  셈하면 안 된다.**
- **판정자에는 실행 간 변동이 1~2건 폭으로 있다**(21단계). 20단계가 기록한 7/135를 같은
  코드로 다시 재면 8/135이고 목록도 다르다. `is_unanswerable`의 독스트링이 "판정은 모든
  반복에서 안정적이었다"고 적은 것은 그만큼 좁혀 읽어야 하고, 1~2건 차이로 조건을
  가르면 안 된다.
- **재정렬 지연은 아직 모른다.** 컨테이너(CPU 2코어) p50 17초, 호스트 MPS 약 1.2초인데
  둘 다 배포 수치가 아니다. 서빙을 정하고 다시 재기 전에는 이 기능의 비용을 말할 수
  없다.
- **17단계가 sparse에 준 우위는 상당 부분 BM25 쪽 설정 결함이었다.** 그 단계의 표는
  `best_fields` BM25(P@1 82.2%, Hit@5 88.1%, MRR@5 0.8438)와 sparse(90.4% / 91.9% /
  0.9093)를 비교한 것인데, 22단계에서 `most_fields`로 바꾼 BM25가 90.4% / 91.9% /
  0.9099로 같은 자리에 선다. 지연은 152.9ms 대 18.6ms이고 별도 서비스도 재색인도
  필요 없다. **"sparse가 더 나은 어휘 검색기"라는 근거는 이제 서지 않는다.**
  단, 색인이 다르므로(sparse 색인 대 `search-docs-only`) 같은 색인에서 다시 재려면
  제거한 인코딩 경로를 되살려야 한다.
- 17단계가 sparse를 걷어낸 **결정 자체**는 다른 근거("고정 융합으로는 강점이 살아남지
  못한다")로도 서지만, 그 근거는 21단계가 고친 컷오프를 통과한 값 위에 있다. 다만
  sparse를 다시 볼 유인은 22단계 이후 크게 줄었다 — 남아 있던 `identifier_number`
  6건도 `most_fields` BM25가 100%로 채운다.
- 리랭커에 대한 8단계의 기각과 18단계의 "원리적으로 안 된다"는 둘 다 좁혀졌다.
  리랭커는 **무응답 판정에는 쓸 수 없고**(관련도를 재는 도구다) **문서 내 청크
  선택에는 듣는다**(`@1` +28.5p). 같은 모델이다.
- 한국어 임베딩 모델(13·15단계 `BGE-m3-ko`)과 재정렬 방식(20단계 밀집 순서)은 이미 바꿨고,
  새 코퍼스도 26단계 holdout으로 만들었다. 비교 기준은 40문항이 아니라 v2 135문항이다.
  **`semantic_hybrid` 청킹은 아직 시험하지 않았다**(이 저장소 문서에 그 청킹의 기록이 없다).
- 19단계 수치에는 홀드아웃이 없다. 재정렬은 임계값이 없어 18단계의 신뢰도 임계값 같은
  과적합 경로는 없지만, 기본값을 켜는 결정에는 별도 검증이 필요하다. 재정렬을 켠 채
  holdout에서 잰 기록도 찾지 못했다.

## 현재 상태와 다음 작업 (2026-09-29 기준, 32단계 이후)

25단계가 세운 다음 작업 넷 중 **1·2번은 반영됐고**, 3·4번은 그대로다. 항목별 상세는
[25단계의 「다음 순서와 현재 상태」](stages/applied/stage-25-core-corpus-against-docs-queries.md)에 있다.
아래는 그 뒤 처리된 것과 아직 열려 있는 것을 나눈 것이다. "기록을 찾지 못했다"는
이후 단계 문서·커밋에서 처리한 흔적을 찾지 못했다는 뜻이다.

## 카테고리 입력 비교 추가 판단 (2026-10-06, 42단계)

[42단계](stages/applied/stage-42-heading-path-input-ablation.md)는 법령 100문항·행정 30문항의 카테고리 검색 입력만 비교했다. SPLADE에 제목 경로를 추가하면 법령 단독은 92→94/100으로 늘지만 hybrid는 91→89/100으로 내려가며, dense에서 경로를 제거하면 단독은 법령·행정 각각 한 문항 내려가고 hybrid 회수는 그대로다. 두 검색기 모두 기본 입력을 유지하고 실험용 색인 옵션만 추가했다.

단독 성능 상승이 융합 상승으로 이어지지 않은 이유는 문항별 이득 중복과 결과 선별이었다. 법령 hybrid의 손실은 (1) 정답 RRF 비율이 95% 아래로 내려간 경우, (2) 컷오프를 통과한 정답이 연결 문서 추가 뒤 5문서 상한에 밀린 경우로 재현됐다. 후자는 실제 검색 결과 정리에서 원래 고른 문서를 잘라내는 경로이며 별도 수정·비교가 남아 있다. 수치는 라벨된 근거 회수이고 생성 답변 정확도와는 구분한다.
