# 12단계: 구어체 어미가 검색을 망가뜨린다 (2026-09-18)

운영 화면에서 `전략물자 알려줘`를 검색하면 결과가 1건 나오는데, 그 1건이
`국제체제 표3 — 주 : NPT (Nuclear Non-proliferation Treaty)`였다. 질의어가 하나도
매칭되지 않는 문서다.

## 무엇이 일어났나

`알려줘`는 nori에서 `알리`(VV) + `어`(EC) + `주`(VX) + `어`(EC)로 분해된다. `EC`는
Lucene 기본 stoptags에 있어 버려지지만 **`VX`(보조용언)는 남는다.** 그 문서 제목의
`주 :`는 표의 각주 표시인데, 검색 토큰이 된 `주`가 여기에 걸렸다.

14.37점의 구성은 이렇다.

| 기여 | 점수 |
|---|---:|
| `title:주` | 10.373 |
| `body:주` | 1.473 |
| 현행판 가점 (function score) | 4.000 |
| `전략` 기여 | 0.000 |
| `물자` 기여 | 0.000 |

제목 필드는 짧고 `주`는 제목에서 희귀하다. IDF가 치솟아 **토큰 하나가 모든 내용어를
합친 것보다 높은 점수**를 냈다.

## 진짜 피해는 컷오프에서 난다

같은 코퍼스에 질의만 바꿔 보면 분명하다.

| 순위 | `전략물자` | `전략물자 알려줘` |
|---|---|---|
| 1 | 12.22 판정기준 해석 세부지침 ✅ | **14.37 국제체제 표3 (노이즈)** |
| 2 | 12.10 확인의무 면제 대상 ✅ | 12.22 판정기준 해석 세부지침 ❌ |
| 3 | 11.22 신구조문 대비표 ✅ | 12.10 확인의무 면제 대상 ❌ |
| 4 | 11.00 전략물자수출입고시 ✅ | 11.22 신구조문 대비표 ❌ |
| | 5건 전부 생존 | **1건만 생존** |

노이즈가 1위에 앉으면서 컷오프 기준선이 `0.90 × 14.37 = 12.94`로 올라갔고, 정답
4건이 전부 그 아래로 깔렸다. 화면에 1건만 뜬 이유다.

[9단계](stage-09-identifier-queries.md)의 "컷오프가 정답을 잘라낸다"와 증상은 같지만
원인이 다르다. 거기서는 RRF가 어휘 경로의 확신을 눌러서였고, 여기서는 **엉뚱한 1위가
기준선을 끌어올려서**다. 컷오프 비율을 조정해서 풀 문제가 아니다.

## 고친 것

`nori_part_of_speech`의 stoptags에 `VX`(보조용언), `VCP`·`VCN`(지정사)을 더했다.
본용언 `VV`는 그대로 둔다 — 주제를 담는 쪽이다.

```
전략물자 알려줘            기존: [전략, 물자, 알리, 주]  수정: [전략, 물자, 알리]
전략물자 수출허가 절차가 어떻게 돼?   되(VV)는 양쪽 다 유지
```

Lucene 기본 목록의 `E`와 `J`는 이 버전에서 거부하는 추상 범주라, 구체 태그
(`EC`·`EF`·`EP`·`ETM`·`ETN`, `JC`·`JKB`…`JX`)로 풀어 적었다. stoptags는 기본값을
확장하는 게 아니라 **대체**하므로 전체 목록을 써야 한다.

## 측정

구어체 평가셋을 새로 만들었다. 135문항의 gold·근거는 그대로 두고 문장 끝만 보조용언
어미로 바꾼 것이다(`…있어?` → `…있는지 알려줘.`). 오타 평가셋과 같은 방식이며
`data/queries_docs_v2_colloquial.jsonl`에 있다. 기존 분석기에서 `주` 토큰이 남는 질의가
135/135였고, 수정 후에는 2/135다.

수정 전/후 × 정식/구어체 네 조합을 같은 코퍼스(1,198청크)에서 쟀다.

**BM25**

| | Precision@1 | Hit@5 | Precision@5(반환분) | MRR@5 |
|---|---:|---:|---:|---:|
| 수정 전 · 정식 | 80.0% | 86.7% | 75.2% | 0.8265 |
| 수정 전 · 구어체 | 76.3% | 83.0% | 72.2% | **0.7898** |
| 수정 후 · 정식 | 82.2% | 88.1% | 77.3% | 0.8438 |
| 수정 후 · 구어체 | 82.2% | 88.1% | 77.6% | **0.8438** |

구어체 어미는 MRR을 0.037, Hit@5를 3.7%p 깎고 있었다. 수정 후 **구어체가 정식 질의와
같은 점수**가 된다. 어미가 더는 순위에 관여하지 않는다는 뜻이다.

정식 질의도 0.8265 → 0.8438로 올랐다. 기존 평가셋에도 `싶`(`-고 싶어`)이나 `않` 같은
VX가 섞여 있었기 때문이다. 구어체 질의에서 상위 5위가 바뀐 질의는 135문항 중 20개다.

**벡터가 대조군이다.** 수정 전후 MRR이 0.9074로 소수점까지 같다. dense 경로는 nori를
쓰지 않으므로, 위 변화가 분석기에서 온 것임이 이것으로 확인된다. 하이브리드는
0.9062 → 0.9099(정식), 0.9037 → 0.9111(구어체).

카테고리별로는 구어체 BM25가 이렇게 움직인다.

| 카테고리 | n | 수정 전 | 수정 후 | 차이 |

| paraphrase | 34 | 0.780 | 0.843 | +0.063 |
| scenario | 68 | 0.795 | 0.844 | +0.049 |

| multi_evidence | 18 | 0.861 | 0.880 | +0.019 |

## 대가

`VX`를 버리면서 **부정 보조용언 `않`도 함께 빠진다.** `면제되지 않는 경우`와
`면제되는 경우`가 같은 토큰열이 된다. BM25는 원래 `않`을 독립 토큰으로만 다뤄
부정의 범위를 표현하지 못했으므로 잃는 것이 크지는 않지만, 부정형 질의를 구분해야
한다면 어휘 경로가 아닌 곳에서 풀어야 한다. 현재 평가셋에는 이 구분을 요구하는
문항이 없어 측정되지 않는다.

이 변경은 색인 분석기라 **전체 재색인이 필요하다.**

## 남는 것

`identifier_article`은 이 수정으로 움직이지 않았다. 4문항 모두 0.250이고,
[10단계](stage-10-learned-sparse.md)·[11단계](stage-11-qwen3-embedding.md)에서도
어느 모드로도 0.312를 넘지 못했다. 세 단계가 같은 곳을 가리킨다.
