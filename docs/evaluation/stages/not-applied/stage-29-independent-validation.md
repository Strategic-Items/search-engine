# 29단계: 새 검증 질문을 검색 전에 동결하고 현재 설정으로 평가

출처 36부모를 검색 전에 무작위로 뽑고(29.1), 질문과 정답을 검색 전에 커밋하고(29.2), 설정을 바꾸지 않고 평가했다(29.3). **결론: 반환 근거를 정답 대안으로 추가한 뒤 core+docs 1위 34/36. 남은 실패 007·036은 연도·보고 기간 혼동이다.**

> 원래 단계별 파일로 나뉘어 있던 기록을 주제별로 합쳤다. 질문을 검색 전에 동결했다는 증거는 각 단계의 개별 커밋에 남아 있으므로, 문서만 합쳤다. 원래 단계는 절 번호로 바꿨고, 절 제목의 옛 번호는 커밋 메시지·결과 파일명(`stage39` 등)과 대조할 수 있도록 괄호에 남겼다.

- 29.1 새 검증 질문의 출처를 검색 전에 동결한다 (2026-09-25)
- 29.2 새 질문과 정답을 검색 전에 동결한다 (2026-09-25)
- 29.3 동결한 새 질문으로 검색 검증과 반환 근거 점검

## 29.1 새 검증 질문의 출처를 검색 전에 동결한다 (2026-09-25) (옛 31단계)

28.1절의 docs 135문항과 holdout 69문항은 이미 검색 결과를 보고 분석한 자료다.
거기에서 더 임계값이나 질의별 예외를 고르면 과적합 위험이 크다. 이번에는 랭커를
수정하지 않고, **질문을 작성하거나 대상 문서를 검색하기 전에** 새 출처를 뽑았다.

### 고정 규칙

- 코퍼스: `data/generated/holdout-v1/core.jsonl`, SHA-256
  `afb464ccfd3125e4dbcf7a044ae07fb2db48ddc43d4bf497be713988571507db`.
- 시드 `20260925`. 부모 문서 단위로 출처별 층화 무작위 추출한다. 본문 총 300자 이상,
  180~5,000자인 청크 하나 이상이 있는 부모만 후보로 한다. 지정 청크도 후보 중 무작위로
  하나 고른다. 문서 제목이나 본문 내용으로 후보를 고르지 않는다.
- 이전 holdout의 추출 부모, 기존 docs·holdout 질의의 정답 부모, 28.1절에서 상위 5위
  판정으로 본 부모를 **추출 전에** 제외한다. 단독 법령 부모 5개는 이전 holdout에서
  전부 사용했으므로 해당 2개 추출 슬롯을 법령 별표로 옮겼다. 이는 선택 문서를 읽기
  전에 확인한 후보 수에 따른 조정이다.
- FAQ 5, 공지 5, 공지 첨부 5, 알기쉬운 전략물자 4, 그 첨부 2, 동향 2,
  동향 첨부 2, 법령 별표 5, 안내 2, 국내외 소식 2, 기타 게시판 2: **36부모**.
- 추출 목록과 지정 청크 ID는
  [동결 매니페스트](../../../../data/generated/validation-v2/frozen_sample.json)에 있다.
  [추출 스크립트](../../../../scripts/sample_independent_validation.py)는 코퍼스와
  이전 라벨·판정 원장만 읽으며 검색 API나 검색 결과를 읽지 않는다.

### 다음 단계의 사전 약속

1. 각 지정 청크만 먼저 읽고 질문·모범답안·필수 근거 문구를 작성한다. 사실을 묻기
   어려운 청크는 다른 문서를 대신 고르지 않고 사유를 남겨 제외한다.
2. 동결된 문구로 같은 답을 담은 다른 부모와 청크를 코퍼스 전체에서 찾아 정답군을
   확장한다. 검색 결과를 보기 전에 질문셋 파일과 SHA-256을 커밋한다.
3. 현재 `title^1` + 다중 인덱스 DFS 설정을 **그대로** 검색한다. 문서 Precision,
   1위 적중, 근거 Recall, 근거 Precision 하한을 보고, 반환 상위 5위에서 빠진
   동등 정답을 판정한다. 이 검증셋으로 검색 가중치나 컷오프를 다시 고르지 않는다.

이번 단계에서는 36부모가 중복 없이 뽑히고 같은 명령으로 바이트 단위 동일한 목록이
생성되는 것만 확인했다. 검색 품질 결과는 아직 없다.

## 29.2 새 질문과 정답을 검색 전에 동결한다 (2026-09-25) (옛 32단계)

29.1절에서 뽑은 36부모의 **지정 청크만 먼저 읽고** 부모당 질문 하나를 작성했다.
샘플의 빈 서식, OCR 표, 영문 통제목록도 임의로 다른 문서로 바꾸지 않았다. 36개
모두 질문을 만들 수 있었으므로 제외는 0건이다.

### 동결 자료

- [질문 초안과 요구사항](../../../../data/generated/validation-v2/queries_spec.json):
  질문, 모범답안, 요구사항별 원문 문구, 지정 부모·청크.
- [core 단독 질문셋](../../../../data/queries_validation_v2.jsonl): 36문항, SHA-256
  `d44e49607289beaeaf28cda567df61b040c885cbdc4807787c6045f0877084ee`.
- [core+docs 질문셋](../../../../data/queries_validation_v2_combined.jsonl): 36문항, SHA-256
  `d5f293dc1ff8ad96470ba2a0c44e99a69f583947cefe86c623fc92ad954c80fb`.
- [매니페스트](../../../../data/queries_validation_v2.manifest.json): 시드, 소스 해시,
  질의 해시와 동결 상태.

`scripts/build_holdout_queries.py`로 요구사항의 문구를 84,413개 core 청크와 docs
청크에서 정규화 문자열 일치로 찾았다. 동일한 완전 답 문서를 `gold` 대안으로 넣고,
core+docs용 질문셋에는 docs 쪽 대안도 넣었다. 질문·모범답안과 지정 청크의 문구가
일치하지 않으면 빌더가 중단한다. 이번에는 36문항 모두 통과했다.

유형은 시나리오 8, 바꿔 묻기 5, 식별자 11, 복수 근거 7, 서식 5문항이다. 질문과
정답은 assistant가 작성했으며 사람 검수 전이다. 문구 일치는 표현이 다른 동등
답을 놓칠 수 있으므로 검색 후 상위 5위 새 문서를 따로 판정해야 한다.

이 시점까지 **이 36개 질문을 검색 API에 보내지 않았다.** 29.3절에서 현재 설정을
그대로 측정한다. 결과를 보고 제목 가중치나 컷오프를 재선택하지 않는다.

## 29.3 동결한 새 질문으로 검색 검증과 반환 근거 점검 (옛 33단계)

### 목적과 설정

29.1절에서 출처 문서 36개를 표본 추출하고, 29.2절에서 각 문서에 대한 질문과 최초 정답표를 **검색 실행 전에** 커밋했다. 이 단계에서는 `title^1`과 다중 인덱스 DFS를 포함한 현재 설정을 그대로 사용했다. 두 질의셋 모두 정답이 존재하는 질문만 포함한다. 무응답 판정은 이 단계의 범위가 아니다.

원본 질문 파일은 `data/queries_validation_v2.jsonl`(core)과 `data/queries_validation_v2_combined.jsonl`(core+docs)이다. 실행 결과는 `data/generated/validation-v2/results/`에 보존했다. API는 로컬 8112(core), 8113(core+docs), 상위 문서 5개 기준이었다. 질의는 검색 설정을 선택하는 데 사용하지 않았다.

### 최초 정답표와 반환 문서 판정

| 조건 | 1위 정답 | 5위 내 정답 | 근거 Recall@5 | 반환 문서 Precision@5 |
|---|---:|---:|---:|---:|
| core, 최초 정답표 | 26/36 | 30/36 | 0.833 | 0.633 |
| core+docs, 최초 정답표 | 27/36 | 30/36 | 0.833 | 0.640 |
| core, 반환 근거 추가 | 33/36 | 34/36 | 0.944 | 0.738 |
| core+docs, 반환 근거 추가 | **34/36** | **34/36** | **0.944** | **0.757** |

상위 결과의 실제 청크를 읽고, 답과 근거를 직접 담은 문서 11개를 7문항의 정답 대안으로 추가했다. 판정 기록은 `data/generated/validation-v2/returned_gold_audit.json`, 파생 질문 파일은 `queries_core_returned_audited.jsonl`과 `queries_combined_returned_audited.jsonl`이다. 원래 동결한 질문 파일은 수정하지 않았다. 대표적인 누락 사례는 다음과 같다.

- 024: 기존 정답 이외에 반환된 세 자료 모두 `9B105`와 마하 0.9 기준을 정확히 적었다. 처음의 5위 내 실패 판정은 정답표 누락이었다.
- 002: 전자매체·구두 이전을 다룬 문서와 이메일·교육·실연을 열거한 FAQ를 추가했다.
- 028: 반환된 FAQ 첨부의 바세나르용 별지 2-3 서식에도 연락 담당자의 전화·이메일란이 있다.
- 030: 반환된 다른 별지 제7호 서식에도 영문 제목 `Korean Import Certificate`가 있다.
- 003, 018, 019도 반환 청크에 질문의 답이 직접 적혀 있어 정답 대안을 추가했다.

보정 후 core+docs의 근거 청크 Precision@5는 **하한 0.438**(평균 반환 5.50청크), 문서 Precision@5는 **하한 0.757**(평균 반환 2.19문서)이다. 추가한 것은 확인된 11문서뿐이다. 나머지 반환 문서를 전수 판정한 수치가 아니므로, 이 precision을 실제 오답 비율로 해석하면 안 된다. 질문과 추가 판정 모두 사람 검수 전이다.

### 남은 실제 실패

동등한 정답 근거를 추가한 뒤에도 007과 036은 상위 5문서에 정답이 없다. 모두 CP 보고 기한을 묻고, **연도와 보고 대상 기간**이 다른 공고·발표 자료가 앞에 나온다.

- 007: 질문은 2026년 상반기 실적보고(2026-07-31, AAA 연 1회)인데, 검색 상위에는 2014·2018년 자료가 포함된다.
- 036: 질문은 2020년 하반기 실적보고 및 운영보고(2021-01-31)인데, 상위에는 2019년 안내와 2024년 하반기 안내가 나온다.

두 정답 문서는 모두 색인돼 있다. 따라서 현재 확인된 실패는 색인 누락이 아니라 **유사한 제목과 본문을 가진 연례 자료 사이에서 질문의 연도·기간을 충분히 구별하지 못한 검색 순위 문제**다. 이 사례만 보고 연도 가중치를 정하면 이 검증셋에 과적합된다. 여러 연도와 다른 주제의 날짜 질문을 별도로 동결하고, 기존 docs·holdout 회귀를 함께 본 뒤 일반 규칙을 검토해야 한다.

### 판단과 다음 일

새 질문에서 `title^1`+DFS의 보정 후 1위 정답은 34/36이다. 현재 설정의 새 검증셋 성능을 기록했으며, 이 질문으로 검색 파라미터를 재선택하지 않는다. 다음은 (1) 007·036의 연도/기간 충돌을 재현할 새 날짜 질문셋을 검색 전에 동결, (2) 후보 개선을 기존 평가셋과 새로 동결한 질문셋 양쪽에서 검사, (3) 이번 36문항과 정답 추가분의 사람 검수다. 무응답 질문에는 별도 판정자가 필요하므로 여기서 다루지 않는다.
