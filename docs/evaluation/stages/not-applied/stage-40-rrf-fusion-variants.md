# 40단계: SPLADE(C)+dense 융합 방식을 재 보고, 카테고리 청크 RRF의 k와 행정·업무 Precision 원인을 가렸다 (2026-10-06)

[다음 아이디어 9번](../../next_ideas.md)(융합 방식 교체)을 쟀다. 지금 SPLADE+dense 오프라인 비교는 전부
RRF k=60 하나만 쓴다. RRF의 k를 바꾸거나, SPLADE 쪽에 가중치를 주거나, 점수를 정규화해 가중합(CombSUM
방식)으로 합치면 달라지는지 봤다.

**결론부터.** 이 세트에서는 어느 변형도 RRF k=60보다 낫지 않다. k를 30~100 사이에서 바꿔도 지표가 완전히
같고(최종 비율 컷오프 0.97에서 상위 몇 개만 남기므로 k 차이가 순서를 못 뒤집는다), SPLADE 쪽 가중치를 올리면
문서 P@1이 떨어진다. 점수합(가중합)은 문서 지표가 RRF와 같고 청크 MRR이 0.004~0.015p 높지만 문항 수(69·135)
대비 잡음과 구분되지 않는다. **반영하지 않는다.** 카테고리 코퍼스(청크 단위 RRF)에서 k를 바꾼 시험은 아래 마지막 절이다.

## 조건

- **모델.** 38단계에서 학습한 SPLADE 설정 C. 원시 랭킹(`ev-C-docs.json`, `ev-C-hs.json`)은 그 단계에서
  이미 떠 둔 것을 재사용했다(재학습하지 않았다).
- **질의.** docs_v2 135문항(`data/queries_docs_v2.jsonl`, 인덱스 `search-docs-only`)과 holdout-small
  69문항(`data/queries_holdout_v1_adjudicated.jsonl`, 인덱스 `search-holdout-small`). 새 질의셋은
  만들지 않았다.
- **dense는 실시간.** 캐시된 임베딩이 아니라 `OllamaEmbedder` + 운영 클러스터에서 그때그때 가져왔다(후보
  50개, 사전 컷오프 0.97 — 운영 하이브리드 경로와 같은 값).
- **바꾼 것은 융합 공식뿐.** SPLADE·dense 각각의 사전 트림(0.97)과 최종 비율 컷오프(0.97)는 고정했다.
- **공식 7가지:**
  - RRF k=30 / 60(현재) / 100
  - RRF k=60, SPLADE 가중치 0.5 / 1.5 (dense는 항상 1.0)
  - 점수합: 각 목록을 자기 1위 점수로 나눠 0~1로 맞춘 뒤 가중합(CombSUM 방식), 가중치 1.0 / 1.5
- **재현.** `scripts/splade_finetune_v2/rrf_variants.py`. 원시 랭킹 경로는 스크래치패드에만 있어 `--splade`
  인자로 지정해야 한다. 결과는 `data/generated/rrf-variants-v1/{docs-v2-135,holdout-small-69}.json`.

- **k는 이 범위에서 무의미하다.** 30·60·100 세 값이 두 세트 모두 소수점까지 같다. 최종 컷오프가 1위 점수의
  97%만 남기므로, 후보가 적은 질문에서는 k가 전체 점수를 같은 비율로 늘리거나 줄일 뿐 순서를 바꾸지 못한다.
  21단계에서 이미 "비율 컷오프 이후에는 점수 절대값에 의미가 없다"고 확인한 것과 같은 이유다.
- **SPLADE 가중치를 올리면 손해만 본다.** docs_v2에서 가중 1.5는 P@1을 0.963→0.933(−4문항)으로 떨어뜨리고
  두 세트 모두 청크 MRR도 낮춘다. 가중 0.5는 docs_v2에서 중립이지만 holdout-small 청크 Recall을 0.884→0.855로
  낮춘다(2문항). SPLADE가 dense보다 더 믿을 이유가 이 세트에는 없다.
- **점수합은 RRF와 거의 같다.** 문서 지표는 완전히 같거나(holdout) 사실상 같고(docs_v2 MRR −0.002), 청크
  MRR만 두 세트에서 각각 +0.004 / +0.015 높다. 204문항 규모에서 이 차이는 잡음과 구분되지 않는다.
- **개발 세트와 홀드아웃의 순위가 같다.** 어느 세트에서도 RRF k=60을 이기는 변형이 없어, 과적합으로 숨겨진
  개선도 없어 보인다.

## 카테고리 코퍼스에서 청크 단위 RRF의 k를 바꿔 컷오프 창을 좁혀 봤다

위 시험은 문서 단위 경로(최종 컷오프 0.97)라서 k가 결과를 바꾸지 못했다. 카테고리 검색의 hybrid는 청크 단위 RRF 뒤
1위 점수의 95%로 자르는 경로(37·38단계, 코드 적용)라 k가 창의 크기를 정한다. 행정·업무 Precision이 낮은 원인을 가리면서 이 경로의 k를 시험했다.

**결론부터.** 행정·업무 Precision이 낮은 것은 문서당 한도나 정답 청크 옆 번호 때문이 아니라, 순위만 쓰는 RRF에서 95% 컷오프가
"두 목록 상위 4~5위"를 거의 그대로 통과시키기 때문이다. 이 경로에서는 k를 줄이면 Precision은 오르지만 정답 청크를 반환하는 질문이 줄어,
세 카테고리에 맞는 k 하나가 없다. 서비스에는 반영하지 않았다.

카테고리 탐색기의 hybrid(파인튜닝 SPLADE C + dense, 청크 단위 RRF k=60, 1위 점수의 95% 컷오프)에서 행정·업무의 Precision이
낮다(0.525, 법령 0.778, 민원FAQ 0.514). 원인과 k를 줄였을 때의 변화를 쟀다. 질문은 법령 50·행정 30·민원FAQ 30문항(점검용)이고,
Precision은 Sonnet이 청크마다 매긴 판정(1 이상이 관련)의 질문 평균이다.

### 원인: 행정·업무 Precision이 낮은 이유

반환 청크 100개 중 무관 판정 51개의 내역은 정답 문서 안의 청크 35개, 다른 문서의 청크 16개다.
정답 문서 안의 35개를 하나씩 보면 문서당 6개 한도로 실린 것은 0개, "각 목록 1위는 남긴다"는 예외로 남은 것은 0개이고 전부 컷오프 선 위다.
정답 청크 옆 번호(간격 1)는 11개뿐이고 간격 2~7이 12개, 25·31·49가 3개다. 35개 모두 SPLADE 7위·dense 5위 안이다.
RRF는 순위만 쓰므로 두 목록의 5위끼리도 점수가 1위 대비 94%(2/65 대 2/61)라, 95% 컷오프가 "두 목록 모두 상위 4~5위"를 거의 그대로 통과시킨다.
행정 문서는 청크가 짧고 문서당 5~10개라 질문과 같은 주제의 문서에서는 그 문서의 청크 대부분이 두 목록 상위 5위에 같이 들어온다.

### k 시험

컷오프 95%·반환 한도는 그대로 두고 k만 바꿨다. k=60에서 탐색기 값이 그대로 재현된다(평균 반환 3.33·3.4·2.9, Precision 0.525·0.778·0.514).
작은 창은 k=60 창의 부분집합이라 판정이 없는 청크는 0개다. 상위 5청크 Recall은 컷오프가 아닌 순서에만 달려 k로 거의 변하지 않는다
(행정 28/30 고정, 법령 47→48, 민원FAQ 30/30).

| 세트 | k | 정답 청크 반환 | 평균 반환 청크 | Precision |
|---|---|---|---|---|
| 행정 30 | 60 | 27/30 | 3.33 | 0.525 |
| | 30 | 25/30 | 2.30 | 0.664 |
| | 20 | 24/30 | 1.97 | 0.683 |
| | 10 | 22/30 | 1.43 | 0.778 |
| | 1~5 | 22/30 | 1.4 | 0.77 |
| 법령 50 | 60 | 47/50 | 3.4 | 0.778 |
| | 30 | 45/50 | 2.56 | 0.853 |
| | 20 | 45/50 | 2.26 | 0.908 |
| | 10 | 40/50 | 1.82 | 0.935 |
| 민원FAQ 30 | 60 | 30/30 | 2.9 | 0.514 |
| | 30 | 30/30 | 2.07 | 0.656 |
| | 20 | 30/30 | 1.57 | 0.822 |
| | 10 | 30/30 | 1.17 | 0.95 |

- k를 줄이면 Precision은 오르지만 행정(k=10에서 27→22)과 법령(40/50)은 정답 청크를 반환하는 질문이 줄어든다. 한 검색기에서만 높게 나온
  정답 청크가 두 목록 합의 컷오프 아래로 밀리기 때문이다. 민원FAQ는 손실 없이 0.95까지 오른다.
- 세 카테고리에 맞는 k가 하나로 정해지지 않는다(민원FAQ k=10, 법령 k=30 이하는 손실). 컷오프 비율과 k를 같이 움직인 조합은 재지 않았다
  (110개 질문에 맞추게 되어 과적합 위험이 크다). 서비스에는 반영하지 않았다.
- 가능한 다음 방법: SPLADE·dense의 실제 점수 격차를 반영하는 컷오프(비율 방식), 정답 문서 안 청크를 다시 순위 매기는 리랭커.
- 스크립트: `scripts/law/sweep_rrf_k.py`. 순위 원자료(`ev-C-*.json`, `emb-bge-*.npz`)는 스크래치패드에만 있어 `RANKS_DIR`로 지정해야 한다.
