# 26단계: 튜닝이 docs에 과적합됐는가 (2026-09-23)

1~25단계의 튜닝값(`title^3`, `most_fields`, 컷오프 비율, 문서 안 청크 순서 등)은 모두
**docs 52문서와 질의 135문항 한 세트**를 보고 골랐다. 이 값들이 처음 보는 문서와 질의에서도
통하는지 묻는다. 이를 위해 core를 docs와 같은 파서로 새로 수집해 홀드아웃을 만들고,
새 질의를 **엔진을 한 번도 돌리기 전에** 동결했다.

**결론부터.** 과적합이 있다. 같은 규모의 새 데이터에서 문서 1위 적중이
**0.948 → 0.841**로 떨어지고(−10.8p, 95% 구간이 0을 넘지 않음), 전체 규모에서는
0.754까지 떨어진다. 튜닝값 가운데 **`title^3`과 하이브리드 컷오프는 어느 세트에서도
최선이 아니다.** 제목 가중치를 1로 낮추면 튜닝 세트에서는 손해가 없고, 새 데이터
전체에서는 1위 적중이 +5.8p 오른다. 하이브리드 자체는 새 데이터에서도 가장 낫다.

## 1. 같은 규모에서의 하락

| 지표 | 튜닝 세트 | 규모 맞춤 | 차이 (95% 부트스트랩) |
|---|---:|---:|---|
| 근거 Recall@5 (주 지표) | 0.963 | 0.906 | −5.7p [−13.3, +1.2] |
| 근거 MRR@5 | 0.818 | 0.788 | −3.0p [−13.7, +7.0] |
| 문서 1위 적중 | 0.948 | 0.841 | **−10.8p [−20.9, −1.4]** |

- 규모를 맞췄으므로(52문서 대 70문서) 이 하락은 규모 탓이 아니다.
- 손실은 두 유형에 몰려 있다. 1위 적중 기준으로 scenario가 0.97 → 0.79,
  multi_evidence가 1.00 → 0.82로 떨어졌다. identifier는 1.00이다.
- 1위에 자주 오르는 문서는 **전략물자수출입고시 본문**(96청크) 7회와
  **수출통제 대상기술 안내 책자**(55청크) 5회다. 이 중 오답 1위는 각각 2회와 3회다.
  둘 다 여러 주제를 다루는 긴 문서다. docs는 부모당 청크 수가 비교적 고르다(평균 23).

## 2. 전체 규모

| 지표 | 규모 맞춤 | 전체 |
|---|---:|---:|
| 근거 Recall@5 | 0.906 | 0.891 |
| 근거 MRR@5 | 0.788 | 0.775 |
| 문서 1위 적중 | 0.841 | 0.754 |

- 부모 수가 47배(70 → 3,293)로 커지면 1위 적중이 8.7p 더 떨어진다. 근거 Recall은 1.5p만 떨어진다.
  창 안에는 남지만 1위를 뺏기는 경우가 늘어난다.
- docs를 함께 색인해도(docs + 전체) holdout 질의 점수는 소수점 셋째 자리까지 같다.
  docs 문서는 holdout 질의의 1위를 뺏지 않았다.

## 3. 시험 A: docs 질의에 새 데이터를 방해물로 섞으면

| 지표 | docs만 | docs + holdout 전체 |
|---|---:|---:|
| 근거 Recall@5 | 0.963 | 0.856 |
| 근거 MRR@5 | 0.818 | 0.717 |
| 문서 1위 적중 | 0.948 | 0.807 |

- 25단계의 core(612부모)를 섞었을 때는 0.963 → 0.911이었다. 이번에는 방해물이 5배
  넘게 많아서 손실도 더 크다.
- 첫 보정 뒤에도 새 데이터의 정답 문서가 4문항(020, 085, 094, 120)에서 빠져 있었다.
  020의 1위 문서는 정답을 담지만 반환된 청크에는 답이 없으므로 문서 적중만 보정했다.
  101은 새 문서가 두 요구사항 중 하나만 뒷받침해 근거만 추가했다. 이 보정으로 시험 A의
  1위 적중은 0.778 → 0.807, 근거 Recall은 0.830 → 0.848이 됐다.
- 이어서 135문항 전체의 상위 5개에서 새 코퍼스 문서 205쌍을 선별했다. 추가 정답
  부모 11건(020의 다른 서식 2건, 087 1건, 094 2건, 110 1건, 120 1건, 128 4건)을
  찾았다. 020의 두 서식은 반환된 청크에도 답이 있어 근거 Recall이 0.848 → 0.856으로
  올랐다. 1위 적중은 변하지 않았다. 제목·반환 청크로 전체를 선별하고 가능성이 있는
  부모의 본문을 확인했으며, 모든 부모의 모든 청크를 사람이 한 줄씩 읽은 것은 아니다.
- 법령 판본 충돌도 있다. 127의 기존 답은 제54조가 상황허가 면제라고 하지만 새 고시
  판본은 제54조가 상황허가 대상이고 제54조의2가 면제다. 이를 추가 정답으로 세지 않았다.
- 원인은 25단계와 같은 방향으로 본다. 두 인덱스의 BM25 통계가 따로 계산되고, 긴 문서가
  제목 가중치를 증폭한다. 이번 단계에서 원인을 따로 분해하지는 않았다.

## 4. 시험 C: 튜닝값이 새 데이터에서도 최선인가

값을 하나씩 바꿔 세 조건에 똑같이 적용했다. 제목 가중치는 저장소 코드를 고치지 않고
질의 생성만 바꿔 띄웠다(`serve_variant.py`). 표의 수치는 문서 1위 적중이다.

| 변형 | 튜닝 세트 | 규모 맞춤 | 전체 |
|---|---:|---:|---:|
| **현재 설정** (하이브리드, `title^3`, 컷오프) | 0.948 | 0.841 | 0.754 |
| `title^1` | 0.956 | **0.870** | **0.812** |
| 컷오프 끄기 (`SEARCH_CUTOFF_RATIO_HYBRID=0`) | 0.948 | 0.841 | 0.754 |
| 벡터만 | 0.963 | 0.870 | 0.696 |
| BM25만 | 0.904 | 0.667 | 0.435 |

근거 Recall@5:

| 변형 | 튜닝 세트 | 규모 맞춤 | 전체 |
|---|---:|---:|---:|
| 현재 설정 | 0.963 | 0.906 | 0.891 |
| `title^1` | 0.963 | 0.906 | 0.877 |
| 컷오프 끄기 | 0.963 | **0.928** | **0.913** |
| 벡터만 | 0.922 | 0.877 | 0.754 |
| BM25만 | 0.878 | 0.732 | 0.565 |

- **`title^3`:** 튜닝 세트에서도 `title^1`보다 낫지 않다(0.948 대 0.956). 새 데이터에서는
  격차가 커진다. 25단계에서 본 제목 가중치 증폭과 같은 방향이다.
- **컷오프:** 튜닝 세트에서는 영향이 0이다. 새 데이터에서만 근거 Recall을 2.2p 깎는다.
  docs의 점수 분포에 맞춰진 값으로 보인다.
- **하이브리드:** 규모가 커질수록 단일 검색기보다 확실히 낫다. 벡터만 쓰는 방식은
  규모 맞춤에서는 하이브리드를 이기지만(0.870), 전체에서는 무너진다(0.696).
- 변형 실행에서 새로 1위에 오른 문서는 판정하지 않았다. `title^1` 4건, 벡터만 13건,
  BM25만 34건이 미판정이다. 판정하면 이 변형들의 점수는 오를 수만 있으므로
  `title^1`이 이긴다는 결론은 바뀌지 않는다. 다만 69문항에서 `title^1`의 1위 적중
  개선은 5건 개선·1건 악화, +5.8p이며 대응표본 부트스트랩 95% 구간은 [0, +13.0]p다.
  표본이 작아 개선 크기는 아직 불확실하다.

### 원인 분해

- **제목 가중치:** 전체 조건에서 `title^1`은 1위 오답 5건을 정답으로 바꾸고 1건을
  악화시켰다. 예를 들어 특허 출원 기술자료 질의(048)는 `title^3`에서 제목에
  "해외출장자의 기술자료"가 있는 FAQ가 1위였지만, `title^1`에서는 특허 출원 예외를
  실제로 설명한 안내 책자가 1위다. 이는 제목 단어의 일치가 본문 근거보다 강하게
  작용한 사례다.
- **컷오프:** 끄면 1위 문서는 그대로이고, 근거가 빠졌던 033과 062의 검색 창에
  근거가 추가된다. 전체 근거 Recall 개선은 +2.2p, 대응표본 부트스트랩 95% 구간은
  [0, +5.8]p다. 컷오프는 순위 오류보다 검색 창의 누락을 만든다.
- **코퍼스 혼합:** docs 질의에 holdout을 섞자 원래 맞던 24문항의 원래 정답이
  1위에서 밀렸지만, 그중 4문항은 새 1위도 정답이었다. 보정 후 20문항이 1위를
  잃었고 1문항이 새로 맞았다. 1위 적중 차이는 −14.1p, 대응표본 부트스트랩
  95% 구간 [−20.7, −8.1]p다. 25단계에서 확인한
  인덱스별 BM25 통계 불일치가 가능한 메커니즘이지만, 이 단계에서는 통계 방식만
  바꾸는 대조 실험을 하지 않았으므로 손실 전부를 거기에 돌릴 수는 없다.

## 5. 이 과정에서 드러난 엔진 버그: 사본 판정

전체 코퍼스를 처음 색인했을 때 84,413청크 중 143청크(104부모)가 빠졌다.

- 원인은 `download_copy_key`였다. 이 함수가 경로를 버리고 **파일 이름만으로** 사본을
  판정했다. 그래서 `faq/113.html`과 `posts/69/113.html`처럼 번호만 같은 다른 문서가
  한 묶음이 됐고, FAQ 94건이 사본으로 지워졌다. 나머지 10건은 21·22차 고시 개정 zip
  안에 있는 같은 이름의 별표와 서식이었다.
- 정답 FAQ 3건(005, 009, 010)이 색인되지 않은 채 측정됐다. 평가의 `gold_missing_ids`는
  prepared jsonl을 기준으로 세기 때문에 이 누락을 잡지 못했다.
- **수정:** 판정 열쇠에 디렉터리를 넣었다([identity.py](../../../../search_engine/indexing/identity.py)).
  브라우저 사본은 원본 옆에 생기기 때문이다. docs에서 지우는 사본은 수정 전과 같은
  6건이고, holdout에서는 0건이다. 회귀 테스트를 추가했다.
- 재색인 후(84,413청크 전부) 수치는 위 표에 반영했다. 옛 인덱스와의 차이는 전체 조건
  근거 Recall@5가 0.870 → 0.891, 1위 적중이 0.739 → 0.754였다. 결론은 바뀌지 않는다.
- docs에서는 파일 이름이 겹치지 않아 드러나지 않았다. 데이터셋을 섞을 때 "조용히
  터지는 곳"이 실제로 나온 사례다.

## 판단

- **튜닝이 docs에 과적합돼 있다.** 같은 규모에서 1위 적중이 10.8p 떨어지고, 구간이
  0을 넘지 않는다.
- **당시 다음 후보: `title^1`과 컷오프 끄기.** 둘 다 튜닝 세트에서 손해가 없고 새 데이터에서
  이득이다. 채택하기 전에 변형 간 부트스트랩 구간을 재고, 미판정 1위를 채운다.
  판정은 이 69문항으로 한다. 이 69문항으로 값을 다시 고르면 그때부터는 이 세트도
  튜닝 세트가 되므로, 고를 후보는 위 두 가지로 제한한다.
- **27단계의 후보(문서 안 bm25 1위 청크 보존)도 이 세트로 판정한다.**
- 멀티 인덱스 BM25 통계 문제(25단계)는 시험 A에서 더 커졌다. `dfs_query_then_fetch`
  지연 측정이 여전히 남아 있다.

## 후속 확인: 제목 가중치와 인덱스 간 BM25 통계 (2026-09-24)

docs v2 135문항을 docs+holdout에서 같은 설정으로 다시 검색했다. 제목은 `title^3`과
`title^1`을 비교했고, BM25 어휘 검색은 기본 통계와 `dfs_query_then_fetch`를 비교했다.
기존 전체 상위 5위 감사에서 확정한 `gold`를 네 결과에 똑같이 적용했다.

| 설정 | 문서 1위 적중 | 반환 문서 Precision@5 | 평균 반환 문서 | 근거 Recall@5 | 근거 Precision@5 하한 |
|---|---:|---:|---:|---:|---:|
| 기존 | 0.807 | 0.596 | 2.39 | 0.856 | 0.199 |
| `title^1` | 0.822 | 0.627 | 2.30 | 0.863 | 0.221 |
| 전역 BM25 통계 | 0.822 | 0.704 | 2.03 | 0.863 | 0.218 |
| 둘 다 | **0.837** | **0.755** | **1.83** | 0.863 | **0.247** |

따라서 제목 가중치만이 원인은 아니다. 인덱스별 BM25 통계를 합치는 쪽이 문서 정밀도에
더 크게 작용한다. 두 설정을 코드에 반영했다. 새로 상위 5위에 든 문서 25쌍은 아직 추가
판정하지 않았으므로 개선 수치는 기존 라벨 기준이며, 특히 Precision은 하한이다.
같은 docs 질문 20개를 번갈아 호출한 소규모 지연 확인에서 중앙값은 기존 98.6ms,
수정 97.8ms였다. 이 표본에서는 뚜렷한 지연 증가가 없었다.
holdout 자체 69문항에서는 같은 라벨 기준으로 문서 1위 0.754→0.797, 반환 문서
Precision 0.539→0.584, 근거 Recall 0.891→0.877이었다. 근거 누락 퇴행도 함께
관찰되므로 후속 판정이 필요하다.

새 데이터 무응답 11문항은 기존 설정과 두 변경을 적용한 설정 모두 11건에서 문서를
반환했다. 상대 점수 컷오프는 답을 담지 않은 최상위 결과를 스스로 제거하지 못한다.
이 변경은 후보 노이즈를 줄이는 것이며, 무응답 포착은 별도 과제다.

## 한계

- 새 질의 69문항과 판정은 모두 assistant가 작성했다. 사람 검수는 대기 중이다.
  v2와 작성자 유형이 같아 작성 습관은 통제되지만, 사람이 쓴 질의와는 다를 수 있다.
- 새 데이터에는 2006~2010년 기사, 2단 편집 PDF, 영어 EAR 원문처럼 원래 더 어려운 문서가
  섞여 있다. "과적합"과 "더 어려운 데이터"를 완전히 가르지는 못한다. 다만 튜닝값을
  바꿨을 때 튜닝 세트는 그대로이고 새 데이터만 오른다(4절). 이 점은 과적합 쪽을
  가리킨다.
- 무응답 질의 11문항은 이번 단계에서 측정하지 않았다.
