# 27단계: 질의마다 검색 방식을 고르면 얻을 게 있는가

오라클 상한 측정(27.1), docs-only 결과로 라우터 학습(27.2), 현재 docs+Core에서 재학습(27.3)을 한 문서로 묶었다. **결론: 세 번 모두 채택하지 않았고 hybrid 고정을 유지한다.** docs-only 오라클 여지는 3문항분이었고, 학습 라우터는 hybrid를 넘지 못했다(44: −0.74%p, 45: +0.49%p, 구간이 0을 포함). 회수 가능한 손실은 방식 선택이 아니라 문서 안 청크 선택 문제였다.

> 원래 단계별 파일로 나뉘어 있던 기록을 주제별로 합쳤다. 질문을 검색 전에 동결했다는 증거는 각 단계의 개별 커밋에 남아 있으므로, 문서만 합쳤다. 원래 단계는 절 번호로 바꿨고, 절 제목의 옛 번호는 커밋 메시지·결과 파일명(`stage39` 등)과 대조할 수 있도록 괄호에 남겼다.

- 27.1 질의마다 검색 방식을 고르면 얻을 게 있는가 (2026-09-23)
- 27.2 오라클 이득을 학습해 질의별 검색 방식 선택
- 27.3 현재 docs+Core에서 조건부 검색 방식 전환

## 27.1 질의마다 검색 방식을 고르면 얻을 게 있는가 (2026-09-23) (옛 27단계)

지금은 모든 질의가 hybrid(BM25+dense RRF)를 탄다. 질의 성격에 따라 키워드만,
벡터만, 하이브리드를 골라 쓰면 나아지는지 묻는다. 라우터를 만들기 전에
**만들 가치가 있는지**부터 쟀다. 기준은 오라클 상한이다. 정답을 보고 나서 질의마다
가장 좋은 방식을 고른 점수이며, 어떤 라우터도 이 점수를 넘을 수 없다.

(26단계는 core 재수집을 통한 과적합 측정에 배정돼 있어 번호를 건너뛴다.)

**결론부터.** 라우터는 만들지 않는다. 오라클도 hybrid보다 근거 Recall@5가
**+0.022(3문항분)** 높을 뿐이다. 그 이득은 전부 bm25에서 오고, vector를 고를 수 있어도
hybrid에 더하는 것은 0이다. 질의만 보고 bm25를 고르는 규칙(식별자 규칙)은
0.904로 **hybrid보다 나쁘다.** 게다가 회수할 수 있는 손실의 실체는 방식 선택이 아니었다.
**같은 문서 안에서 어떤 청크를 싣느냐**의 문제였다.

### 조건

- 코퍼스 `search-docs-only`(docs 1,198청크), 기준일 2026-09-17, 현재 코드 그대로.
- 질의 `data/queries_docs_v2.jsonl` 135문항. 단, 25단계 커밋 `f866da5`가 core 사본
  2건(018, 020)을 공동 정답으로 더해서 docs 전용 검증기(`verify_gold`)가 거부한다.
  그래서 그 직전 판본(`f866da5^`)으로 돌렸다. 두 판본은 core 부모만 다르므로
  docs-only 채점 결과는 같다.
- `search-compare --repeats 1` → `data/generated/docs-v2/comparison-135q-stage27-modes.json`
- 분석: `scripts/evaluate_mode_oracle.py` → `data/generated/docs-v2/mode-oracle-135q.json`

hybrid 근거 Recall@5 0.9630은 25단계 docs-only 값과 같다. 재현은 확인됐다.

### 1. 오라클 상한

| 선택 | 근거 Recall@5 | 근거 MRR@5 |
|---|---:|---:|
| bm25 고정 | 0.8778 | 0.7007 |
| vector 고정 | 0.9222 | 0.8163 |
| **hybrid 고정 (현재)** | **0.9630** | **0.8179** |
| 오라클 (셋 중 최선) | 0.9852 | 0.9241 |
| 오라클 bm25+hybrid | 0.9852 | 0.9169 |
| 오라클 vector+hybrid | 0.9630 | 0.8250 |

- Recall 격차 +0.022는 문항으로 3건분이다(034, 074 각 1, 039·101 각 0.5).
  모두 bm25만 근거를 실은 경우다.
- MRR 격차(+0.106)는 크지만 대부분 hybrid가 근거를 2위에 두고 bm25가 1위에 둔
  경우다(27건 중 21건). 창 안의 청크는 모두 답변 모델에 실리므로 주 지표를
  바꾸지 않는다.

유형별 근거 Recall@5:

| 유형 | 질의 | bm25 | vector | hybrid | 오라클 |
|---|---:|---:|---:|---:|---:|
| identifier_article | 4 | 0.750 | 0.500 | 1.000 | 1.000 |
| identifier_mixed | 5 | 1.000 | 1.000 | 1.000 | 1.000 |
| identifier_number | 6 | 1.000 | 1.000 | 1.000 | 1.000 |
| multi_evidence | 18 | 0.861 | 0.833 | 0.917 | 0.944 |
| paraphrase | 34 | 0.853 | 0.956 | 0.985 | 1.000 |
| scenario | 68 | 0.882 | 0.941 | 0.956 | 0.985 |

"식별자 질의는 키워드로"라는 직관과 달리, 식별자 유형에서는 hybrid가 이미 만점이고
bm25 단독은 조항 질의에서 오히려 떨어진다.

### 2. 질의만 보고 고를 수 있는가

라우터는 검색 전에 질의만 본다. 가장 그럴듯한 특징으로 숫자, `제N조`, 영문 두 글자
이상(`IDENTIFIER` 정규식)을 골랐다.

- 135문항 중 95문항이 이 특징을 가진다. 한국어 행정 질의는 연도나 호수가 흔해서
  변별력이 없다.
- 규칙 "식별자면 bm25, 아니면 hybrid"의 근거 Recall@5는 **0.9037**이다.
  식별자 질의 중 bm25가 hybrid보다 나쁜 10건(053, 069, 083, 087, 095, 097, 104, 106,
  112, 130)이 이득 3건을 압도한다.
- bm25가 hybrid를 이긴 27건도 식별자 여부, 길이, 유형으로 갈리지 않는다(paraphrase
  5, scenario 14, multi 2, identifier 5).

이 규칙은 시험지를 본 뒤에 고른 것이므로 과대평가됐을 수 있다. 그런데도 진다.
다른 특징을 더 찾는 것은 같은 135문항에 맞추는 과적합이 되므로 하지 않는다.

### 3. 회수할 수 있던 손실의 실체

hybrid가 0이고 bm25가 1인 두 건(034, 074)을 열어 보면 **세 방식 모두 같은 문서를
1위로 찾았다.** 차이는 그 문서에서 실은 청크 6개였다.

| 질의 | 근거 청크 | bm25가 실은 청크 | hybrid가 실은 청크 |
|---|---|---|---|
| 074 | `#0003` | **#0003**, 0000, 0016, 0010, 0001, 0014 | 0012, 0015, 0005, 0009, 0010, 0014 |
| 034 | `#0000` | **#0000**, 0004, 0016, 0009, 0005, 0012 | 0004, 0012, 0013, 0008, 0011, 0009 |

20단계부터 hybrid는 문서 안 청크를 dense 순서로 고른다. 그래서 bm25가 1위로 올린
근거 청크가 창에서 밀려났다. 이것은 "어느 검색기를 쓸까"가 아니라
**문서 안에서 어느 청크를 싣느냐**의 문제이고, 라우팅으로는 풀 수 없다. 라우팅은
034를 얻는 대신 다른 곳에서 잃는다.

### 판단

- **채택하지 않는다.** 방식 라우팅의 상한은 3문항이고, 관찰 가능한 규칙은 손해다.
  hybrid 고정을 유지한다.
- **다음 후보(미측정):** hybrid의 문서 안 청크 선택에서, 어휘 검색기가 그 문서에서
  1위로 올린 청크를 dense 순서와 함께 보장해 싣는다(RRF 리더 보존을 청크 단위로
  내리는 것). 오라클 격차 3문항분(034, 074, 039, 101)이 **모두** 이 모양이다.
  039는 562호 문서의 `#0000`을, 101은 무형이전 문서의 `#0005`를 bm25만 실었다.
  이것도 이 135문항에서 발견한 것이므로, 판정은 26단계의 동결 질의로 해야 한다.

## 27.2 오라클 이득을 학습해 질의별 검색 방식 선택 (옛 44단계)

### 목적과 조건

27.1절의 오라클 결과에서 특징을 뽑아 검색 방식을 예측하면 이득을 회수할 수 있는지 시험했다. 운영 라우터는 변경하지 않았다. 입력은 당시 docs 135문항의 BM25·vector·hybrid 비교 결과 `data/generated/docs-v2/comparison-135q-stage27-modes.json`이다. **30.10절 현재 코드의 검색 결과가 아니라 27.1절의 역사적 결과를 재분석한 실험**이다.

오라클은 정답을 본 뒤 고른 상한이며, 학습 모델이 평가 질문의 정답을 보게 하면 의미가 없다. 그래서 정답 부모가 하나라도 겹치는 질문들을 연결해 33개 묶음으로 만들고, 5개 fold에 각 27문항을 배정했다. 각 평가 fold의 예측은 나머지 108문항으로 학습한 모델에서만 얻었다. 학습과 평가 사이 정답 부모가 겹치지 않는 것을 코드에서 검사한다. gold는 학습 목표와 분할·채점에만 사용하고, 추론 특징에는 넣지 않는다.

사전 설정은 `data/generated/routing-v1/protocol.md`에 실행 전에 작성했다. 이후 결과를 보고 특징이나 기준을 바꾸지 않았다.

### 모델과 특징

각 단독 검색 방식에 대해 hybrid 대비 **근거 Recall@5 이득**을 예측하는 깊이 2 회귀 트리를 학습했다. 잎 최소 8문항, 예측 이득이 0.02를 넘을 때만 가장 큰 이득의 방식으로 전환한다. 그 외에는 hybrid를 유지한다. MRR은 보조 지표로만 보고 학습 목표로 쓰지 않았다.

- 질문 모델: 길이, 단어 수, 숫자·영문 수, 조항·연도·인용 포함 여부, 의문 표현 수.
- 질문+결과 모델: 위 특징과 세 방식의 반환 부모·청크 수, 상위 5문서의 부모/청크 Jaccard 일치도, 1위 문서 일치 여부.
- 문서 이름, 질문 ID, 정답, 모범답안, 사람이 붙인 질문 유형은 특징에서 제외했다. 문서/청크 ID는 일치도 계산에만 사용했다.
- 원 보고서에 검색 점수가 없어 점수 격차는 시험하지 않았다. 결과 특징은 세 검색 결과를 이미 얻어야 계산되므로, 검색 비용을 줄이는 라우터가 아니다.

### 평가 결과

모든 라우터 값은 학습에 쓰지 않은 fold 예측을 합친 값이다.

| 방식 | 근거 Recall@5 | 근거 MRR@5 | hybrid 대비 Recall 개선/악화 문항 |
|---|---:|---:|---:|
| hybrid 고정 | 0.96296 | 0.81788 | — |
| BM25 고정 | 0.87778 | 0.70069 | 4 / 16 |
| vector 고정 | 0.92222 | 0.81630 | 0 / 7 |
| 정답을 보고 선택하는 오라클 | 0.98519 | 0.92407 | 4 / 0 |
| 질문 특징 라우터 | 0.92222 | 0.77325 | 1 / 7 |
| 질문+결과 특징 라우터 | 0.95556 | 0.80660 | 1 / 2 |

질문 모델은 38문항을 BM25로 전환했다. 질문+결과 모델은 16문항을 BM25로 전환했다. vector의 Recall 개선 사례가 없어 두 모델 모두 vector를 선택하지 않았다. 이는 벡터가 모든 측면에서 불필요하다는 뜻은 아니다. MRR 개선은 학습 목표 밖이다.

33개 문서 묶음 단위 paired bootstrap 5,000회로 구한 hybrid 대비 Recall 차이의 참고용 95% 구간:

- 질문 모델: −4.07%p, 구간 [−7.30, −1.06]%p.
- 질문+결과 모델: −0.74%p, 구간 [−1.86, 0.00]%p.

### 어떤 특징을 배웠고 왜 실패했는가

질문 트리는 주로 질문 길이와 단어 수를 사용했다. 결과 특징을 허용한 트리는 주로 BM25·vector의 청크 일치도와 hybrid가 반환한 청크 수를 사용했다. 분할 특징은 fold마다 달라 보편적인 규칙으로 확정하지 않는다.

질문+결과 모델의 실질적인 Recall 변동은 다음 세 문항이다.

| 질문 | hybrid → 선택한 BM25 Recall | 영향 |
|---|---:|---|
| docs-v2-101 | 0.5 → 1.0 | 근거 한 그룹 회수 |
| docs-v2-095 | 1.0 → 0.0 | 근거 전체 손실 |
| docs-v2-112 | 1.0 → 0.5 | 근거 한 그룹 손실 |

같은 무형이전 자료를 묻는 095와 101은 동일한 평가 묶음에 있어 해당 문서의 질문을 학습에서 보지 않았다. 모델은 101에서 올바르게 전환했지만 095에서도 전환해 더 큰 손실을 냈다. **검색 결과가 비슷하게 겹친다는 사실만으로 어느 방식이 정답 근거를 보존했는지는 구분하지 못했다.**

Recall을 개선할 수 있는 질문은 오라클에서도 4개, 총 3문항분에 불과하다. 적은 양성 사례로 그보다 많은 전환 손실을 피하는 규칙을 학습하기 어려웠다. 이는 이번 모델과 자료에서 관찰한 결과이며, 모든 라우터가 불가능하다는 증명은 아니다.

### 판단과 한계

**채택하지 않는다.** 질문+결과 모델도 hybrid 고정의 Recall과 MRR을 넘지 못했다. 결과를 보고 트리 깊이·특징·전환 기준을 반복 조정하지 않는다. 현재 서비스 검색 방식은 그대로 유지한다.

문서별 분할은 같은 문서를 묻는 유사 질문의 누수를 줄였지만, 원 자료는 과거 분석과 검색 튜닝에 이미 사용했다. 사람 검수 전 gold의 한계도 있다. 이번 구간을 독립적인 일반화 검정으로 주장하지 않는다. 현재 코드에서의 효과, 새로운 도메인에서의 효과는 미측정이다. 향후 후보를 채택하려면 현재 검색 결과로 학습 데이터를 수집하고, 모델과 특징을 동결한 뒤 새로운 문서·질문으로 평가해야 한다.

### 재현과 검증

```sh
.venv/bin/python -m scripts.evaluate_learned_router \
  data/generated/docs-v2/comparison-135q-stage27-modes.json \
  --out data/generated/routing-v1/oof-stage27.json
```

결과 파일에는 입력 SHA256, 문서 묶음과 fold 배정, fold별 트리, 질문별 예측 이득·선택·실제 점수가 들어 있다. 세 방식의 질문·근거 라벨 일치, fold의 완전한 분할, 학습·평가 정답 부모 비중첩을 실행 시 검증했다. 같은 명령을 다시 실행해 결과 파일이 동일함을 확인했다. 표준 라이브러리만 사용하며 운영 의존성은 추가하지 않았다.

## 27.3 현재 docs+Core에서 조건부 검색 방식 전환 (옛 45단계)

### 조건과 사전 설정

27.2절은 27.1절 당시 docs-only 결과를 재분석했다. 이번에는 사용자 요청대로 **현재 코드로 docs+Core를 함께 검색**했다.

- Core: `search-holdout-v20260923102126-0143e7`, 84,413청크.
- docs: `search-docs-only-v20260918101819-0ae9e1`, 1,198청크.
- 합계 85,611청크. 별칭을 실제 인덱스 이름으로 해석해 실행 중 고정했다. 옛 기본 `search-documents` 인덱스를 추가한 조건은 아니다.
- 주 평가: docs 135문항 + holdout 69문항 = 204문항. 30.9절 결과 파일에서 당시 보정된 질문·정답을 추출했다.
- 별도 평가: validation-v2 core+docs 반환 정답 보정본 36문항. 모델 학습·기준 선택에 사용하지 않았다.
- 날짜 2026-09-25로 고정, k=5, 후보 깊이도 5, 반복 1회, 재작성 끔. BM25·vector·hybrid를 모두 같은 설정·정답으로 채점했다. 현재 검색 코드는 수정하지 않았다.

84,413과 1,198건의 색인 건수·임베딩 존재·차원을 확인하고, 질문의 근거 청크 존재·부모 ID·기록된 인용을 검사했다. 전체 코퍼스 본문을 준비 파일과 일대일 대조한 검증은 아니다. docs 018·020에 옛 Core에서 추가했던 `yestrade-form-22209#0002`, `yestrade-form-23307#0000`은 현재 두 인덱스에 없다. 해당 두 대안만 평가 범위에서 제외하고 현재 색인된 대체 정답을 유지했다. 근거 요구사항이 통째로 사라진 질문은 없다. 원본 정답 파일은 변경하지 않았다.

사전 설정: `data/generated/routing-combined-v1/protocol.md`. 질문 파일, 원본 SHA256, 실행 설정과 인덱스, 현재 검색 코드 SHA256은 같은 폴더에 남겼다.

### 하이브리드 기본, 예상 이득이 있을 때만 전환

27.2절과 같은 특징·깊이 2 회귀 트리·잎 최소 8문항·예측 Recall 이득 0.02 초과 기준을 사용했다. 결과를 보고 조정하지 않았다.

204문항의 정답 부모 연결 성분 84개를 5개 fold(41/41/41/41/40문항)로 나눴다. 각 질문은 자신이 속한 fold를 학습하지 않은 모델로 예측했다. 같은 정답 부모가 학습·평가 양쪽에 있는 것을 금지했다. 전체 정답 부모가 다른 질문 사이 부분 근거 출처까지 완전히 분리한 검증은 아니다.

### 주 평가 결과

| 방식 | 근거 Recall@5 | 근거 MRR@5 | Recall 개선/악화 문항 |
|---|---:|---:|---:|
| 하이브리드 고정 | 0.86765 | 0.74688 | — |
| BM25 고정 | 0.71078 | 0.56555 | 5 / 39 |
| vector 고정 | 0.82108 | 0.72102 | 4 / 14 |
| 정답을 보고 최선 선택 | 0.90686 | 0.82207 | 9 / 0 |
| 질문 특징으로 조건부 전환 | 0.83824 | 0.72695 | 1 / 8 |
| 질문+결과 특징으로 조건부 전환 | **0.87255** | 0.73912 | 2 / 1 |

질문+결과 모델은 173문항에서 hybrid를 유지하고 19개를 BM25, 12개를 vector로 전환했다. 근거 Recall은 **+0.49%p**다. 문서 묶음 단위 paired bootstrap 5,000회의 참고용 95% 구간은 **[−1.12, +2.37]%p**로 0을 포함한다.

| 질문셋 | hybrid Recall | 질문+결과 전환 Recall |
|---|---:|---:|
| docs 135 | 0.86296 | 0.87037 |
| holdout 69 | 0.87681 | 0.87681 |

### 정밀도와 순위의 비용

| 지표, 204문항 | hybrid 고정 | 질문+결과 전환 |
|---|---:|---:|
| 문서 1위 적중 | 0.82353 | 0.81863 |
| 문서 Hit@5 | 0.89216 | 0.89706 |
| 반환 문서 Precision@5 하한 | 0.70572 | 0.69747 |
| 근거 Precision@5 하한 | 0.28043 | 0.27625 |
| 근거 MRR@5 | 0.74688 | 0.73912 |

Recall이 조금 올랐지만 다른 주요 지표가 함께 좋아진 것은 아니다. Precision은 기존 정답 라벨 기준 하한이다. BM25·vector가 새로 반환한 모든 문서/청크를 전수 판정하지 않았으므로, 표의 감소를 실제 무관한 결과 증가로 단정하지 않는다. 다만 동일한 고정 라벨에서 하이브리드를 대체할 일관된 이득은 확인하지 못했다.

질문+결과 전환에서 실제 근거 Recall이 변한 세 문항:

| 질문 | 선택 | hybrid → 전환 Recall |
|---|---|---:|
| docs-v2-074, 청년인턴 증명서 제출 방식 | BM25 | 0 → 1 |
| holdout-v1-004, 국내 외국 대사관 납품 | BM25 | 0 → 1 |
| holdout-v1-040, 수중익선 통제 조건 | BM25 | 1 → 0 |

서로 다른 두 실패는 회수했지만, 하이브리드가 이미 맞힌 한 질문을 잘못 전환했다. 특정 세 질문을 보고 예외 규칙을 추가하지 않았다. vector 전환 12개는 이 평가에서 Recall 증가나 감소를 만들지 않았다.

### 별도 36문항 평가

204문항 전체로 학습한 뒤 별도 36문항을 예측했다. 이 질문들의 라벨은 모델 학습에 사용하지 않았다. 정답 부모가 학습 자료와 겹치는 5문항은 표시하고, 나머지 31문항도 따로 채점했다.

| 방식 | 별도 36 Recall | 정답 부모 분리 31 Recall |
|---|---:|---:|
| hybrid | 1.000 | 1.000 |
| BM25 | 0.88889 | 0.87097 |
| vector | 0.88889 | 0.87097 |
| 질문 특징 전환 | 1.000 | 1.000 |
| 질문+결과 전환 | 1.000 | 1.000 |

질문+결과 모델은 36문항 중 19개를 vector로 전환했지만 Recall·MRR은 hybrid와 같았다. hybrid가 이미 Recall 100%여서 개선 능력을 입증하는 자료가 되지는 않는다. 또한 이 36문항은 기존 검색 개발 과정에서 사용한 자료이므로, 완전히 새로운 독립 최종 시험이라고 주장하지 않는다.

### 판단

**운영에는 채택하지 않고 hybrid를 유지한다.** docs-only와 달리 합친 코퍼스에서는 오라클 Recall 여지가 +3.92%p이고 vector 개선 사례도 있지만, 현재 특징으로 실제 회수한 이득은 +0.49%p에 그쳤다. 불확실성 구간은 0을 포함하며 정밀도·순위도 개선되지 않았다. 이번 결과로 임계값을 재튜닝하지 않는다.

이 실험은 방식 전체 전환을 다룬다. 하이브리드 문서 선택은 유지하면서 문서 내 BM25 근거 청크만 보완하는 방법은 아직 이번 조건에서 시험하지 않았다.
