# 43단계: 임베딩 입력에 메타데이터 필드를 하나씩 넣어 법령 검색을 비교 (2026-10-06)

법령·고시 100문서·4,633청크·100문항에서 dense와 SPLADE의 입력에 메타데이터 한 줄을 한 번에 하나씩 더하고, dense·SPLADE·hybrid의 청크 Recall과 Precision을 쟀다. 필드 10개 × 검색기 2개 = 20개 arm과, 조건을 통과한 필드를 모은 조합 arm 1개다.

**상태: 반영하지 않는다.** 운영 인덱스·별칭·컷오프·모델·색인 코드는 바꾸지 않았다. 실험 스크립트만 추가했다.

## 판단

- 어떤 필드도 hybrid 청크 회수를 뚜렷하게 올리지 못했다. 단독 필드 20개의 hybrid 회수는 88~92/100(기준 91)이고, 한 문항 차이는 잡음 범위다.
- SPLADE에 넣은 필드는 대체로 해로웠다. `doc_status`·`revision_date`·`columns`는 hybrid가 91→88/100으로 내려갔다. 질문 001·012·020·093을 반복해서 잃었다.
- dense에 넣은 필드는 대체로 중립이거나 한 문항 안팎의 이득이었다. 그중 `doc_type`·`published_at`·`columns`가 hybrid 91→92/100이다. `doc_number`는 89, `issuer`는 90으로 내려갔다.
- 조합 arm(dense 8개 필드 + SPLADE 2개 필드)은 hybrid 91→92/100, MRR 0.798→0.823이지만, 이 조합은 같은 100문항의 결과를 보고 골랐다. 선택 편향이 있어 일반화 근거로 쓰지 않는다. 청크 Precision(하한)은 0.558→0.553으로 그대로다.
- 기본 입력은 dense `title + heading_path + body`, SPLADE `title + body`를 유지한다. 판본 표지(`doc_status`, 연도)를 입력에 넣는 방식으로는 옛 판이 앞서는 문제가 풀리지 않았다.

## 읽는 법

- **한 문항 차이는 잡음이다.** 질문 100개에 정답 그룹이 하나라서 청크 Recall이 이진이고 한 문항이 1%p다. 20개 arm의 hybrid 변화는 −3~+1이다. 아래 쌍체 부트스트랩으로 확인했다.
- **SPLADE 입력에 필드를 넣으면 단독 SPLADE는 변화가 거의 없는데 hybrid가 떨어지는 경향이 있다.** 42단계의 SPLADE 경로 추가와 같은 모양이다(단독 ↑, hybrid ↓). 반복해서 잃은 질문 001·012·020·093은 RRF 순위가 조금만 밀려도 95% 컷오프를 못 넘는 경계 질문으로 보이지만, 이번에 후보·컷오프 단계를 추적하지는 않았다.
- **dense에서 `doc_number`·`issuer`가 내려간 이유는 확인하지 않았다.** 번호·기관명이 본문 의미 신호를 희석했을 가능성이 있지만 추정이다.
- **판본 표지가 옛 판 문제를 풀지 못한다.** `doc_status`·`published_at`·`effective_from`을 dense에 넣어도 hybrid 회수는 91~92로 그대로다. 임베딩에 넣는 것은 판본을 구분하게 만들 뿐 최신 판을 앞세우지 않는다. 순위 규칙이 따로 필요하다는 앞의 판단과 일치한다.
- **조합 arm은 선택 편향이 있다.** 같은 100문항에서 통과한 필드만 모았으므로 +1·MRR +0.025를 개선으로 읽으면 안 된다. 일반화 여부는 이 질문으로 검증할 수 없다.
- **Precision은 컷오프를 건 라벨 하한이다.** 모든 arm이 0.53~0.56으로 모여 있어 입력 변경이 컷오프 뒤 반환 청크 구성을 바꾸지는 못했다.

## 쌍체 부트스트랩

arm 21개를 기준과 비교해 dense·SPLADE·hybrid 각각의 청크 Recall, MRR, 청크 Precision(하한) 변화를 질문 100개 재표집(5,000회)으로 구간 추정했다. `scripts/paired_bootstrap.py`의 구간 함수를 재사용했고, 구간이 0을 포함하지 않으면 별표를 붙였다. 전체 수치는 `bootstrap.json`에 있다.

**hybrid, 구간이 0을 포함하지 않은 경우**

| arm | 지표 | 변화 | 95% 구간 |
|---|---|---:|---|
| dense + columns | MRR | +0.012 | [+0.000, +0.028] |
| dense + published_at | MRR | +0.009 | [+0.000, +0.021] |
| SPLADE + issuer | MRR | −0.016 | [−0.036, −0.000] |
| SPLADE + revision_date | MRR | −0.018 | [−0.037, −0.002] |
| dense + doc_number | Precision | −0.018 | [−0.039, −0.000] |
| dense + superseded_by | Precision | −0.015 | [−0.032, −0.001] |
| SPLADE + columns | Precision | −0.028 | [−0.054, −0.005] |
| SPLADE + doc_status | Precision | −0.026 | [−0.047, −0.007] |
| SPLADE + revision_date | Precision | −0.018 | [−0.031, −0.007] |

- **청크 Recall은 hybrid 20개 arm과 조합 arm 모두 구간이 0을 포함한다.** 조합 arm도 +0.010 [−0.020, +0.050]이고 MRR +0.025 [−0.006, +0.060]이다. 91→92/100은 기준과 구분되지 않는다.
- **구간 189개(arm 21 × 모드 3 × 지표 3) 중 0을 제외한 것은 11개(5.8%)다.** 효과가 전혀 없어도 5% 수준(약 9~10개)은 우연히 나오는 크기라서, 이 11개를 개별 효과로 읽지 않는다. 다중 비교 보정은 하지 않았다. 구간 경계가 0에 닿은 것(±0.000)이 여럿이라 재표집 시드에 따라 달라질 수 있다.
- **방향은 일관된 쪽이 하나 있다.** hybrid에서 0을 제외한 Precision 5개가 모두 감소이고, 그중 4개는 SPLADE 입력 변경이거나 dense `doc_number`·`superseded_by`다. SPLADE에 필드를 넣으면 hybrid Precision이 내려간다는 위 관찰과 방향은 같지만, 개별로는 보정 전 유의성이라 약한 근거다.
- **이득 쪽 구간은 hybrid에서 MRR 두 개뿐이고, 모두 하한이 0에 닿는다.** 입력에 필드를 넣어 얻는 이득은 이 질문 셋으로는 입증되지 않는다.
- 이 결론은 반영하지 않는다는 판단을 바꾸지 않는다.

## 해석 범위

- 질문은 본문을 보고 만든 점검용 100문항이다. 새 자료에서의 성능이나 생성 답변 정확도는 측정하지 않았다.
- 필드는 한 번에 하나만 넣었다. 필드 간 상호작용은 조합 arm 한 개로만 봤다.
- 입력 표현(라벨 문구, 줄 위치)은 한 가지만 시험했다. SPLADE의 256토큰 제한 때문에 줄을 더하면 잘림이 늘 수 있고, 이 영향은 분리하지 않았다.
- 파인튜닝 SPLADE C는 `title + body`로 학습됐다. 입력 분포를 바꾼 이번 SPLADE arm의 손실에 이 불일치가 얼마나 기여했는지는 모른다.

## 재현

```bash
.venv/bin/python scripts/law/ablate_embedding_fields.py            # 약 1시간, 끊겨도 이어서 실행
.venv/bin/python scripts/law/ablate_embedding_fields.py --fields doc_status --skip-all-arm   # 필드 하나만
```

- 스크립트: `scripts/law/ablate_embedding_fields.py`, 구간 추정은 `scripts/law/bootstrap_embedding_fields.py`
- 원자료: `data/generated/embedding-fields-2026-10-06/arms/*.json`(arm별 질문 단위 결과·반환 창), `metadata.json`(기준 인덱스·모델·컷오프·SHA-256·필드 채움), `vectors/`(dense 벡터)
- SPLADE arm은 기준 인덱스를 복제한 임시 인덱스에서 채점하고 arm마다 지운다. 운영 별칭은 건드리지 않는다.
