# 35단계: 전략물자 도메인으로 SPLADE를 파인튜닝했다 (2026-10-01)

24단계에서 학습된 SPLADE(`telepix/PIXIE-Splade-v1.5`)를 그대로 쓰면 BM25+dense hybrid보다
첫 문서 정확도가 높았다. 다만 약점이 남았다. 전략물자 수출입고시 주변에 비슷한 문서가
촘촘히 겹치는 구간(`docs-v2-019`, `127`, `128`)이다. BM25는 고정이지만 SPLADE는
재학습할 수 있으므로, **전략물자 도메인 질의로 확장 가중치(어휘는 그대로)를 맞추면 이
구간이 좋아지는지** 확인했다.

**결론부터.** 좋아지지 않았다. 오답 후보 오염을 고친 뒤에도 가장 나은 설정이 기준
모델과 같거나 1문항 낮았고, 이긴 문항은 1개(`006`), 진 문항은 2개(`040`, `083`)였다.
겨냥한 `019`, `127`, `128`은 하나도 고쳐지지 않았다. 이 규모(질의 108개)와 방식으로는
파인튜닝을 채택할 근거가 없다. 운영 기본값과 24단계의 판단은 바뀌지 않는다.

## 조건

**학습 환경.** 맥 M1 Pro(통합 메모리 16GB)의 MPS다. Docker(Colima)는 맥 GPU를 쓰지
못해 별도 가상환경(Python 3.12, torch 2.14, transformers 5.18)에서 돌렸다. 배치 4,
길이 256에서 한 스텝이 약 0.9초, 메모리는 1.8GB였다. 모델은 1.5억 파라미터, 어휘
50,000이다.

**학습 청크.** docs 1,198청크에서 `전략물자`·`이중용도`·`전략기술`·`수출허가`·`통제품목`·
`캐치올`이 제목과 본문에 합쳐 2번 이상 나오고, 본문이 150자 이상이며, **평가 질의
(`queries_docs_v2*`)의 근거 청크가 아닌** 97청크를 골랐다. 대외무역법 시행령은 hwp,
hwpx, pdf 세 사본이 있어 같은 조문이 세 번 들어 있다. 고르는 코드는
`scripts/splade_finetune/select_chunks.py`다.

**합성 질의.** 겹치는 사본을 빼고 내용이 있는 54개 청크 위치마다 질의를 2개씩, 모두
108개를 Claude가 직접 썼다(`synth_queries.py`). 서식 빈칸이나 목차만 있는 청크는
뺐다. 질의는 정답 청크의 표현을 그대로 베끼지 않고 구어체와 격식체를 섞었다. 이
질의는 학습 전용이고 평가에는 쓰지 않았다. 새 질의 생성은 사전에 확인을 받았다.

**오답(hard negative).** 기준 모델로 1,198청크를 모두 인코딩해 질의별 상위 30개를
후보로 뽑고, 정답과 **같은 본문의 다른 형식 사본**은 오답에서 뺐다(30자 조각을 공유하는
청크). 배치마다 질의당 후보 1개를 뽑고 같은 배치의 다른 문서는 in-batch 오답으로 썼다.

**학습.** 손실은 `CrossEntropy(질의·문서 내적) + λ_q·FLOPS(질의) + λ_d·FLOPS(문서)`다.
AdamW, weight decay 0.01, 선형 감쇠, 배치 4, 문서 256토큰, 질의 64토큰이다.

**평가.** 24단계와 같은 `scripts/evaluate_splade.py`로 `data/queries_docs_v2.jsonl` 135문항,
문서 단위 P@1을 쟀다. 기준은 이번 환경에서 다시 쟀고 130/135(96.3%)였다. 24단계 문서의
129/135(95.6%)와 1문항 다르며, 이번 비교는 모두 이 환경의 기준과 맞췄다.

## 첫 시도와 그 결과

| 설정 | lr | 에폭 | λ_q / λ_d | P@1 (기준 130) |
|---|---:|---:|---|---:|
| a | 5e-6 | 3 | 3e-4 / 1e-4 | 126 |
| b | 2e-6 | 2 | 0 / 0 | 129 |
| c | 1e-6 | 2 | 1e-5 / 1e-5 | 128 |
| d | 2e-6 | 3 | 0 / 0 (오답 후보 8개) | 128 |

모든 설정이 기준보다 낮았다. 설정 a는 이긴 문항이 없고 4문항을 졌으며, 전략물자와 무관한
`083`(중싱통신 보고서)까지 틀렸다.

학습 손실(CE)은 5스텝 안에 0 근처로 떨어졌다. 기준 모델이 합성 질의의 정답을 이미
1위에 두기 때문에 **배울 신호가 거의 없었다.** 신호가 약한 학습에서 움직인 것은 대부분
정규화 항이었고, 설정 a에서 문서당 term 수가 1,458에서 520으로 줄었다.

## 설계 오류를 찾았다: 오답 후보에 평가 정답이 섞였다

평가 질의의 근거 청크는 학습 **정답**에서만 뺐고 **오답 후보**에서는 빼지 않았다. 설정
d의 질의별 상위 5개 오답 540건을 확인하니 **124건(23%)이 평가 질의의 근거 청크**였고,
31개 평가 질의에 걸려 있었다. 모델은 한 질의에서 그 청크를 오답으로 배우고, 같은 청크가
정답인 다른 평가 질의에서 점수를 잃는다. b~d에서 잃은 `018`, `040`, `130`이 모두 이 31개
안에 있었다. 상관이 확인된 것이며 인과가 증명된 것은 아니다.

따라서 위 표는 "파인튜닝이 안 된다"의 증거가 아니라 **잘못 설계한 학습의 결과**다.

## 오염을 고쳐 다시 돌렸다

오답 후보에서 `queries_docs_v2*`의 모든 근거 청크와 그 사본(같은 본문의 다른 형식), 모두
144청크를 뺐다. 나머지는 그대로 두고 세 설정을 다시 돌렸다.

| 설정 | P@1 (기준 130) | 이긴 문항 | 진 문항 | Hit@5 (ratio 0.97) | 반환분 P | MRR@5 | 문서당 term |
|---|---:|---|---|---:|---:|---:|---:|
| 기준 (PIXIE 그대로) | 130 | - | - | 0.970 | 0.916 | 0.967 | 1,458 |
| a2 (a와 같은 값) | 127 | 없음 | 040, 083, 089 | 0.956 | 0.899 | 0.946 | 520 |
| b2 (b와 같은 값) | 129 | 006 | 040, 083 | 0.956 | 0.931 | 0.956 | 1,503 |
| c2 (c와 같은 값) | 128 | 없음 | 040, 083 | 0.963 | 0.933 | 0.953 | 1,425 |

- 오염을 고친 뒤 손실이 줄었다(a 126 → a2 127, 나머지는 129와 128). 오염이 일부 해를
  끼쳤지만 이득으로 바뀌지는 않았다.
- `040`(수출의 정의와 면세점)과 `083`(중싱통신 보고서)은 세 설정 모두에서 졌다. 전략물자
  도메인과 거리가 있는 질의의 순위를 도메인 학습이 밀어낸다.
- 기준이 틀리는 다섯 문항(`006`, `007`, `019`, `020`, `123`) 가운데 고친 것은 b2의
  `006` 하나다. 겨냥한 `019`, `127`, `128`은 그대로다.
- 반환분 정밀도는 b2와 c2가 0.931과 0.933으로 기준(0.916)보다 약간 높다. 그러나 P@1과
  MRR이 낮아 전체 이득으로 보지 않는다. 문서당 term이 줄어드는 효과는 정확도 손실과
  맞바꾸는 것이어서 이번 목표와 별개다.

## 판단

**채택하지 않는다.** 가장 나은 b2도 기준 대비 1문항 낮고, 이긴 문항은 1개, 진 문항은
2개다. 135문항에서 1~2문항 차이는 노이즈 범위일 수 있으나, 이득이 있다고 말할 근거도
없다.

원인으로 보이는 것은 세 가지다.

1. **신호가 약하다.** 기준이 합성 질의를 이미 푼다. 약점인 `019`, `127`, `128`은 질의-문서
   매칭이 아니라 **서로 비슷한 문서 사이의 구분** 문제여서, 청크 하나에서 질의 두 개를
   뽑는 방식으로는 가르치지 못한다.
2. **데이터가 작고 단조롭다.** 질의 108개를 한 사람(Claude)이 썼다. 1.5억 파라미터를
   움직이기에 너무 적고, 문체 다양성이 낮다.
3. **기준이 높다.** 96.3%에서는 올릴 여지가 작고 내릴 여지가 크다.

## 한계

- **평가 세트로 설정을 골랐다.** 설정 세 개를 docs_v2 135문항에서 비교했다. 튜닝에
  쓰인 세트이므로 이 점수는 낙관적이다. 그래도 기준을 넘지 못했으니 결론은 바뀌지 않는다.
- **홀드아웃은 재지 않았다.** docs_v2에서 이미 기준보다 낮아 의미가 없다고 봤다.
- **사본 누출은 확인하지 않았다.** 평가 근거 청크는 학습 정답에서 뺐지만, 그 청크의 다른
  형식 사본이 학습 정답으로 들어갔는지는 따로 검사하지 않았다.
- **설정이 세 개다.** 학습률, 에폭, 정규화, 오답 후보 수를 넓게 훑지 않았다. "이 방식으로는
  이득이 없다"이지 "파인튜닝이 원리적으로 안 된다"가 아니다.
- **어휘 확장은 하지 않았다.** 어휘는 그대로 두고 가중치만 바꿨다. 도메인 용어를 토크나이저에
  추가하려면 MLM 이어학습이 먼저 필요한데, 이 맥(16GB)에서는 무겁다.

## 다음에 해볼 수 있는 것

- 약점 구간(`019`, `127`, `128`)에 맞춘 **구분형 질의**를 쓴다. 비슷한 두 조문 중 한 조문만
  정답이 되는 질문과 그 구간 전용 오답이 필요하다. 새 질의 생성이라 사전 확인이 필요하다.
- 파인튜닝을 접고 24단계의 채택 조건(미판정 청크 판정, 필터 적용 후 hybrid와 재비교,
  온라인 지연과 인덱스 크기 측정)으로 PIXIE를 그대로 hybrid에 붙인다.

## 재현

```bash
python3 scripts/splade_finetune/select_chunks.py train_chunks.json   # 학습 청크 97개
cd <작업 폴더>   # train_chunks.json, synth_queries.py, train_splade.py가 있는 곳
python train_splade.py --out ckpt-b2 --lr 2e-6 --epochs 2 --lam_q 0 --lam_d 0
python scripts/evaluate_splade.py --corpus data/generated/docs-v2/review-corpus/docs.jsonl \
  --queries data/queries_docs_v2.jsonl --model ckpt-b2 --batch-size 8 --max-length 256 \
  --out eval-ckpt-b2.json
```

`run_cfg.sh`가 학습, 평가, 기준 대비 요약을 한 번에 돌린다. 학습 환경은 MPS를 쓰는 맥이며
`PYTORCH_ENABLE_MPS_FALLBACK=1`이 필요할 수 있다. `train_splade.py`는 `train_chunks.json`과
`synth_queries.py`를 현재 폴더에서 읽고 저장소 절대 경로(`REPO`)가 코드에 박혀 있으므로
다른 환경에서는 경로를 고쳐야 한다. 체크포인트와 평가 원자료는 스크래치패드에만 있고
저장소에는 넣지 않았다.
