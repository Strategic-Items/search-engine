# 34단계: 어휘 검색에서 효과 없는 장치를 걷어낸다 (2026-09-29)

어휘 검색에는 처음 설계할 때 넣고 한 번도 넣고 뺀 비교를 하지 않은 장치가 있었다. 각 장치가 지금 색인에서 실제로
영향을 주는지 세고, 하나씩 빼고 재검색해 결과를 비교했다.

**결론부터.**

| 장치 | 판정 | 근거 |
|---|---|---|
| `.standard` 부속 필드(제목 1.5, 본문 0.5) | **쿼리에서 뺐다** | 개발 셋 차이가 한두 문항이고 방향이 엇갈림. 식별자 질문 22개에서는 있는 쪽이 1문항 앞섬 (34.1) |
| 문서 종류 부스트(`INTENT_HINTS`, 가중치 14) | **지웠다** | 대상 종류값이 색인에 0개, 빼도 결과가 같음 (34.2) |
| 현행판 우대(`superseded_by`, +4) | 유지 | 죽은 코드가 아니다. 모든 문서에 붙는 상수 +4로 작동하며 빼면 손해가 나는 쪽 (34.3) |
| `period_hint` 가산점(+4) | 유지 | 지금 값이 0~1개라 판단할 근거가 없음. 재색인 뒤 재확인 (34.2, 다음 작업) |
| 시행일 필터(`effective_from/to`) | 유지 | 지금 값이 0개라 항상 통과. 기준일 기능이라 성능이 아닌 정확성의 문제 (34.2) |
| 동의어 확장(20개 그룹) | 유지 | 있고 없고의 차이가 잡음 수준이지만, 지우려면 색인 설정을 바꿔 다시 만들어야 함 (34.4) |

## 조건

- 현재 코드에서 `build_query`의 `multi_match.fields`만 바꿔 재검색했다. dense 검색과 나머지 설정은 그대로다.
- 판정자·재작성·리랭커·LLM 청크 필터는 끄고 k=5, 기준일 2026-09-29에 재검색했다.
- 청크 컷오프는 걸지 않았다. 정답표는 28단계 판정을 반영한 것이다.
- 개발 셋: docs 135(`core,docs` 검색), holdout 69(`core` 검색). 식별자 질문은 두 셋의 `identifier_*` 범주다.
- 열은 청크 5개(Hit@5, Recall@5, MRR@5, Precision, 평균 청크)와 문서 5개(같은 다섯 가지)다. 청크 Precision은 하한이다.
- 재현: `scripts/ablate_lexical_devices.py`가 장치를 하나씩 켜거나 빼고 같은 질의를 다시 검색한다. 예:
  `.venv/bin/python scripts/ablate_lexical_devices.py --report data/generated/holdout-v1/results/holdout-title1-dfs-top5-audited.json --datasets core --alias search-holdout`
  (`--category-prefix identifier`로 식별자 질문만). 위 표는 28단계 판정을 반영한 정답표로 채점했다.

## 34.1 `.standard` 부속 필드

`title.standard^1.5`, `body.standard^0.5`는 첫 커밋(`f91d5a3`, 2026-09-15)부터 있었고, 설계 문서는 "nori가 잘못 쪼갠 경우의 보험"이라고 적는다([retrieval_v1.md](../../../design/retrieval_v1.md)). 넣은 것과 뺀 것을 비교한 기록은 없었다. 쿼리에서만 뺐고 색인 매핑의 하위 필드는 그대로 둔다(재색인 불필요).

### 전체 질의셋

| 질의셋 | 필드 | 청크 Hit | 청크 Recall | 청크 MRR | 청크 Precision | 평균 청크 | 문서 Hit | 문서 Recall | 문서 MRR | 문서 Precision | 평균 문서 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| docs 135 | 현재(`.standard` 있음) | 0.904 | 0.893 | 0.752 | 0.252 | 6.33 | 0.904 | 0.813 | 0.869 | 0.773 | 1.76 |
| docs 135 | 없음 | 0.911 | 0.896 | 0.758 | 0.252 | 6.36 | 0.911 | 0.816 | 0.879 | 0.789 | 1.70 |
| holdout 69 | 현재 | 0.913 | 0.891 | 0.768 | 0.351 | 6.71 | 0.899 | 0.639 | 0.844 | 0.613 | 2.51 |
| holdout 69 | 없음 | 0.899 | 0.884 | 0.759 | 0.354 | 6.94 | 0.899 | 0.640 | 0.821 | 0.611 | 2.77 |

docs 135는 빼면 조금 좋아지고(Hit 1문항), holdout 69는 조금 나빠진다(Hit 1문항). 문항 하나가 각각 0.7p, 1.4p라
잡음과 구분되지 않는다.

잡음 수준이고 식별자 질문 22개에서 있는 쪽이 1문항 앞선 것이 유일한 근거라, 코드 단순화와 저울질해 뺐다. 손실은 127 하나다.

## 34.2 색인에 값이 없어서 작동하지 않는 장치

현재 색인(`search-holdout` 84,413청크, `search-docs-only` 1,198청크)에서 각 장치가 대상으로 삼는 값이 있는 청크를
세고, 장치를 하나씩 빼고 재검색해 결과가 달라지는 질문을 셌다(docs 135, holdout 69, 반환 문서와 청크가 모두
같은지 비교).

| 장치 | 대상 청크 | 뺐을 때 달라진 질문 | 처리 |
|---|---:|---|---|
| 문서 종류 부스트(`INTENT_HINTS`, 가중치 14) | 0 (종류값이 색인에 없음) | 0 / 0 | **삭제** |
| `period_hint` 가산점(가중치 4) | 0~1 | 0 / 0 | 유지 (아래) |
| 시행일 필터(`effective_from`, `effective_to`) | 0 | 0 / 0 | 유지 (아래) |
| 현행판 우대(`superseded_by`, 가중치 4) | 0 | **31 / 8** | 유지 |

- **현행판 우대는 죽은 코드가 아니다.** `superseded_by`가 있는 문서가 없으므로 "없는 문서에 +4"가 모든 문서에 붙는다.
  이것이 BM25 점수 전체에 4를 더하는 상수로 작동해서, 비율로 자르는 트림과 컷오프의 기준이 달라진다. 뺐더니 docs 135에서
  31개, holdout 69에서 8개 질문의 결과가 달라졌다. 효과는 34.3에서 쟀다.
- **`period_hint`와 시행일 필터는 지금은 영향이 없지만 지우지 않았다.** 색인기(`indexer.py`, `prepare.py`)가 이 값을
  만들고 있고 docs 재색인이 25단계의 열린 항목이다. 재색인하면 살아난다. 시행일 필터는 API의 기준일(`as_of`)과
  연결되어 있다.
- 종류 부스트는 색인기에도 그 종류값을 만드는 곳이 없어서 코드와 테스트, `search` 패키지의 내보내기(`GUIDE_TYPES` 등)를
  지웠다. 지우기 전에 뺀 채 재검색한 결과가 현재와 같았다.

## 34.3 현행판 우대(+4)를 빼면 나빠지는가

8개 질의셋에서 뺐을 때와 비교했다(청크 Recall / 문서 Precision, 현재 → 뺌).

| 질의셋 | 달라진 질문 | 청크 Recall | 문서 MRR | 문서 Precision |
|---|---:|---|---|---|
| docs 135 | 31 | 0.896 → 0.896 | 0.879 → 0.883 | 0.789 → 0.781 |
| holdout 69 | 8 | 0.884 → 0.870 | 0.821 → 0.814 | 0.611 → 0.617 |
| 동결 검증 36 (core) | 7 | 0.861 → 0.861 | 0.801 → 0.801 | 0.705 → 0.691 |
| 동결 검증 36 (core+docs) | 6 | 0.861 → 0.861 | 0.801 → 0.801 | 0.705 → 0.691 |
| 날짜 14 | 2 | 0.929 → 0.929 | 0.857 → 0.857 | 0.436 → 0.418 |
| 날짜 확인 8 | 1 | 1.000 → 1.000 | 0.688 → 0.688 | 0.315 → 0.315 |
| 주제·기간 7 | 0 | 같음 | 같음 | 같음 |
| 기간(타) 7 | 1 | 1.000 → 1.000 | 0.857 → 0.786 | 0.571 → 0.560 |

청크 Recall은 어디서도 오르지 않고 holdout 69에서만 1문항(−1.4p) 내려간다. 문서 Precision은 뺐을 때 5개 셋에서 내려간다.
효과는 작지만 없을 때 손해가 나는 쪽이라 **유지한다.** 다만 이유가 다르다: 현행판을 우대해서가 아니라, 모든 문서에 붙는
상수가 점수 기준을 올려 트림·컷오프를 덜 가파르게 만들어서다. 상수 크기(4)를 바꿔 보는 것은 하지 않았다.

## 34.4 동의어 확장이 도움이 되는가

동의어(20개 그룹, 검색 시점의 `synonym_graph`, 본문만 확장)를 빼고 검색했다. 검색할 때 분석기를 `korean_nori`로 바꿔 확장만
없앴다. 열은 위와 같다.

| 질의셋 | 동의어 | 청크 Hit | 청크 Recall | 청크 MRR | 청크 Precision | 평균 청크 | 문서 Hit | 문서 Recall | 문서 MRR | 문서 Precision | 평균 문서 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| docs 135 | 있음 | 0.911 | 0.896 | 0.758 | 0.252 | 6.36 | 0.911 | 0.816 | 0.879 | 0.789 | 1.70 |
| docs 135 | 없음 | 0.911 | 0.896 | 0.758 | 0.252 | 6.36 | 0.911 | 0.816 | 0.879 | 0.790 | 1.69 |
| holdout 69 | 있음 | 0.899 | 0.884 | 0.759 | 0.354 | 6.94 | 0.899 | 0.640 | 0.821 | 0.611 | 2.77 |
| holdout 69 | 없음 | 0.899 | 0.884 | 0.752 | 0.355 | 6.86 | 0.899 | 0.647 | 0.814 | 0.625 | 2.68 |

식별자 질문 22개에서는 결과가 같다. 설계 문서의 자체 측정도 상위 5건이 65개(없음) 대 66개(본문만)로 1건 차이였다. 효과가
잡음 수준이지만 지우려면 색인 설정을 바꿔 다시 만들어야 하고 해가 없어서 **유지한다.**

## 판단과 다음 작업

- **반영:** `.standard` 필드를 쿼리에서 뺐다. 문서 종류 부스트와 그 테스트·내보내기를 지웠다. `CURRENT_EDITION_WEIGHT` 위에
  실제 동작과 이 단계의 측정을 주석으로 남겼다.
- **유지:** 현행판 우대(+4), `period_hint` 가산점, 시행일 필터, 동의어.
- **다음 작업:** docs를 재색인해 `period_hint`가 채워진 색인을 만들면 `period_hint` 가산점과 "날짜 없는 문서" 가산점의
  상호작용을 다시 재고, 그때 이 가산점을 남길지 판단한다. docs 코퍼스는 재생성하지 않고 색인기만 다시 돌리는 범위에서만
  한다. 지금은 하지 않았다.
- **한계:** 식별자 질문이 22개뿐이어서 `.standard`의 효과를 확인하거나 반증하지 못했다. `.standard`와 동의어 비교는
  개발 셋에서만 했고 동결 검증 36과 날짜·기간 셋은 재지 않았다. 식별자 질문이 훨씬 많은 새 질의셋은 먼저 허락을 받아
  만든다. 현행판 우대의 상수 크기(4)는 바꿔 보지 않았다.
- 모든 질문과 판정은 assistant가 작성했고 사람 검수 전이다.
- 실행 중인 API 서버는 재시작해야 반영된다.
