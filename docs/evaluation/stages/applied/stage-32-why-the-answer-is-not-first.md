# 32단계: core+docs에서 정답이 1위에 오지 않는 이유 (2026-09-29)

core와 docs를 합친 뒤 docs 질의의 근거 Recall@5는 0.863, 문서 1위 적중은 0.837에 머물렀다
(28단계 설정, docs 135문항). 목표 0.9까지 올리려고 원인을 나눠 보고 여섯 가지 처방을 시험했다.

**결론부터.** 반영한 것은 하나다. 연도를 대는 질의에서 **날짜를 모르는 문서도 가산점을
받게** 했다(32.3). 퇴행 없이 docs 1위 적중이 0.837 → 0.844, 반환 문서 Precision이
0.757 → 0.773이 됐다. 나머지는 모두 기각했다.

- 정답 문서는 대부분 **이미 후보 안에 있다.** 놓친 19문항 모두 정답 부모가 한 검색기의
  상위 약 20위 안에 있었다.
- 1위를 뺏는 문서는 **같은 주제인데 답이 없는 문서**다. 같은 세미나의 개최 안내문, 같은
  사건의 다른 연도 자료, 비슷한 서식이 그렇다. BM25와 벡터 모두 이것을 가를 신호가 없다.
- 크로스엔코더처럼 청크를 **하나씩** 채점하는 LLM도 가르지 못했다. 후보를 **한꺼번에**
  보여 주고 고르게 하면 개발 셋에서는 docs 근거 Recall이 0.919가 된다. 그러나 동결 셋
  세 개에서는 1위 52 → 53문항으로 거의 같았고, 질문마다 LLM 호출 한 번이 붙는다.
  비용에 비해 효과가 없어 기각했다.

측정은 판정자·재작성·리랭커를 끄고, k=5, 기준일 2026-09-25로 했다. docs 질의는
`search-holdout,search-docs-only`, holdout 질의는 `search-holdout`에서 검색했다. 정답은
28단계 보정 결과 파일(`*-title1-dfs-top5-audited.json`)과 각 동결 셋의 반환 근거 보정본을
그대로 썼다. 새로 판정한 문서는 없으므로 Precision은 하한이다.

## 32.1 무엇이 근거를 놓치게 하는가

204문항(docs 135 + holdout 69)에서 근거를 놓친 그룹은 33개였다. 정답이 검색 파이프라인의
어디까지 살아남았는지로 나눴다(`classify_all.py`).

| 정답이 살아남은 곳 | 그룹 수 |
|---|---:|
| 한 검색기 목록에만 남음 (다른 검색기 원시 목록에는 있었지만 트림에 잘림) | 9 |
| 한 검색기 목록에만 남음 (다른 검색기는 못 찾음) | 6 |
| 두 원시 목록에 있었지만 둘 다 트림에 잘림 | 6 |
| 후보에 없음 | 7 |
| 두 목록에 남았지만 융합 순위·창에서 밀림 | 3 |
| 같은 근거가 다른 부모로 나뉨 | 2 |

**하이브리드는 사실상 두 목록의 교집합만 반환한다.** 최종 컷오프는 1위 RRF 점수의 0.90이다.
k=60에서 두 목록 모두 1위인 문서는 2/61, 한 목록에만 있는 문서는 최대 1/61이다. 그래서
한 목록에만 든 문서는 그 목록의 1위가 아니면 반드시 잘린다. 21단계가 이미 적은 구조다.

그러나 컷오프를 푸는 것은 답이 아니다. 최종 컷오프만 바꿔 재면 다음과 같다(`sweep_hybrid_cut.py`,
127번 질문을 고치기 전).

| 최종 컷오프 | docs 근거 Recall@5 | docs 평균 반환 문서 | holdout 근거 Recall@5 | holdout 평균 반환 문서 |
|---|---:|---:|---:|---:|
| 0.90 (현재) | 0.863 | 1.83 | 0.877 | 2.51 |
| 0.50 | 0.863 | 1.99 | 0.877 | 2.86 |
| 0 | 0.881 | 2.43 | 0.906 | 3.96 |

0.50은 효과가 없다. 한 목록에만 있는 문서의 최고점이 정확히 그 경계(1/61)다. 0으로 끄면
Recall은 조금 오르지만 반환 문서가 크게 늘고 반환 문서 Precision이 docs 0.745 → 0.647,
holdout 0.550 → 0.395로 떨어진다(이 표의 Precision은 `gold_groups`만 쓴 채점이라 아래 표와
기준이 조금 다르다).

**잘린 정답의 순위는 낮지 않았다.** 잘린 19문항(21그룹)의 정답 부모 순위를 검색기별로 쟀다
(`why_low.py`). 037·081·033은 두 검색기 모두에서 2~3위다. 1위와 점수 간격이 트림 비율
(BM25 0.90, 벡터 0.97)보다 커서 잘린 것이다. 1위 문서가 무엇이었는지 보면 원인은 넷으로 나뉜다.

| 원인 | 문항 |
|---|---|
| 연도를 댄 질의에서 다른 해 같은 주제 문서가 앞섬 | 081, 086, 097, 101, 103, 104, 106, holdout-037 |
| 복수 근거 질의에서 두 번째 문서가 1위 대비 비율로 잘림 | 037, 039, 050, 086, holdout-001 |
| 빈칸 많은 서식 청크가 어휘·의미 모두 약함 | 017, 018 |
| 기타 | 004, 008, 009, 028, 033 |

## 32.2 기각: 사본 병합, 부모 순위 RRF, 트림 제거

**FAQ 사본 병합.** core의 FAQ 202건 중 183건이 `yestrade-faq-N`(게시판)과
`yestrade-faq-N-XXXX`(9차 Q&A PDF 첨부) 두 부모로 들어 있다. 둘은 같은 `source_url`을 쓴다.
본문 8자 조각 겹침으로 보면 182쌍이 FAQ 본문의 78% 이상을 공유하고, `faq-196`만 다른
문서(별표 24 원문)다(1%). 이 182쌍을 융합에서 한 문서로 세도 **어느 셋에서도 근거
Recall이 오르지 않았다**(`sweep_dup.py`). 004의 사본은 벡터 트림에서 먼저 잘려서, 합쳐도
여전히 한 목록에만 남는다. 1위 적중이 떨어진 3건(holdout-002, validation-028의 두 조건)은
정답 라벨이 사본 한쪽만 담아 생긴 채점 착시였다.

**RRF를 부모 순위로 세기와 트림 제거.** `_rrf`는 순위를 청크 위치로 센다. 청크가 많은
문서가 앞을 차지하면 뒤 문서의 순위가 부풀려진다(097은 BM25 부모 49위가 청크 119위로
들어간다). 부모 순위로 바꾸고, 트림도 꺼 봤다(`sweep_rank.py`).

| 질의셋 | 지표 | 현재 | 부모 순위 | 트림 끔 | 둘 다 |
|---|---|---:|---:|---:|---:|
| docs 135 | 근거 Recall@5 | 0.870 | 0.870 | 0.885 | 0.896 |
| docs 135 | 반환 문서 Precision | 0.757 | 0.753 | 0.665 | 0.502 |
| holdout 69 | 근거 Recall@5 | 0.877 | 0.877 | 0.906 | 0.913 |
| 동결 검증 36 (core+docs) | 근거 Recall@5 | 1.000 | 1.000 | 0.972 | 0.972 |
| 동결 검증 36 (core+docs) | 1위 적중 | 1.000 | 1.000 | 0.917 | 0.944 |

부모 순위만으로는 거의 변화가 없다. 트림이 목록을 이미 짧게 줄여 놓기 때문이다. 트림을
끄면 개발 셋 Recall은 오르지만 **동결 검증 셋에서는 Recall과 1위가 떨어진다.** 정답과
비슷한 순위의 방해 문서가 함께 들어오기 때문이다.

## 32.3 반영: 날짜를 모르는 문서의 기간 가산점

연도를 대는 질의(`2005년 …`)는 발행일·시행일이 그 기간에 드는 문서에 +6, 추정 날짜
`period_hint`가 드는 문서에 +4를 준다. docs 인덱스(2026-09-18)는 대부분 날짜가 비어 있다.
그래서 그 해 날짜가 붙은 **core의 방해 문서만** 가산점을 받았다. 가산점을 빼고 재면
정답 BM25 부모 순위가 101은 7 → 2위, 103은 10 → 6위, 104는 35 → 21위로 오른다.

docs 인덱스는 고정하기로 했으므로 인덱스는 건드리지 않았다. 대신 날짜 필드
(`published_at`, `effective_from`, `period_hint`)가 **하나도 없는 문서**에도 가산점을 준다.
무게는 "확인된 날짜 일치(6) > 추정 날짜 일치(4) ≥ 날짜 없음"이라는 기존 원칙에 따라 4로
정했다. 6이 docs 1위에서 조금 더 좋았지만(0.852) 추정 날짜보다 앞서게 되어 쓰지 않았다
([query.py](../../../../search_engine/search/query.py), [test_query.py](../../../../tests/search/test_query.py)).

| 질의셋 | 1위 적중 | 근거 Recall@5 | 반환 문서 Precision |
|---|---:|---:|---:|
| docs 135 | 0.837 → 0.844 | 0.870 → 0.874 | 0.757 → 0.773 |
| holdout 69 | 0.812 → 0.812 | 0.877 → 0.877 | 0.613 → 0.613 |
| 동결 검증 36 (core) | 0.944 → 0.944 | 1.000 → 1.000 | 0.753 → 0.771 |
| 동결 검증 36 (core+docs) | 1.000 → 1.000 | 1.000 → 1.000 | 0.775 → 0.794 |
| 날짜 14, 주제·기간 7, 출처 지목 16 | 변화 없음 | 변화 없음 | 변화 없음 |

바뀐 docs 문항은 모두 같은 방향이다. 날짜 없는 docs 정답이 1위로 올라오거나(016, 095),
불필요한 반환 문서가 빠졌다. 101은 근거 Recall 0.5 → 1.0이다. 반영 전 기준선은 아래
32.6절의 127번 질문 수정 뒤 값이다. 실행 중인 8112·8113 서버는 재시작해야 반영된다.

## 32.4 기각: 질문의 출처 설명을 본문에서만 찾기

103~106은 가산점을 빼도 BM25 21~45위다. 1위는 `미국 전략물자 수출통제 세미나 개최` 같은
개최 안내문이다. 답은 없지만 질문의 출처 설명("2005년 미국 수출통제 세미나에서는")과
제목이 거의 그대로 겹친다. 답을 담은 정답은 제목이 `상무부 세미나 QnA`로 짧다.

질문 앞머리의 "YYYY년 …(자료·세미나·기사 등)…에서(는)"를 출처 설명으로 떼어 내고,
이 부분은 **본문에서만** 찾게 했다. 개발 5문항에서는 097이 26 → 5위, 103이 6 → 1위,
104가 12 → 3위, 106이 23 → 11위로 올랐다. holdout-037은 7 → 20위로 떨어졌다. 정답 제목에
출처("연재 기사")가 들어 있었기 때문이다. 벡터를 내용 부분만으로 임베딩하는 변형은 103을
16 → 95위로 떨어뜨려 쓰지 않았다(`source_variants.py`).

| 질의셋 | 규칙 적용 문항 | 1위 적중 | 근거 Recall@5 |
|---|---:|---:|---:|
| docs 135 (규칙을 만든 셋) | — | 0.844 → 0.852 | 0.874 → 0.889 |
| 출처 지목 16 (새로 동결) | 16/16 | 0.688 → 0.688 | 0.812 → 0.812 |
| 동결 검증 36 (core+docs) | 3/36 | **1.000 → 0.944** | 1.000 → 1.000 |
| 날짜 14 | 6/14 | **0.714 → 0.643** | 1.000 → 1.000 |

**전제가 틀렸다.** 출처 설명이 곧 정답 문서의 제목인 경우가 흔하다. "2020년 하반기 CP
실적보고와 운영보고 안내에서는"이라고 물으면 그 안내문이 정답이다(validation-035·036,
date-002·007). 정규식도 "2010년 워크숍은 어느 장소에서"의 장소 질문을 출처로 오인했다.
"안내문에 적힌 것"과 "안내된 자료 속 내용"은 질문 문장만으로 가를 수 없다. 코드는 되돌렸다.

이 시험을 위해 출처를 지목하는 질문 16개를 규칙을 만들기 전에 동결했다
([queries_source_ref_v1.jsonl](../../../../data/queries_source_ref_v1.jsonl),
`data/generated/source-ref-v1/`). 이전 질의셋의 정답과 이미 열어 본 문서를 빼고 시드
20260929로 추출했다. 같은 해에 다시 올라온 사본만 공동 정답으로 넣도록 빌더에
`source_year`를 더했다. 결론은 기존 동결 셋만으로도 나왔으므로 이 셋은 **기록용**이다.
설정 선택에 쓰지 않는다. 현재 성능은 근거 Recall 0.812, 1위 0.688이고, 놓친 3문항 중
001·004는 영어 EAR 원문, 014는 답을 담은 첨부 대신 게시물이 반환된 경우다.

## 32.5 기각: LLM으로 문서 순위 다시 매기기

리랭커 기록(8·18·19·20단계)은 모두 docs만 있을 때 **문서 안 청크 순서**나 무응답 판정에
쓴 것이다. 문서 순위를 다시 매긴 적은 없었다. 18단계는 "주제는 맞고 답은 없는 경우는
리랭커도 가려낼 수 없다"고 적었다. 그래서 관련도가 아니라 "답을 담았는가"를 묻는 LLM
(`qwen3-vl-30b-a3b`, 31단계 필터와 같은 모델)으로 두 방식을 재 봤다. 대상은 261문항
(docs 135, holdout 69, 동결 검증 36, 날짜 14, 주제·기간 7)이다.

**청크마다 등급(0/1/2) 매기기** (`llm_rerank.py`). 컷오프 없는 상위 20부모 × 청크 4개를
31단계 필터 프롬프트로 채점하고, 부모의 최고 등급 순으로 정렬했다.

| 질의셋 | 1위 적중 | 근거 Recall@5 | 반환 문서 Precision |
|---|---:|---:|---:|
| docs 135 | 0.844 → 0.844 | 0.874 → 0.881 | 0.773 → 0.319 |
| holdout 69 | 0.812 → **0.681** | 0.877 → 0.833 | 0.613 → 0.296 |
| 동결 검증 36 | 1.000 → **0.806** | 1.000 → 0.889 | 0.794 → 0.291 |

후보 20개 안에 정답이 있는 비율은 docs 130/135, holdout 67/69이고 나머지는 전부였다.
문제는 등급이 후하다는 것이다. 후보 상위 8부모 중 평균 4.7개가 2(직접 답함)를 받았고,
86문항은 8개 전부 2였다. 1위를 잃은 28건 중 17건은 정답에 1, 방해 문서에 2를 줬다.

**후보를 한꺼번에 보여 주고 고르게 하기** (`llm_listwise.py`). 상위 10부모 × 청크 3개
(평균 19.1개, 28,000자 이내, 본문은 자르지 않음)를 한 프롬프트에 넣었다. "질문이 묻는 바로
그 사실을 적은 발췌문을 최대 5개 고르라, 같은 주제라도 그 사실이 없으면 고르지 말라"고
물었다. 고른 문서를 먼저 두고 남은 자리를 기존 결과로 채웠다. 청크는 기존처럼 부모당
6개를 전달했다.

| 질의셋 | 1위 적중 | 근거 Recall@5 | 5위 안 정답 | 반환 문서 Precision |
|---|---:|---:|---:|---:|
| docs 135 | 0.844 → **0.904** | 0.874 → **0.919** | 0.904 → 0.941 | 0.773 → 0.747 |
| holdout 69 | 0.812 → 0.826 | 0.877 → **0.913** | 0.899 → 0.942 | 0.613 → 0.529 |
| 동결 검증 36 | 1.000 → 0.917 | 1.000 → 0.972 | 1.000 → 0.972 | 0.794 → 0.560 |
| 날짜 14 | 0.714 → 1.000 | 1.000 → 1.000 | 1.000 → 1.000 | 0.511 → 0.523 |
| 주제·기간 7 | 0.857 → 0.857 | 1.000 → 1.000 | 1.000 → 1.000 | 0.786 → 0.762 |

지금까지 시도 중 처음으로 같은 주제 안에서 답을 가려냈다(1위 새로 맞힘 21건, 잃음 11건).
그러나 동결 검증 셋에서 잃은 3건은 모두 **질문이 정한 조건을 놓친 실제 오답**이다.

- 012: 6월 24일 세미나의 Q&A 시각을 물었는데 다른 세미나 프로그램을 골랐다.
- 018: HS코드와 시스템을 물었는데 HS코드 언급이 없는 시스템 이용안내서를 골랐다.
- 028: 바세나르용(별지 2의3) 서약서를 물었는데 일반용(별지 2의2)을 골랐다.

동결 셋 세 개의 1위를 합치면 52 → 53문항이다. 날짜 14도 30단계 설계에 쓴 셋이라 새 질문에서의
이득은 증명되지 않았다. 비용은 질문마다 약 12,000토큰짜리 LLM 호출 한 번이다. 6개 병렬 실행에서
질문당 약 10초였고, 현재 검색은 약 0.1초다. **비용에 비해 효과가 없어 기각했다.**

## 32.6 함께 고친 것: docs-v2-127 질문

127은 "전략물자 수출입고시 제54조는 어떤 허가의 면제를 정한 조항이야?"였다. 현행 고시는
제54조가 상황허가 자체이고 제54조의2가 그 면제다. 옛 판본을 따르는 별지 16 서식만이
전제를 뒷받침했다. 질문을 서식을 지목하도록 고쳤다. 정답과 근거 라벨은 그대로다.

> 사전거래보고서 서식의 허가면제 사유 칸에서 전략물자 수출입고시 제54조는 어떤 허가의
> 면제로 적혀 있어?

구어체 판도 같이 고쳤고, 매니페스트의 해시와 사유를 갱신했다. 이 수정으로 docs 근거
Recall이 0.863 → 0.870이 됐다. 검색이 좋아진 것이 아니다. 질문이 서식을 지목해 전보다
쉬워졌다. 이 문서의 32.2절 이후 기준선은 수정 뒤 값이다.

130은 라벨 누락으로 확인했다. 현행 통관고시(`law-admrul-2100000268604#0000`) 제2조 제3호에
정답 문구가 그대로 있다. 라벨은 아직 고치지 않았다.

## 판단

- **반영:** 날짜 없는 문서의 기간 가산점(32.3).
- **기각:** 최종 컷오프 완화, FAQ 사본 병합, 부모 순위 RRF, 트림 제거, 출처 설명 분리,
  LLM 청크 등급 재정렬, LLM 목록 선택.
- **본질적인 문제는 풀리지 않았다.** 정답은 후보 안에 있지만, 같은 주제의 방해 문서와
  가를 신호가 없다. 가중치·컷오프·규칙은 개발 셋에서만 오르고 동결 셋에서 퇴행했다.
  이 구분을 할 수 있는 것은 지금까지 목록 선택 LLM뿐이었고, 그것도 조건(날짜·서식 번호)을
  놓친다.
- **docs 135에서 0.9를 목표로 계속 밀면 이 셋에 과적합된다.** 동결 셋에서는 현재 엔진의
  근거 Recall이 이미 1.000이고, 남은 실패는 docs·holdout 안의 소수 문항에 몰려 있다.

## 한계

- 모든 질문과 판정은 assistant가 작성했고 사람 검수 전이다.
- 동결 셋 세 개도 30단계 이후 여러 번 검색했다. 완전히 새 질문이라 보기는 어렵다.
- LLM 실험의 지연은 병렬 부하에서 잰 값이다. 단일 요청 지연은 재지 않았다.
- 새로 반환된 문서를 판정하지 않았으므로 Precision은 하한이다.

## 재현

실험 스크립트와 결과는 `data/generated/stage32-diagnosis/`에 있다. 저장소 루트에서 실행한다.
세션 중 임시 폴더에서 만든 것이라 경로 상수를 고쳐야 할 수 있다. `llm_listwise_out.json`은
두 번째 실행 결과다. 첫 실행 결과 파일은 다른 스크립트가 덮어써 잃었고, 두 번째 실행의
선택과 수치는 첫 실행 로그와 같았다(온도 0).
