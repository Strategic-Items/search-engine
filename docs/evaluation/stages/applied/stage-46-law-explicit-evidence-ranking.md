# 46. 법령 명시 근거 일치 가산점 (2026-10-12)

## 단계 정의

**질문에 명시된 조문·별표·별지·통제번호와 대상 항목을 담은 청크의 조회 점수를 높여, SPLADE 상위 25개 안에서 정답 근거를 회수한다.**

이 단계의 변경 단위는 법령의 조회 전 순위 산정이다. 후보 수를 확대하거나 조문·통제번호별 후보를 추가로 조회하지 않는다. SPLADE 25개와 dense 25개를 합치는 기존 hybrid를 유지하며, BM25 보조 항은 최종 구현에서 제거했다.

## 문제와 변경

- 037: 제85조의 위반 결과를 물었지만 제88조의 서류 보관 규정이 앞섰다.
- 075: 통제번호 3A002.d.1을 명시했지만 같은 별표의 다른 품목이 앞섰다.
- 076: 전문판정서 주의사항을 물었지만 서식 제목이 주의사항 본문보다 앞섰다.

법령의 SPLADE 조회 점수는 다음처럼 계산한다.

```text
SPLADE 점수
+ 6 × [명시 조문·별표·별지와 제목 경로의 구절 일치]
+ 6 × [명시 통제번호와 본문의 구절 일치]
+ 6 × [위 근거 범위 일치 AND 질문에서 추출한 대상 항목과 본문의 구절 일치]
```

각 대괄호는 조건을 만족하면 1, 아니면 0이다. 번호가 여러 개 맞더라도 같은 조건의 가산점이 일치 개수만큼 늘어나지는 않는다. 제목 경로 일치와 통제번호 일치는 별도로 더해, 같은 별표 안에서도 통제번호를 맞춘 청크가 우선하도록 한다.

대상 항목은 질문 문구에서 추출한다. 예를 들어 “별지 제4호 ... 주의사항에는 무엇”에서는 해당 서식 범위 안에서 주의사항을 담은 본문을 우대한다. 질문 ID·정답 문서 ID로 분기하지 않는다. 구절 일치는 OpenSearch 분석기를 거친 일치이므로 법령 문맥의 완전한 의미 판정은 아니다.

가산점을 적용한 조회의 상위 25개와 dense의 상위 25개를 청크 RRF(k=60)로 합친다. 최종 RRF는 순위를 사용하고, 조회 원점수나 가산점 자체를 최종 점수에 직접 더하지 않는다.

## 범위와 고정 조건

- 법령 카테고리의 SPLADE 쪽 조회와 그 결과를 사용하는 hybrid에 적용한다. dense 단독 조회 점수는 바꾸지 않는다.
- `SEARCH_LAW_CANDIDATES=25`로 고정하며 50 설정을 거부한다. `SEARCH_LAW_REFERENCE_BOOST=6`을 사용한다.
- BM25 보조 계산 코드·가중치 설정을 제거했다. SPLADE 모델 미설정 시 BM25 단독 검색으로 대체하지 않는다.
- 조회는 두 목록만 만들고 추가 조문·통제번호 조회는 실행하지 않는다.
- 컷오프 0.7, 최대 10청크·5문서·문서당 6청크를 유지한다.
- 청킹·인덱스·질문·근거 라벨은 그대로다.

## 최종 구현의 실제 검색 검증

서비스 인덱스 `search-law-v20261008061513-3ba81c`, 150문서·6,288청크와 `queries_law150_v1.jsonl`의 평가 대상 149문항을 사용했다. 053은 제외한다. 검색 기준일은 2026-10-07, 대체 문서 가중치는 0.97이다. 모든 evidence_groups를 충족해야 성공이다. LLM 청크 필터·답변 판정·리랭커·질의 재작성은 껐다.

기준선과 수정 후 모두 BM25 없이 각 25개만 조회하고 추가 후보 조회도 없다. 가산점 0과 6을 실제 `retrieve` 함수로 비교했다. 과거 추가 통제번호 조회가 있던 145/149 기준선 또는 후보 50개 실험과 직접 혼동하지 않는다.

| 지표 | 가산점 없음 | 가산점 6 |
|---|---:|---:|
| 근거 반환 | 144/149 | **147/149** |
| 첫 문서 적중 | 129/149 | 128/149 |
| 청크 Precision 하한 | 0.2313 | **0.2547** |
| 평균 반환 청크 | 7.987 | **7.738** |
| 각 검색기의 후보 수 | 25 | 25 |
| 추가 후보 조회 | 0 | 0 |

037·075·076이 새로 성공했고, 기준선의 성공 문항이 실패로 바뀐 경우는 0개다. 근거 회수와 청크 Precision 하한은 개선됐지만 첫 문서 적중은 1문항 줄었다. 생성 답변 정확도 개선을 뜻하지 않는다.

## BM25 제외 결정

동일 후보 수에서 명시 근거 가산점만으로도 근거 회수가 147/149다. 별도 BM25 보조 비교에서는 근거 회수 증가 없이 첫 문서 적중이 128→133/149로 증가했지만, 청크 Precision 하한이 내려가고 평균 반환 청크가 늘었다. 사용자의 선택에 따라 BM25를 제외하고 근거 일치 가산점만 최종 단계로 채택했다. 이전 비교 결과는 `data/generated/law-fixed25-2026-10-12/`에 보존한다.

## 남은 문제와 검증 한계

043은 여러 판본의 일반 규정이 직접 근거보다 앞서고, 125는 금액 행과 단위 헤더가 분리돼 있다. 둘은 이번 변경으로 해결되지 않았다. 이 평가셋을 보며 선택한 규칙과 가산점이므로 새로운 질문에서의 일반화는 아직 측정하지 않았다. 추가 튜닝을 중단하고 현재 설정을 고정했다.

검색 구간 평균은 기준선 33.6ms, 수정 후 33.2ms였다. 질의 인코딩을 미리 끝내고 순차 측정한 값으로 전체 API 지연이나 부하 시험 결과가 아니다.

## 서버 반영 (2026-10-12)

프런트엔드가 연결하는 로컬 API `http://127.0.0.1:8092`를 재시작해 커밋 `bc90f3a`의 조회 로직을 반영했다. 법령 SPLADE·dense 후보는 각각 25개, 명시 근거 가산점은 6, hybrid 컷오프는 0.7이다. 법령 BM25와 추가 조문·통제번호 후보 조회는 없다. 위 검증에 사용한 서비스 색인(6,288청크)을 유지했다.

`/health/live`와 `/health/ready`가 모두 200으로 응답했고, 실제 `/v1/categories/law/search/compare` 요청에서 SPLADE·vector·hybrid 세 모드가 오류 없이 반환됐다. 037·075·076은 hybrid 최종 반환에서 모든 근거 요건을 충족했다. 서비스의 기존 LLM 청크 필터 설정은 유지했으므로, 필터를 끈 149문항 평가와 실제 API 응답은 구분한다. 관련 테스트 139개도 재통과했다.
