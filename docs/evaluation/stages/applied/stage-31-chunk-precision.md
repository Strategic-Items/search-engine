# 31단계: 전달 청크의 Precision을 올릴 수 있는가

청크 Precision 하한을 LLM 필터(31.1), 점수 컷오프(31.2), 본문 전용 청크 점수(31.3)로 올려 보고, SPLADE를 같은 95% 컷오프 조건에서 다시 비교했다(31.4). **결론: LLM 필터는 Recall 손실 없이 25.1% → 37.8%. 점수 컷오프는 최고 68.9%로 80%에 못 미치고, 강하게 자를수록 Recall이 크게 줄었다. 제목 제거는 오히려 나빴고, SPLADE는 95% 조건에서 청크 1위만 +2.2p였다.**

> 원래 단계별 파일로 나뉘어 있던 기록을 주제별로 합쳤다. 질문을 검색 전에 동결했다는 증거는 각 단계의 개별 커밋에 남아 있으므로, 문서만 합쳤다. 원래 단계는 절 번호로 바꿨고, 절 제목의 옛 번호는 커밋 메시지·결과 파일명(`stage39` 등)과 대조할 수 있도록 괄호에 남겼다.

## 31.1 선택된 청크에서 무관한 내용을 LLM으로 걸러낸다 (2026-09-28) (옛 46단계)

문서 컷오프 이후에는 정답 문서 안의 다른 절도 함께 전달된다. 문서당 청크 수를 일괄 줄이지 않고, `qwen3-vl-30b-a3b`로 청크를 0(무관)/1(필요한 조건·맥락)/2(직접 근거)로 평가해 0점만 제거하는 필터를 추가했다. 질문을 부정하거나 답을 결정하는 규칙도 직접 근거로 인정한다.

선택된 청크 전체 본문을 자르지 않고 6개씩 평가한다. 남은 문서와 청크 순서는 보존하며 선두가 제거되면 다음 청크가 대표 본문이 된다. 모든 청크가 무관한 문서는 제거한다. 어떤 배치든 응답 형식 오류나 연결 실패가 있으면 해당 질문의 원래 후보 전체를 보존한다. 검색 점수와 별개인 `chunk_relevance` 및 `passages[].relevance`로 등급을 전달한다.

### 후보를 고정한 135문항 비교

`evaluation-135q-docs-only-no-judge.json`의 문서·청크 후보를 고정하고 현재 인덱스에서 해당 청크 본문을 읽어 필터만 비교했다. 정답 라벨과 모범답안은 필터에 전달하지 않았다. 재검색하거나 무응답 판정자를 함께 실행한 결과는 아니다.

| 지표 | 필터 전 | 필터 후 |
|---|---:|---:|
| 청크 Precision (정답 라벨 하한) | 25.14% | 37.78% |
| 청크 Recall | 96.30% | 96.30% |
| 모든 근거 전달 | 94.81% | 94.81% |

| 문서 Recall | 97.65% | 97.65% |
| 질문당 전달 청크 | 6.87개 | 5.32개 |

청크 Precision은 12.64%p 올랐다. 기존에 전달되던 정답 근거 그룹을 추가로 잃은 질문은 0개다. 전체 135개 중 형식 오류 2개는 원래 후보를 그대로 유지했고 지표에 포함했다.

6개 질문을 병렬 처리한 이번 실행에서 추가 필터 지연 p50은 15.33초다. 서버 부하와 배치 수에 영향을 받으므로 운영 단일 요청의 지연으로 일반화하지 않는다.

### 적용과 한계

배포 기본값은 `SEARCH_CHUNK_FILTER=false`, 이 작업의 로컬 `.env`는 `true`로 설정했다. 현재 채팅 모델과 같은 30B를 사용하며 필터 다음에 기존 무응답 판정자가 실행된다. 사용자 실행 중인 API는 재시작해야 설정을 읽는다.

이는 기존 평가셋의 저장 후보에 대한 실험이다. 독립 새 질문, 무응답 질문, 실제 답변 품질, 필터와 무응답 판정자를 함께 켠 효과는 측정하지 않았다. 청크 Precision은 여전히 정답 라벨 기준 하한이며 LLM 0/1/2 등급은 사람 검수를 거치지 않았다. 화면의 기존 26.4%는 과거 무응답 판정자 사용 실행의 저장값이며 이번 37.78%와 실험 조건이 다르다.

## 31.2 LLM을 끄고 점수 컷오프로 청크 Precision 80%를 시험한다 (2026-09-28) (옛 47단계)

사용자는 청크 관련도 LLM 및 무응답 판정자 없이 컷오프를 높여 청크 Precision 80%에 도달할 수 있는지 물었다. 두 판정자와 쿼리 재작성, 리랭커를 끄고 기존 docs 질문 135개를 현재 인덱스에서 다시 검색했다. 검색 후보와 질의 임베딩을 질의별로 캐시하고 동일한 원시 검색 결과로 45가지 컷오프 조합을 비교했다. 운영 설정은 변경하지 않았다.

문서 비율은 0.90/0.95/0.98/0.99/1.00, 청크는 비율 0(끔)/0.95/0.98/0.99/0.995/1.00 또는 절대 점수 0.80/0.85/0.90을 비교했다. 단일 벡터 검색기로 축소되는 질의의 기존 문서 비율 0.99는 낮추지 않았다. 문서 컷오프의 검색기 선두 면제 규칙도 유지했다.

청크 비율은 반환 후보 전체의 최고 벡터 검색 점수에 대한 비율이다. 모든 문서에서 그 기준을 통과하는 청크만 남기고, 청크가 하나도 안 남으면 문서를 제외한다. BM25 점수와 벡터 점수를 같은 척도로 섞지 않는다. 벡터 후보에 없어 점수를 알 수 없는 청크 21개는 보존했다. 이 필터는 실험 스크립트에서만 실행했으며 프로덕션 검색에는 추가하지 않았다.

### 문서 비율 0.90을 고정한 청크 컷오프

| 청크 비율 | 청크 Precision 하한 | 청크 Recall | 평균 전달 청크 |
|---|---:|---:|---:|
| 끔 | 27.36% | 96.30% | 5.60개 |
| 0.95 | 42.45% | 94.44% | 4.04개 |
| 0.98 | 59.95% | 85.19% | 2.18개 |
| 0.99 | 66.43% | 77.41% | 1.61개 |
| 0.995 | 68.36% | 75.19% | 1.39개 |
| 1.0 | 68.91% | 68.89% | 1.16개 |

문서 컷오프만 0.90에서 1.00으로 올리면 청크 Precision은 27.36%에서 28.01%로 소폭 오른다. 최고 점수 문서를 남겨도 그 문서 안의 청크를 자르는 것은 아니기 때문이다.

확인한 45조합 중 최고 청크 Precision은 68.91%이며 Recall은 68.89%다. 80%를 달성한 조합은 없다. 청크 비율 0.95는 Precision 42.45%, Recall 94.44%로, 손실이 작은 쪽의 후보다. 0.98은 Precision 59.95%, Recall 85.19%다. 따라서 Precision 숫자만 올리려 강하게 자르면 정답 근거 손실이 커진다.

절대 바닥값도 개선을 보장하지 않았다. 0.80에서 전체 질문 평균 Precision 33.06%, Recall 48.15%이며 결과가 남는 질문은 82/135다. 그 82문항만 계산한 조건부 Precision은 54.43%다. 빈 결과 질문을 제외해서 높은 수치를 얻는 것과 전체 질문에서 좋은 검색을 하는 것을 구분해야 한다.

### 범위와 해석

80% 목표는 기존 화면과 같은 정답 청크 라벨 기준 하한으로 해석했다. 유용한 조건·맥락은 정답 라벨이 없으면 비정답으로 계산된다. 이 실험은 동일 평가셋의 후보 튜닝 실험이며 독립 일반화 성능이나 답변 품질을 증명하지 않는다. 제목 때문에 높은 점수를 받는 현상을 직접 분리해 검증한 실험도 아니다.

이번 재검색의 기본 청크 Precision은 27.36%다. 31.1절은 과거 저장된 후보의 25.14%를 기준으로 측정했으므로 둘의 차이를 컷오프 효과로 해석하지 않는다. 원자료 인덱스와 질의별 결과를 아래에 저장했다.

[원자료](../../../../data/generated/chunk-cutoff-v1/sweep.json), [실험 스크립트](../../../../scripts/sweep_chunk_cutoff.py). 재현: `.venv/bin/python scripts/sweep_chunk_cutoff.py`. 읽기 전용 실험이며 API 재시작 및 운영 설정 변경 없이 실행했다.

## 31.3 문서는 제목으로 찾고 청크는 본문만 점수 매긴다 (2026-09-28) (옛 48단계)

31.2절의 컷오프가 정답 청크 Precision 80%에 도달하지 못하자, 반복된 문서 제목이 무관 청크의 점수를 올리는 원인인지 시험했다. 문서 검색에는 기존 제목+본문 하이브리드를 유지하고, 청크 점수만 같은 모델의 본문 전용 임베딩으로 바꿨다. LLM 판정자 두 개, 쿼리 재작성, 크로스엔코더는 모두 끄고 평가했다.

### 제목의 영향을 분리한 비교

135개 질문에서 반환된 문서 순위와 문서별 검색 후보 풀을 고정했다. 문서당 6개로 자르기 전 후보를 대상으로, 기존 제목+본문 임베딩과 새 본문 전용 임베딩의 정확한 코사인 유사도를 각각 계산하고 높은 순서로 최대 6개를 선택했다. 후보를 고정했으므로 본문 검색으로 새로운 문서를 찾는 실험은 아니다.

기존 임베딩은 `제목: {title}\n\n본문: {body}`, 비교 임베딩은 `본문: {body}`다. 별도 제목 필드만 제외했으며 본문에 실제로 적힌 제목·소제목은 삭제하지 않았다. 같은 임베딩 모델로 서로 다른 본문 425개의 벡터를 생성했고 본문은 잘라내지 않았다. 질의 벡터는 양쪽이 공유한다.

컷오프는 선택된 전체 청크 중 최고 **코사인 유사도**에 대한 비율이며, 양쪽에 같은 비율을 적용했다. 31.2절의 OpenSearch kNN 점수 비율과 숫자 자체를 동일하게 해석하면 안 된다. 이번 비교는 어휘 전용 후보에도 정확한 코사인 점수를 계산하지만 31.2절은 벡터 점수가 없는 청크를 보존했다.

| 컷오프 비율 | 제목+본문 Precision | 제목+본문 Recall | 본문만 Precision | 본문만 Recall |
|---|---:|---:|---:|---:|
| 끔 | 27.36% | 96.30% | 27.30% | 96.67% |
| 0.9 | 50.78% | 91.85% | 50.35% | 76.67% |
| 0.95 | 62.47% | 85.19% | 56.22% | 65.93% |
| 0.98 | 70.19% | 76.30% | 59.90% | 62.96% |
| 0.99 | 72.10% | 73.70% | 61.75% | 61.85% |
| 0.995 | 73.33% | 70.74% | 62.10% | 60.00% |
| 1.0 | 73.33% | 68.89% | 62.22% | 58.52% |

제목을 제외하면 더 잘 걸러질 것이라는 가설은 이번 실험에서 지지되지 않았다. 컷오프 없이 최대 6개를 유지하면 Precision은 거의 동일하고, Recall은 96.30%에서 96.67%로 0.37%p 높아졌다. 모든 근거 전달은 94.81%에서 95.56%로 한 질문 개선이다.

그러나 컷오프를 적용하면 본문 전용 점수가 정답 근거를 훨씬 많이 제거했다. 비율 0.95에서 Recall은 제목+본문 85.19%, 본문만 65.93%다. 최고점 청크만 남길 때 Precision도 제목+본문 73.33%, 본문만 62.22%로 더 낮다. 두 방식 모두 시험한 비율에서 80%에 도달하지 못했다.

문서 제목이 본문을 해석하는 데 도움이 되거나 본문 전용 점수의 분포가 다를 가능성은 있지만, 원인 자체를 입증한 것은 아니다. 제목 제거가 검색 품질을 개선한다는 근거가 없으므로 운영 청크 선택 방식을 변경하지 않았다. 별도 임베딩 생성은 실험 캐시에만 저장했고 원래 인덱스를 재색인하거나 API를 재시작하지 않았다.

### 범위와 재현

지표는 기존 정답 청크 라벨 기준 하한이다. 조건·맥락까지 인정하는 23단계의 관련도 Precision과 다른 기준이다. 같은 평가셋에서 비교했으므로 독립 새 질문이나 실제 답변 품질에 대한 일반화를 주장하지 않는다. 본문 자체에 포함된 제목을 지웠을 때의 효과도 측정하지 않았다.

[결과 원자료](../../../../data/generated/body-only-chunks-v1/comparison.json), [실험 스크립트](../../../../scripts/compare_body_only_chunks.py). 재현: `.venv/bin/python scripts/compare_body_only_chunks.py`. 캐시에는 후보 본문·기존 벡터·질의 벡터와 모델 및 인덱스명이 기록되며, 본문 전용 벡터는 모델명과 본문 해시로 구분한다.

## 31.4 SPLADE를 현재 95% 청크 컷오프 결과와 같은 조건으로 비교한다 (2026-09-28) (옛 49단계)

기존 프론트 SPLADE 표는 24단계의 상위 5청크 지표였다. 대표 카드의 31.2절 95% 컷오프 지표(Recall 94.4%, Precision 42.5%, 청크 1위 정확도 72.6%)와 평가 창 및 컷오프가 달라 직접 비교할 수 없었다. 동일한 전달 정책으로 다시 평가해 프론트 비교표를 교체했다.

### 비교 조건

동일 docs 135문항, 같은 고정 인덱스에서 두 LLM 판정자·리랭커·쿼리 재작성 없이 실행했다. BM25+벡터는 현행 retrieve 경로를 그대로 사용했다. SPLADE+벡터는 같은 경로에서 어휘 후보만 저장된 `telepix/PIXIE-Splade-v1.5` 순위로 교체했다. 저장 SPLADE 청크 ID가 현재 인덱스에 모두 존재함을 확인했고 동일 유효기간·공고번호 필터를 적용했다. 벡터 질의 및 후보 응답은 같은 질의 내에서 공유했다.

두 방식 모두 어휘 융합 비율 0.90, 벡터 융합 비율 0.97, 문서 최종 비율 0.90과 검색기 선두 예외를 사용했다. BM25 원시 하한 14.75는 SPLADE 점수 척도에 적용하지 않았다. 이는 SPLADE 하한을 독립적으로 보정한 실험이 아니다. 두 방식 모두 최대 5개 문서와 문서당 최대 6개 청크를 선택하고, 전체 선택 청크 중 최고 벡터 검색 점수의 95% 이상을 유지했다. 벡터 후보에 없어 점수를 알 수 없는 청크는 기존 31.2절과 같이 보존했다.

새 BM25 기준 결과는 프론트 대표 수치의 `chunk-cutoff-95.json` 지표 및 청크 1위 98문항과 정확히 일치함을 확인했다.

| 지표 | BM25+벡터 (95%) | SPLADE+벡터 (95%) | 변화 |
|---|---:|---:|---:|
| 문서 Recall | 91.05% | 89.20% | -1.85%p |
| 문서 Precision | 93.85% | 93.23% | -0.62%p |
| 문서 1위 정확도 | 95.56% | 97.04% | +1.48%p |
| 청크 Recall | 94.44% | 94.07% | -0.37%p |
| 청크 Precision 하한 | 42.45% | 42.39% | -0.06%p |
| 청크 1위 정확도 | 72.59% | 74.81% | +2.22%p |

첫 청크가 정답인 질문은 98/135에서 101/135로 3개 늘었다. 질문당 평균 전달 청크는 4.04개에서 4.00개다. 근거 전부 전달 비율은 두 방식 모두 92.59%다.

SPLADE는 첫 청크 순서에서 개선됐지만 근거 Recall과 라벨 Precision이 소폭 낮아졌다. 기존 24단계에서 측정한 상위 5청크 개선을 현재 전달 창의 개선으로 해석해서는 안 된다. 관련 맥락을 포함하는 Precision은 사용자 요청에 따라 화면에 넣지 않았고 이번 비교에서도 사용하지 않았다.

### 범위와 적용

저장된 SPLADE 모델 출력과 현재 벡터 검색을 결합한 오프라인 실험이다. 새 코퍼스 재학습·실시간 SPLADE 지연·무응답 안전성·생성 답변 품질·독립 새 질문의 성능은 측정하지 않았다. 운영 검색 설정은 바꾸지 않았다. 프론트는 질문 목록과 라우팅 섹션 사이의 SPLADE 비교를 이 실행으로 교체했다.
