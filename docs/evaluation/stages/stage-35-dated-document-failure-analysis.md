# 35단계: 날짜 질문에서 연례 공고 혼동 재현

34단계에서 검색 전에 커밋한 날짜 질문 14개를 현재 `title^1` + DFS, core+docs 인덱스로 평가했다. API 8113, 상위 5문서 기준이다. 원본 실행 결과는 `data/generated/date-validation-v1/results/combined-current-raw.json`이다.

| 집합 | 1위 정답 | 5위 내 정답 |
|---|---:|---:|
| CP 보고 공고 8문항 | **1/8** | **4/8** |
| 다른 날짜 문서 6문항 | 5/6 | 5/6 |

다른 날짜 문서 중 011의 반환 첨부파일이 동일한 워크숍 일시와 장소를 직접 적고 있어 정답 대안으로 추가했다. [판정 원장](../../../data/generated/date-validation-v1/returned_gold_audit.json)과 파생 질문셋·결과를 원본과 별도로 보존했다. 보정 뒤 다른 날짜 문서는 1위 5/6, 5위 안 6/6이다. CP 수치는 변하지 않는다. 나머지 반환 문서의 관련성을 전수 판정하지 않았으므로 precision 수치는 하한이다.

## 확인된 순위 문제

- 001·002·004·006·007에서 **2014년 CP 워크숍 첨부** `yestrade-69-6494-2394794-z003`이 상위에 자주 나온다. 2015·2017·2022·2024·2025년의 서로 다른 실적보고 질문에 이 문서가 답할 수는 없다.
- 003은 2019년 상반기 보고를 묻는데 2018년 상반기 공고가 앞에 나온다.
- 005는 2022년 하반기 보고를 묻는데 2014·2015·2018년 보고 공문과 발표자료가 앞에 나온다.
- 008은 2025년 하반기 보고를 묻는데 2025년 **상반기** 공문 및 워크숍 자료가 앞에 나온다.
- 모든 지정 정답 문서는 인덱스에 있다. 4개 CP 질문에서는 지정 정답이 반환 상위 5위 밖에 있다.

읽기 전용으로 OpenSearch의 현재 `build_query`를 직접 실행해 보니 001의 BM25는 정답 공고를 1위에 두었으나 최종 하이브리드 결과는 2014년 첨부를 1위에 뒀다. 007의 BM25는 해당 연도 첨부를 1위, 정답 공고를 5위에 두었다. 반면 005는 BM25 상위 10문서에도 지정 정답이 없었다. 따라서 문제는 **융합이 어휘적 연도 단서를 약화시키는 경우**와 **어휘 검색 자체가 `2022년`과 제목의 `22년도`, 대상 기간과 발행일의 차이를 충분히 구별하지 못하는 경우**가 섞여 있다. 현재 `_requested_period` 부스트는 발행연도에만 작용한다. 2022년 하반기 보고 공고처럼 2023년 1월에 발행된 문서는 대상 기간과 발행연도가 다르다.

이 진단셋은 오류를 겨냥해 고른 질문이라 일반적인 검색 성능으로 외삽할 수 없다. 여기서 가장 잘 나오는 연도 가중치나 예외를 선택하지 않는다. 다음 개선은 질문에 명시된 **대상 연도와 상·하반기**를 문서 제목의 기간 및 본문 근거와 비교하는 일반 규칙을 후보로 검토하고, 별도로 동결한 새 날짜 질문과 기존 docs·holdout 평가셋에서 회귀를 확인해야 한다. 정답 없는 문서의 판정은 이번 작업에서 제외한다.
