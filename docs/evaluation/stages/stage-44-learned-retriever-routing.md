# 44단계: 오라클 이득을 학습해 질의별 검색 방식 선택

## 목적과 조건

27단계의 오라클 결과에서 특징을 뽑아 검색 방식을 예측하면 이득을 회수할 수 있는지 시험했다. 운영 라우터는 변경하지 않았다. 입력은 당시 docs 135문항의 BM25·vector·hybrid 비교 결과 `data/generated/docs-v2/comparison-135q-stage27-modes.json`이다. **43단계 현재 코드의 검색 결과가 아니라 27단계의 역사적 결과를 재분석한 실험**이다.

오라클은 정답을 본 뒤 고른 상한이며, 학습 모델이 평가 질문의 정답을 보게 하면 의미가 없다. 그래서 정답 부모가 하나라도 겹치는 질문들을 연결해 33개 묶음으로 만들고, 5개 fold에 각 27문항을 배정했다. 각 평가 fold의 예측은 나머지 108문항으로 학습한 모델에서만 얻었다. 학습과 평가 사이 정답 부모가 겹치지 않는 것을 코드에서 검사한다. gold는 학습 목표와 분할·채점에만 사용하고, 추론 특징에는 넣지 않는다.

사전 설정은 `data/generated/routing-v1/protocol.md`에 실행 전에 작성했다. 이후 결과를 보고 특징이나 기준을 바꾸지 않았다.

## 모델과 특징

각 단독 검색 방식에 대해 hybrid 대비 **근거 Recall@5 이득**을 예측하는 깊이 2 회귀 트리를 학습했다. 잎 최소 8문항, 예측 이득이 0.02를 넘을 때만 가장 큰 이득의 방식으로 전환한다. 그 외에는 hybrid를 유지한다. MRR은 보조 지표로만 보고 학습 목표로 쓰지 않았다.

- 질문 모델: 길이, 단어 수, 숫자·영문 수, 조항·연도·인용 포함 여부, 의문 표현 수.
- 질문+결과 모델: 위 특징과 세 방식의 반환 부모·청크 수, 상위 5문서의 부모/청크 Jaccard 일치도, 1위 문서 일치 여부.
- 문서 이름, 질문 ID, 정답, 모범답안, 사람이 붙인 질문 유형은 특징에서 제외했다. 문서/청크 ID는 일치도 계산에만 사용했다.
- 원 보고서에 검색 점수가 없어 점수 격차는 시험하지 않았다. 결과 특징은 세 검색 결과를 이미 얻어야 계산되므로, 검색 비용을 줄이는 라우터가 아니다.

## 평가 결과

모든 라우터 값은 학습에 쓰지 않은 fold 예측을 합친 값이다.

| 방식 | 근거 Recall@5 | 근거 MRR@5 | hybrid 대비 Recall 개선/악화 문항 |
|---|---:|---:|---:|
| hybrid 고정 | 0.96296 | 0.81788 | — |
| BM25 고정 | 0.87778 | 0.70069 | 4 / 16 |
| vector 고정 | 0.92222 | 0.81630 | 0 / 7 |
| 정답을 보고 선택하는 오라클 | 0.98519 | 0.92407 | 4 / 0 |
| 질문 특징 라우터 | 0.92222 | 0.77325 | 1 / 7 |
| 질문+결과 특징 라우터 | 0.95556 | 0.80660 | 1 / 2 |

질문 모델은 38문항을 BM25로 전환했다. 질문+결과 모델은 16문항을 BM25로 전환했다. vector의 Recall 개선 사례가 없어 두 모델 모두 vector를 선택하지 않았다. 이는 벡터가 모든 측면에서 불필요하다는 뜻은 아니다. MRR 개선은 학습 목표 밖이다.

33개 문서 묶음 단위 paired bootstrap 5,000회로 구한 hybrid 대비 Recall 차이의 참고용 95% 구간:

- 질문 모델: −4.07%p, 구간 [−7.30, −1.06]%p.
- 질문+결과 모델: −0.74%p, 구간 [−1.86, 0.00]%p.

## 어떤 특징을 배웠고 왜 실패했는가

질문 트리는 주로 질문 길이와 단어 수를 사용했다. 결과 특징을 허용한 트리는 주로 BM25·vector의 청크 일치도와 hybrid가 반환한 청크 수를 사용했다. 분할 특징은 fold마다 달라 보편적인 규칙으로 확정하지 않는다.

질문+결과 모델의 실질적인 Recall 변동은 다음 세 문항이다.

| 질문 | hybrid → 선택한 BM25 Recall | 영향 |
|---|---:|---|
| docs-v2-101 | 0.5 → 1.0 | 근거 한 그룹 회수 |
| docs-v2-095 | 1.0 → 0.0 | 근거 전체 손실 |
| docs-v2-112 | 1.0 → 0.5 | 근거 한 그룹 손실 |

같은 무형이전 자료를 묻는 095와 101은 동일한 평가 묶음에 있어 해당 문서의 질문을 학습에서 보지 않았다. 모델은 101에서 올바르게 전환했지만 095에서도 전환해 더 큰 손실을 냈다. **검색 결과가 비슷하게 겹친다는 사실만으로 어느 방식이 정답 근거를 보존했는지는 구분하지 못했다.**

Recall을 개선할 수 있는 질문은 오라클에서도 4개, 총 3문항분에 불과하다. 적은 양성 사례로 그보다 많은 전환 손실을 피하는 규칙을 학습하기 어려웠다. 이는 이번 모델과 자료에서 관찰한 결과이며, 모든 라우터가 불가능하다는 증명은 아니다.

## 판단과 한계

**채택하지 않는다.** 질문+결과 모델도 hybrid 고정의 Recall과 MRR을 넘지 못했다. 결과를 보고 트리 깊이·특징·전환 기준을 반복 조정하지 않는다. 현재 서비스 검색 방식은 그대로 유지한다.

문서별 분할은 같은 문서를 묻는 유사 질문의 누수를 줄였지만, 원 자료는 과거 분석과 검색 튜닝에 이미 사용했다. 사람 검수 전 gold의 한계도 있다. 이번 구간을 독립적인 일반화 검정으로 주장하지 않는다. 현재 코드에서의 효과, 새로운 도메인에서의 효과는 미측정이다. 향후 후보를 채택하려면 현재 검색 결과로 학습 데이터를 수집하고, 모델과 특징을 동결한 뒤 새로운 문서·질문으로 평가해야 한다.

## 재현과 검증

```sh
.venv/bin/python -m scripts.evaluate_learned_router \
  data/generated/docs-v2/comparison-135q-stage27-modes.json \
  --out data/generated/routing-v1/oof-stage27.json
```

결과 파일에는 입력 SHA256, 문서 묶음과 fold 배정, fold별 트리, 질문별 예측 이득·선택·실제 점수가 들어 있다. 세 방식의 질문·근거 라벨 일치, fold의 완전한 분할, 학습·평가 정답 부모 비중첩을 실행 시 검증했다. 같은 명령을 다시 실행해 결과 파일이 동일함을 확인했다. 표준 라이브러리만 사용하며 운영 의존성은 추가하지 않았다.
