# 45단계: 현재 docs+Core에서 조건부 검색 방식 전환

## 조건과 사전 설정

44단계는 27단계 당시 docs-only 결과를 재분석했다. 이번에는 사용자 요청대로 **현재 코드로 docs+Core를 함께 검색**했다.

- Core: `search-holdout-v20260923102126-0143e7`, 84,413청크.
- docs: `search-docs-only-v20260918101819-0ae9e1`, 1,198청크.
- 합계 85,611청크. 별칭을 실제 인덱스 이름으로 해석해 실행 중 고정했다. 옛 기본 `search-documents` 인덱스를 추가한 조건은 아니다.
- 주 평가: docs 135문항 + holdout 69문항 = 204문항. 42단계 결과 파일에서 당시 보정된 질문·정답을 추출했다.
- 별도 평가: validation-v2 core+docs 반환 정답 보정본 36문항. 모델 학습·기준 선택에 사용하지 않았다.
- 날짜 2026-09-25로 고정, k=5, 후보 깊이도 5, 반복 1회, 재작성 끔. BM25·vector·hybrid를 모두 같은 설정·정답으로 채점했다. 현재 검색 코드는 수정하지 않았다.

84,413과 1,198건의 색인 건수·임베딩 존재·차원을 확인하고, 질문의 근거 청크 존재·부모 ID·기록된 인용을 검사했다. 전체 코퍼스 본문을 준비 파일과 일대일 대조한 검증은 아니다. docs 018·020에 옛 Core에서 추가했던 `yestrade-form-22209#0002`, `yestrade-form-23307#0000`은 현재 두 인덱스에 없다. 해당 두 대안만 평가 범위에서 제외하고 현재 색인된 대체 정답을 유지했다. 근거 요구사항이 통째로 사라진 질문은 없다. 원본 정답 파일은 변경하지 않았다.

사전 설정: `data/generated/routing-combined-v1/protocol.md`. 질문 파일, 원본 SHA256, 실행 설정과 인덱스, 현재 검색 코드 SHA256은 같은 폴더에 남겼다.

## 하이브리드 기본, 예상 이득이 있을 때만 전환

44단계와 같은 특징·깊이 2 회귀 트리·잎 최소 8문항·예측 Recall 이득 0.02 초과 기준을 사용했다. 결과를 보고 조정하지 않았다.

204문항의 정답 부모 연결 성분 84개를 5개 fold(41/41/41/41/40문항)로 나눴다. 각 질문은 자신이 속한 fold를 학습하지 않은 모델로 예측했다. 같은 정답 부모가 학습·평가 양쪽에 있는 것을 금지했다. 전체 정답 부모가 다른 질문 사이 부분 근거 출처까지 완전히 분리한 검증은 아니다.

## 주 평가 결과

| 방식 | 근거 Recall@5 | 근거 MRR@5 | Recall 개선/악화 문항 |
|---|---:|---:|---:|
| 하이브리드 고정 | 0.86765 | 0.74688 | — |
| BM25 고정 | 0.71078 | 0.56555 | 5 / 39 |
| vector 고정 | 0.82108 | 0.72102 | 4 / 14 |
| 정답을 보고 최선 선택 | 0.90686 | 0.82207 | 9 / 0 |
| 질문 특징으로 조건부 전환 | 0.83824 | 0.72695 | 1 / 8 |
| 질문+결과 특징으로 조건부 전환 | **0.87255** | 0.73912 | 2 / 1 |

질문+결과 모델은 173문항에서 hybrid를 유지하고 19개를 BM25, 12개를 vector로 전환했다. 근거 Recall은 **+0.49%p**다. 문서 묶음 단위 paired bootstrap 5,000회의 참고용 95% 구간은 **[−1.12, +2.37]%p**로 0을 포함한다.

| 질문셋 | hybrid Recall | 질문+결과 전환 Recall |
|---|---:|---:|
| docs 135 | 0.86296 | 0.87037 |
| holdout 69 | 0.87681 | 0.87681 |

## 정밀도와 순위의 비용

| 지표, 204문항 | hybrid 고정 | 질문+결과 전환 |
|---|---:|---:|
| 문서 1위 적중 | 0.82353 | 0.81863 |
| 문서 Hit@5 | 0.89216 | 0.89706 |
| 반환 문서 Precision@5 하한 | 0.70572 | 0.69747 |
| 근거 Precision@5 하한 | 0.28043 | 0.27625 |
| 근거 MRR@5 | 0.74688 | 0.73912 |

Recall이 조금 올랐지만 다른 주요 지표가 함께 좋아진 것은 아니다. Precision은 기존 정답 라벨 기준 하한이다. BM25·vector가 새로 반환한 모든 문서/청크를 전수 판정하지 않았으므로, 표의 감소를 실제 무관한 결과 증가로 단정하지 않는다. 다만 동일한 고정 라벨에서 하이브리드를 대체할 일관된 이득은 확인하지 못했다.

질문+결과 전환에서 실제 근거 Recall이 변한 세 문항:

| 질문 | 선택 | hybrid → 전환 Recall |
|---|---|---:|
| docs-v2-074, 청년인턴 증명서 제출 방식 | BM25 | 0 → 1 |
| holdout-v1-004, 국내 외국 대사관 납품 | BM25 | 0 → 1 |
| holdout-v1-040, 수중익선 통제 조건 | BM25 | 1 → 0 |

서로 다른 두 실패는 회수했지만, 하이브리드가 이미 맞힌 한 질문을 잘못 전환했다. 특정 세 질문을 보고 예외 규칙을 추가하지 않았다. vector 전환 12개는 이 평가에서 Recall 증가나 감소를 만들지 않았다.

## 별도 36문항 평가

204문항 전체로 학습한 뒤 별도 36문항을 예측했다. 이 질문들의 라벨은 모델 학습에 사용하지 않았다. 정답 부모가 학습 자료와 겹치는 5문항은 표시하고, 나머지 31문항도 따로 채점했다.

| 방식 | 별도 36 Recall | 정답 부모 분리 31 Recall |
|---|---:|---:|
| hybrid | 1.000 | 1.000 |
| BM25 | 0.88889 | 0.87097 |
| vector | 0.88889 | 0.87097 |
| 질문 특징 전환 | 1.000 | 1.000 |
| 질문+결과 전환 | 1.000 | 1.000 |

질문+결과 모델은 36문항 중 19개를 vector로 전환했지만 Recall·MRR은 hybrid와 같았다. hybrid가 이미 Recall 100%여서 개선 능력을 입증하는 자료가 되지는 않는다. 또한 이 36문항은 기존 검색 개발 과정에서 사용한 자료이므로, 완전히 새로운 독립 최종 시험이라고 주장하지 않는다.

## 판단

**운영에는 채택하지 않고 hybrid를 유지한다.** docs-only와 달리 합친 코퍼스에서는 오라클 Recall 여지가 +3.92%p이고 vector 개선 사례도 있지만, 현재 특징으로 실제 회수한 이득은 +0.49%p에 그쳤다. 불확실성 구간은 0을 포함하며 정밀도·순위도 개선되지 않았다. 이번 결과로 임계값을 재튜닝하지 않는다.

이 실험은 방식 전체 전환을 다룬다. 하이브리드 문서 선택은 유지하면서 문서 내 BM25 근거 청크만 보완하는 방법은 아직 이번 조건에서 시험하지 않았다.

## 재현과 확인

```sh
.venv/bin/python -m scripts.compare_combined_routing
.venv/bin/python -m scripts.evaluate_learned_router \
  data/generated/routing-combined-v1/comparison204.json \
  --evaluation-report data/generated/routing-combined-v1/comparison36.json \
  --out data/generated/routing-combined-v1/router.json
```

고정된 검색 결과의 오프라인 라우터 계산을 다시 실행해 바이트 동일성을 확인했다. 질문별 선택, 실제 점수, fold별 모델, 별도 평가 모델, docs/holdout별 정밀도와 Recall은 `router.json`에 있다. 기존 44단계 계산도 재실행해 핵심 summary가 보존되는 것을 확인했다. 운영 검색 코드와 의존성에는 변경이 없다.
