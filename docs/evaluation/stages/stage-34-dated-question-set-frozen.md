# 34단계: 날짜가 비슷한 문서를 구별하는 질문 동결

33단계에서 연례 CP 보고 공고 2문항이 다른 연도의 문서에 밀렸다. 이를 한두 질문에 맞춘 규칙으로 고치지 않도록, **검색하기 전에** 날짜 질문 14개를 작성해 동결했다.

- 질문: [data/queries_date_validation_v1.jsonl](../../../data/queries_date_validation_v1.jsonl). SHA-256 `0e31089ed15bbc3b1d88ff1059dcd1cea9ea024f5b03dd14f047ca651dbc18c4`.
- 출처·동결 상태: [manifest.json](../../../data/generated/date-validation-v1/manifest.json). 원본은 `core.jsonl`이며 그 해시도 매니페스트에 기록했다.
- CP 보고 8문항: 2015, 2017, 2019, 2022 상·하반기, 2024, 2025 상·하반기 공고에서 마감일·보고 대상·첨부 내용 등을 물었다.
- 다른 날짜 문서 6문항: 2010·2017·2019년 워크숍, 2022년 HS 개정, 2013년 교육, 2016년 멘토링 공고.

질문과 모범답안은 각 출처 본문을 읽고 작성했다. 각 문항에 출처 부모와 확인한 근거 청크를 지정했으며, 요구 문구가 해당 청크에 있는지 공백 정규화 후 검사했다. **이 커밋 시점까지 14개 질문을 검색 API에 보내지 않았다.** 질문은 실패 원인을 겨냥해 의도적으로 고른 진단셋이라 일반 코퍼스 성능의 무작위 추정치가 아니다. 초기 정답은 출처 문서 하나만 담으므로, 검색 후 동등 문서가 반환되면 원본을 보존한 채 별도 판정으로 보정해야 한다. 질문과 판정은 사람 검수 전이다.

다음 단계에서는 현재 랭커를 먼저 그대로 평가하고, 새 진단셋에 맞춘 임계값 변경 없이 반복되는 원인을 조사한다. 무응답 문서는 이 단계에서 다루지 않는다.
