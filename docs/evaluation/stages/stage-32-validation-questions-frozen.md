# 32단계: 새 질문과 정답을 검색 전에 동결한다 (2026-09-25)

31단계에서 뽑은 36부모의 **지정 청크만 먼저 읽고** 부모당 질문 하나를 작성했다.
샘플의 빈 서식, OCR 표, 영문 통제목록도 임의로 다른 문서로 바꾸지 않았다. 36개
모두 질문을 만들 수 있었으므로 제외는 0건이다.

## 동결 자료

- [질문 초안과 요구사항](../../../data/generated/validation-v2/queries_spec.json):
  질문, 모범답안, 요구사항별 원문 문구, 지정 부모·청크.
- [core 단독 질문셋](../../../data/queries_validation_v2.jsonl): 36문항, SHA-256
  `d44e49607289beaeaf28cda567df61b040c885cbdc4807787c6045f0877084ee`.
- [core+docs 질문셋](../../../data/queries_validation_v2_combined.jsonl): 36문항, SHA-256
  `d5f293dc1ff8ad96470ba2a0c44e99a69f583947cefe86c623fc92ad954c80fb`.
- [매니페스트](../../../data/queries_validation_v2.manifest.json): 시드, 소스 해시,
  질의 해시와 동결 상태.

`scripts/build_holdout_queries.py`로 요구사항의 문구를 84,413개 core 청크와 docs
청크에서 정규화 문자열 일치로 찾았다. 동일한 완전 답 문서를 `gold` 대안으로 넣고,
core+docs용 질문셋에는 docs 쪽 대안도 넣었다. 질문·모범답안과 지정 청크의 문구가
일치하지 않으면 빌더가 중단한다. 이번에는 36문항 모두 통과했다.

유형은 시나리오 8, 바꿔 묻기 5, 식별자 11, 복수 근거 7, 서식 5문항이다. 질문과
정답은 assistant가 작성했으며 사람 검수 전이다. 문구 일치는 표현이 다른 동등
답을 놓칠 수 있으므로 검색 후 상위 5위 새 문서를 따로 판정해야 한다.

이 시점까지 **이 36개 질문을 검색 API에 보내지 않았다.** 33단계에서 현재 설정을
그대로 측정한다. 결과를 보고 제목 가중치나 컷오프를 재선택하지 않는다.
