# 28단계: `title^1`+다중 인덱스 DFS 랭커의 판정, 평가 도구 수정, 서버 반영

랭커 수정 `af064c9`를 고정한 채 새 상위 결과의 라벨을 판정하고(28.1), 그 재측정 중 드러난 혼합 코퍼스 평가기의 색인 범위 오류를 고치고(28.2), 수정한 코드를 실험 서버에 반영해 결과가 같은지 확인했다(28.3). **결론: 반환 문서 Precision@5가 docs +15.9p, holdout +7.0p 올랐고, 근거 손실은 holdout-v1-004 한 문항이다.**

> 원래 단계별 파일로 나뉘어 있던 기록을 주제별로 합쳤다. 질문을 검색 전에 동결했다는 증거는 각 단계의 개별 커밋에 남아 있으므로, 문서만 합쳤다. 원래 단계는 절 번호로 바꿨고, 절 제목의 옛 번호는 커밋 메시지·결과 파일명(`stage39` 등)과 대조할 수 있도록 괄호에 남겼다.

- 28.1 제목 가중치와 전역 BM25 변경을 고정한 뒤 새 결과를 판정한다 (2026-09-25)
- 28.2 혼합 코퍼스 평가에서 색인 범위를 정확히 확인한다 (2026-09-25)
- 28.3 수정한 랭커를 실험 검색 서버에 반영한다 (2026-09-25)

## 28.1 제목 가중치와 전역 BM25 변경을 고정한 뒤 새 결과를 판정한다 (2026-09-25) (옛 28단계)

26단계 후속 수정 `af064c9`는 제목 가중치를 `title^3`에서 `title^1`로 낮추고,
서로 다른 인덱스를 함께 검색할 때 BM25에 `dfs_query_then_fetch`를 사용한다.
수정 후 처음 상위 5위에 들어온 문서를 기존 `gold`만으로 오답 처리하면 정밀도 개선을
과소평가할 수 있다. 이번 단계는 **랭커를 고정한 채 라벨만 검토**했다. 이 결과를 보고
004번만을 위한 검색 규칙이나 컷오프는 만들지 않는다.

### 범위와 판정

- docs v2 135문항: 이전 상위 5위에 없던 문서 25쌍을 확인했다. 기존 정답 3쌍,
  부분 답 1쌍, 완전 답을 확인하지 못한 21쌍이었다. 새 완전 정답은 없었다.
- holdout v1 69문항: 새 문서 35쌍 중 기존 정답 5쌍, 새 완전 정답 5쌍,
  부분 답 3쌍, 완전 답을 확인하지 못한 22쌍이었다.
- 새 정답: 002의 고시 제23조(15일·기술심사 제외), 023의 6A002.a.2.a 영상 강화 튜브,
  027의 다이아몬드 고시 제7·8조(서류·7일), 057의 통관고시 제3조(신고서 번호),
  064의 목록 해설(CAS 번호). 모두 실제 반환 청크에도 답이 있었다.
- 판정은 질문과 모범답안에 반환 청크를 대조하고, 완전 정답 가능성이 있는 부모의
  다른 청크도 확인했다. 모든 부모의 모든 청크를 한 줄씩 수동 검수한 것은 아니다.
  판정자는 assistant이며 사람 검수는 아직 없다.
  [판정 원장](../../../data/generated/holdout-v1/title1_dfs_top5_audit.json)에 쌍별
  상태와 근거 청크를 남겼다.

### 동일 질의의 변경 전후

기존과 새 결과에 **동일한 보정 `gold`**를 적용했다. 수치는 질문별 평균이며 차이의
구간은 질문을 단위로 10,000번 재표집한 대응표본 부트스트랩 95% 구간이다.

| 질의셋·지표 | 기존 | 수정 | 차이 [95% 구간] |
|---|---:|---:|---:|
| docs 135 · 문서 1위 | 0.807 | 0.837 | +3.0p [0, +6.7]p |
| docs 135 · 반환 문서 Precision@5 | 0.596 | **0.755** | **+15.9p [+11.6, +20.3]p** |
| docs 135 · 근거 Recall@5 | 0.856 | 0.863 | +0.7p [0, +2.2]p |
| docs 135 · 근거 Precision@5 하한 | 0.199 | 0.247 | +4.8p [+2.9, +7.1]p |
| holdout 69 · 문서 1위 | 0.754 | 0.797 | +4.3p [−2.9, +11.6]p |
| holdout 69 · 반환 문서 Precision@5 | 0.539 | **0.609** | **+7.0p [+2.1, +12.1]p** |
| holdout 69 · 근거 Recall@5 | 0.891 | 0.877 | −1.4p [−4.3, 0]p |
| holdout 69 · 근거 Precision@5 하한 | 0.308 | 0.346 | +3.8p [−0.2, +8.2]p |

수정 결과: [docs 135](../../../data/generated/holdout-v1/results/mixed-title1-dfs-top5-audited.json),
[holdout 69](../../../data/generated/holdout-v1/results/holdout-title1-dfs-top5-audited.json).
Precision 하한은 아직 모든 비정답 청크를 개별적으로 무관하다고 판정하지 않았기
때문이다. 문서 Precision도 상위 5위 밖의 정답 문서를 전수 조사한 값은 아니다.

### 실제 퇴행: holdout-v1-004

질문은 주한 외국공관 납품과 재외 한국공관 반출의 수출 여부를 구분해 묻는다. 기존
검색은 `yestrade-faq-5#0000`을 2위에 실어 완전한 답을 제공했다. 수정 후 같은 1위
문서 뒤에 `yestrade-faq-105`(해외 출장자의 기술 이전)와 무형이전 FAQ가 올라왔고,
정답 FAQ는 상위 5위에서 빠졌다. 새 두 문서에는 공관에 대한 답이 없다.
근거 Recall 손실은 69문항 중 이 **한 문항**이다. 이를 보고 제목 가중치를 다시
미세 조정하면 holdout 자체에 과적합된다. 현 변경의 비용으로 기록한다.

### 판단과 다음 검증

다중 인덱스의 통계를 공유하는 것은 코퍼스마다 다른 BM25 기준을 비교하던 구조적
문제를 바로잡는다. 제목 반복에 따른 `title^3` 증폭도 낮췄다. 두 질의셋에서 반환
문서 Precision이 올랐고 docs의 근거 Recall 손실은 없었다. 다만 두 질의셋 모두
개발 과정에서 이미 열어 본 자료이므로 **독립적인 일반화 성능 증명은 아니다**.
다음에는 코퍼스 출처 또는 수집 시점을 분리한 새 질의셋을 먼저 동결하고, 이 설정을
바꾸지 않은 채 평가해야 한다. 그 전에는 004 전용 보정이나 추가 임계값 탐색을 하지 않는다.

## 28.2 혼합 코퍼스 평가에서 색인 범위를 정확히 확인한다 (2026-09-25) (옛 29단계)

28.1절 재측정 때 평가기에 holdout의 `core.jsonl` 폴더만 주면 docs 정답이 모두
미색인으로 표시됐다. 평가기는 결과 JSON을 쓴 뒤 `answerable['queries']`를 읽으며
`KeyError`로 종료했다. 검색 자체의 오류는 아니지만, 순위 실패와 색인 범위 실패를
가르는 보고서가 신뢰할 수 없게 된다.

### 수정

- `search-evaluate --prepared DIR`를 여러 번 줄 수 있게 했다. 각 폴더의
  `core.jsonl`·`docs.jsonl`·`hsk.jsonl` ID를 합쳐 색인 범위를 확인한다.
- 정답이 색인된 질문이 0개여도 보고서는 `0건`으로 출력한다.
- 별도 폴더의 부모 ID를 합치는 테스트와 정답 전부 미색인인 보고서 테스트를 추가했다.

### 확인

```sh
.venv/bin/search-evaluate data/queries_docs_v2.jsonl \
  --base-url http://127.0.0.1:8113 \
  --prepared data/generated/holdout-v1 \
  --prepared data/generated/docs-v2/review-corpus \
  --k 5 --out /tmp/stage29-multicorpus-check.json
```

135문항의 보고서가 정상 종료됐다. 정답이 모두 색인된 질문은 133개이며,
`docs-v2-018`의 `yestrade-form-22209`와 `docs-v2-020`의 `yestrade-form-23307`은
두 준비 폴더 어디에도 없다고 구분해 표시했다. 이 확인에 쓴 8113 서버는 이전
검색 코드로 실행 중이므로, 여기서 나온 검색 적중률은 28.1절의 새 랭커 성능이 아니다.
전체 테스트는 236개 통과했다.

### 범위

이 단계는 평가 도구의 색인 범위와 보고서 종료 오류만 고쳤다. 검색 순위와 `gold`는
변경하지 않았다. 여러 준비 폴더에 파일이 있더라도 실제 검색 인덱스의 별칭이 그
파일을 가리키는지는 별도로 확인해야 한다.

## 28.3 수정한 랭커를 실험 검색 서버에 반영한다 (2026-09-25) (옛 30단계)

26단계 후속 코드 수정 `af064c9`와 28.1절 판정까지 완료했지만, 기존 8112·8113
프로세스는 수정 전 코드를 실행 중이었다. 두 서버를 같은 환경 설정으로 순서대로
재시작했다.

| 포트 | 검색 범위 | 별칭 | 확인 |
|---|---|---|---|
| 8112 | `SEARCH_DOCUMENT_DATASETS=core` | `search-holdout` | `/v1/search` HTTP 200 |
| 8113 | `SEARCH_DOCUMENT_DATASETS=core,docs` | `search-holdout` + docs 별칭 | `/v1/search` HTTP 200 |

두 서버 모두 `SEARCH_HSK_ENABLED=false`다. 실제 검색 결과를 28.1절의 저장 결과와
대조했다. 8113의 docs-v2-001·007·020·130, 8112의 holdout-v1-002·004·064에서
반환 부모 순서가 전부 일치했다. 004의 알려진 근거 누락도 그대로 재현된다.

이는 새 코드가 현재 서버에 적용됐다는 연기 테스트다. 전체 135·69문항을 다시
측정한 독립 검증이나 새 자료에서의 일반화 검증은 아니다. 28.1절의 확인된
검색 품질 수치와 퇴행은 그대로 따른다.
