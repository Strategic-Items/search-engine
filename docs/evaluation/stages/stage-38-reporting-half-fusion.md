# 38단계: 명시된 보고 반기를 하이브리드 순위에 반영

## 변경

질문에 하나의 `YYYY년 상반기/하반기`가 명시되면, 기존 어휘·벡터 후보 중 제목에 **같은 연도와 반기**가 적힌 청크를 세 번째 RRF 목록으로 만든다. `20YY년`, `YY년도`, `YYYY` 등 제목 표기를 2000년대 연도로 정규화한다. 대상 기간이 발행일의 다음 해일 수도 있으므로 `published_at`으로 필터링하지 않는다. 기간이 모호하거나 제목에서 일치하지 않으면 기존 검색 그대로다. 기존 주제 검색 후보 밖의 문서를 추가하지 않는다. 코드 위치는 `search_engine/search/query.py`다.

처음 구현은 융합 전 점수 컷오프를 통과한 후보만 대상으로 했으나, 36단계 질문을 보고 해당 처리 순서를 수정했다. 따라서 36단계 8문항은 **개발 중 확인**이며 독립 검증이 아니다. 37단계의 CP 이외 7문항은 이 수정 뒤, 검색 실행 전에 동결했고 그 결과를 보고 후보를 다시 고르지 않았다.

## 같은 질문·정답으로 전후 비교

| 질문셋 | 1위 기존 → 변경 | 5위 내 기존 → 변경 | 근거 Recall@5 기존 → 변경 |
|---|---:|---:|---:|
| 35단계 날짜 진단 14 | 6 → 10 | 10 → 12 | 0.714 → 0.857 |
| 36단계 CP 확인 8 | 0 → 4 | 4 → 7 | 0.500 → 0.875 |
| 37단계 비CP 기간 7 | 5 → 7 | 7 → 7 | 1.000 → 1.000 |
| 33단계 새 검증 36 | 34 → 36 | 34 → 36 | 0.944 → 1.000 |
| docs 135 | 113 → 113 | 120 → 120 | 0.863 → 0.863 |
| holdout 69 | 55 → 55 | 62 → 62 | 0.877 → 0.877 |

37단계 비CP 기간 7문항은 검색 결과의 동등한 상담회 첨부 두 건을 본문으로 확인해 **양쪽 실행에 동일한 정답표**로 추가한 수치다. 원래 동결한 질문 파일은 보존했다. docs 135와 holdout 69는 집계뿐 아니라 반환 부모·청크 배열도 질문별로 모두 동일했다. 그 두 회귀셋의 `gold_groups`에 빠져 있던 기존 정답 부모를 파생 입력 파일에서 같은 그룹에 넣었고, 기존 서버를 다시 평가하여 이전 28단계 수치와 같음을 확인한 뒤 후보와 비교했다.

결과 파일은 `data/generated/date-validation-v1/results/`, `data/generated/date-confirm-v1/results/`, `data/generated/period-other-v1/results/`, `data/generated/validation-v2/results/`에 있다. 문서 precision은 아직 모든 반환 후보를 완전히 판정한 값이 아니므로 하한이다. 질문과 추가 정답은 사람 검수 전이다. 기간 관련 집합은 작고 특정 유형에 치우쳐 있으므로 통계적 일반화까지 주장하지 않는다.

## 남은 실패와 적용 범위

CP 확인셋에서 2023년 하반기 공고와 날짜 진단의 2025년 하반기 공고는 최종 상위 5위 밖이다. 이후 40단계에서 원시 검색을 직접 확인하니 두 문서 모두 어휘 25청크와 벡터 50청크 안에 있었다. **후보 생성 문제라는 앞선 진단은 틀렸다.** 연도·반기만 일치하는 다른 주제의 문서가 반기 목록을 앞서고, 원래 목록에서 점수 컷오프로 잘린 정답 문서는 최종 비율 컷오프도 통과하지 못한다. 이 질문들에 맞춰 후보 크기나 가중치를 다시 고르면 과적합되므로 이번 변경에 포함하지 않았다.

단위 테스트는 두 자리 연도, 반기 불일치, 복수 기간 질문, 융합 전 점수 컷오프 아래 후보의 회복을 확인한다. 전체 테스트 239개가 통과했다. 무응답 문서 판정은 별도 판정자가 필요하므로 이번 범위에서 제외했다.
