# 표 하나를 청크 하나로 보관하는 실험 — 2026-10-12

파서 저장소의 `data/category_chunks` 번들 189개에서 비어 있지 않은 표 원소 394개를 비교했다.
운영 청커와 인덱스는 바꾸지 않았다. 표 분할 조건만 비활성화한 함수 복사본으로 실행했다.

|---|---:|---:|---:|

전체 문서의 청크 수는 6,898개에서 3,212개로 줄었다. 표 394개 중 182개가 분할에서 단일 청크로 바뀌며,
212개는 현재도 한 청크다. 본문 길이는 HTML·Markdown 마크업이 포함된 색인 본문 기준이다.
세 번째 열은 셀·행 경계를 탭·줄바꿈으로 남기고 HTML 태그를 제거한 진단용 표현이다.
Markdown 표는 그대로 두었다. 병합 정보 등을 보완한 완성된 검색용 직렬화는 아니다.

위반행위 평가표는 현재도 통째로 들어간다. 분할 판정 시 HTML을 제거한 길이가 660자로 800자 이하이기 때문이다.
색인 본문에는 HTML이 남아 SPLADE 입력이 1,319토큰으로 늘어난다. 이 사례에서는 태그를 제거하면 469토큰이 된다.

## 해석

- 표 전체를 보존하면 행·열의 비교 맥락을 한 청크에 담고 청크 수를 줄일 수 있다.
- 현재 SPLADE 인코더는 `truncation=True`, 문서 최대 512토큰을 사용한다. 한도를 넘는 입력의 초과 부분은
  희소 벡터에 반영되지 않는다. 원문 전체를 저장하는 것과 검색 모델이 전체를 읽는 것은 다르다.
- HTML을 제거해도 167개 표(42.4%)가 512토큰을 넘는다. 큰 목록·대비표의 길이는 마크업 정리만으로 해결되지 않는다.
- RAG 프롬프트의 `format_documents`는 선택된 본문 전체를 붙인다. 큰 표가 선택되면 전달하는 근거도 커진다.
- 작은 표의 전체 보존은 후보 전략으로 남길 수 있다. 판단 기준은 글자 수뿐 아니라 실제 모델 입력 토큰이어야 한다.

## 측정 범위와 제한

표 하나는 파싱된 표 원소 기준이며 여러 페이지 또는 여러 논리 표를 포함할 수 있다.
표별 토큰은 실제 설정의 `/Users/jeongbin/models/splade-c` 토크나이저로, 제목·표 내부의 이용 가능한 제목 경로와
본문을 구성해 절단 없이 셌다. 표별 비교는 표 원소를 독립 실행했으므로 주변 문서 제목 경로는 포함하지 않는다.
실제 전체 문서 파이프라인의 청크 수는 별도로 측정했다.

검색 Recall·순위·답변 정확도, dense 임베딩과 reranker의 실제 절단 여부는 측정하지 않았다.
이 결과만으로 단일 청크 방식의 검색 성능 향상·하락을 확정할 수 없다.
