# 앞으로 시도할 수 있는 방법 (미측정 후보)

> **이 문서의 지위.** 2026-10-01 기준으로 단계 문서 1~34와 `docs/design/`를 읽고, 같은 이름의
> 시도 기록을 찾지 못한 방법을 모은 것이다. **아무것도 측정하지 않았다.** 효과 크기는 가설이며,
> 코드를 전수 확인한 것이 아니므로 이미 해본 것이 있으면 이 문서를 고친다.
> 기존 진행 상태는 [현재 판단과 다음 측정](current_judgment.md)이 맡는다.

## 병목이 어디인가

- docs만 읽을 때 근거 Recall@5는 0.963이지만 core를 섞으면 0.911, docs+holdout은 0.863이다.
- 처음 보는 데이터에서 문서 1위 적중이 0.948 → 0.841(−10.8p)로 떨어졌다([26단계](stages/not-applied/stage-26-holdout-overfitting-check.md)).
- 정답은 대부분 후보 안에 있고, 같은 주제인데 답이 없는 문서에 밀린다([32단계](stages/applied/stage-32-why-the-answer-is-not-first.md)).
- 가중치·규칙·청크별 LLM 등급·부모 순위 RRF는 이미 기각됐다. **새 신호나 새 정보**가 필요하다.

## 후보 (효과 기대 순)

### 1. 문서 단위 cross-encoder 재정렬
- 리랭커는 8단계에서 기각, 19단계에서는 문서 *안* 청크 선택에만 썼다(`@1` +28.5p).
- 문서 후보 top-N을 리랭커로 다시 정렬한 기록은 없다. 32단계 병목과 직접 맞닿아 있다.
- 지연: 호스트 MPS 약 1.2초, 컨테이너(CPU 2코어) p50 17초. 서빙 환경을 정한 뒤 다시 재야 한다.
- 시험 자리: 기존 동결셋(validation-v2, date-validation-v1)으로 가능. 새 질의셋은 필요 없다.

### 2. Contextual Retrieval (청크에 문맥을 붙여 색인)
- LLM으로 청크마다 "이 청크가 어느 문서의 어느 부분인가"를 한두 문장 만들어 앞에 붙인 뒤 임베딩과 BM25를 만든다.
- 청크가 제목·시행일·서식 번호 같은 문서 맥락을 잃어 방해 문서에 밀리는 문제를 겨냥한다.
- 색인 때 한 번만 비용이 들고 검색 경로 지연은 늘지 않는다.
- 제약: **docs는 재생성 금지**(docs 코퍼스 고정 결정, 2026-09-23). 맥락 필드는 새 별도 인덱스에 만든다. 전체 84,413청크는 생성 비용이 크므로 docs 1,198청크로 먼저 본다.
- 선행 확인: 32단계 실패 사례가 정말 맥락 부족 때문인지 먼저 본다.

### 3. doc2query / 가상 질문 색인
- 청크마다 "이 청크가 답이 되는 질문" 3~5개를 LLM으로 만들어 별도 필드로 색인한다. 질문–질문 비교로 어휘·의미 격차를 줄인다.
- **누수 주의:** 평가셋 질문이 아니라 청크에서만 생성한다. 생성 프롬프트에 평가 질문을 넣지 않는다.

### 4. BGE-M3 multi-vector(ColBERT 방식) 재채점
- dense·sparse는 써 봤고 같은 모델의 토큰 단위 multi-vector 점수는 안 썼다.
- 상위 N개 후보만 재채점하면 비용이 작고 추가 모델이 필요 없다.

### 5. Learning-to-Rank
- BM25·dense·제목 일치·기간 일치·현행판 여부 등 이미 있는 신호를 피처로 두고 LightGBM 등으로 순위를 학습한다.
- 27단계는 검색 방식 라우팅이었고 순위 학습이 아니다.
- 문서 단위로 fold를 나눠야 과적합을 피한다.

### 6. 질의 구조화 → 메타데이터 필터·부스트
- 질의에서 연도·반기·고시 차수·서식 번호·문서 종류를 뽑아 필터나 강한 가산점으로 쓴다.
- 30단계는 기간에 한해 비슷한 일을 한다. 문서 종류와 차수까지 일반화한 것은 없다.

### 7. 문서 간 관계 그래프
- 대체 관계는 서식에만 있다([supersession_v1](../design/supersession_v1.md)).
- 고시 ↔ 별표 ↔ 공지, 개정 이력을 묶어 방해 문서와 정답을 가른다.

### 8. Pseudo-Relevance Feedback (RM3)
- 1차 상위 결과에서 용어를 뽑아 질의를 확장한다. 5단계는 LLM 재작성이고 동의어는 정적 사전 20그룹이다.

### 9. 융합 방식 교체 — 측정함, 기각 ([40단계](stages/not-applied/stage-40-rrf-fusion-variants.md))
- SPLADE(C)+dense에서 RRF k(30/60/100), SPLADE 가중 RRF, 점수 정규화 후 가중합(CombSUM 방식)을 docs_v2 135·
  holdout-small 69로 비교했다. k는 최종 비율 컷오프 때문에 이 범위에서 무의미하고, SPLADE 가중치를 올리면
  문서 P@1이 떨어지며, 점수합은 RRF와 사실상 같다(차이는 잡음 수준). 질의 길이·유형별 가중치는 아직 안 쟀다.

### 10. 제목 전용 임베딩 필드
- 제목만 따로 벡터화해 별도 목록으로 RRF에 넣는다. 지금의 `title^1`은 BM25 쪽 제어다.

### 11. 임베딩 질의 프롬프트·Matryoshka
- 질의 instruction 접두어(모델 지원 여부 확인 필요). 차원 축소는 성능보다 지연·크기 이점이다.

### 12. 임베딩 파인튜닝
- BGE-m3-ko로 교체한 것이 전부이고(Qwen3-0.6B는 11단계 기각, 4B는 위 13번) 도메인 쌍 학습은 없다.
- 학습 문서와 시험 문서를 분리해야 한다. 과적합 측정이라는 26단계 목적과 충돌하기 쉽다.

### 13. Qwen3-Embedding-4B를 BGE-m3-ko와 다시 비교 (추후)
- [11단계](stages/not-applied/stage-11-qwen3-embedding.md)가 시험한 것은 0.6B 하나이고 dense 단독 비교뿐이다. 4B 이상은 시험하지 않았다. 11단계의 "포화라서 dense 여지가 좁다"는 진단은 [13단계](stages/applied/stage-13-bge-m3-ko.md)에서 절반 틀렸다고 확인됐다.
- 비교 기준은 bge-m3가 아니라 현행 BGE-m3-ko. 질의 접두사(`Instruct:`)를 적용한 조건으로 재고(접두사 유무가 MRR 0.8778 → 0.9037), 하이브리드까지 본다.
- 제약: 8B는 쓸 수 없고 4B를 쓸 수 있는지는 서빙 환경에서 먼저 확인한다. 출력 차원이 1024가 아니면 매핑 변경과 전체 재색인이 필요하다. 새 인덱스(alias)로 따로 만든다.
- 시험 자리: 기존 135문항과 동결셋. 새 질의셋은 필요 없다.

## 이미 열려 있는 항목 (참고)

[현재 판단](current_judgment.md)의 「아직 열려 있는 것」과 겹치는 것만 적는다.

- 재청킹 재판단(두 처방 적용 후 미측정), `semantic_hybrid` 청킹 미시험
- SPLADE 채택 조건 3가지(미판정 19% 블라인드 판정, 같은 규칙 재비교, 지연·인덱스 크기)
- 첨부 미파싱 core 문서 22건, 거대 공지 4건 첨부 분리, docs–core 중복 5건
- docs 인덱스 재색인(`period_hint` 0건; 인덱스만, 코퍼스는 고정)
- LLM 청크 필터 + 무응답 판정자 조합 효과와 운영 지연(p50 15.33초)
- HSK 코드 정확 일치 재측정, core 질의 93문항 `evidence_groups`, 사람 검수, 답변 사실성

## 시험할 때 지킬 것

- 측정 먼저: 곡선 전체와 Recall·Precision 둘 다 보고, 짐작한 상수로 정하지 않는다.
- 주 지표는 근거 청크 지표(`evidence_recall_at_k` 등)이고 문서 지표는 진단용이다.
- 기존 동결셋으로 먼저 시험하고, 새 질의셋이 필요하면 만들기 전에 묻는다.
- 개발 셋 점수와 holdout 점수의 차이를 함께 적어 과적합 크기를 본다.
