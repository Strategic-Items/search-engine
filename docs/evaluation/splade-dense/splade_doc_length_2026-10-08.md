# SPLADE 문서 최대 길이 비교 (2026-10-08)

법령·고시 코퍼스 6,503청크에서 문서 인코딩 최대 길이 256·512·1024를 비교했다. dense 벡터는 같은 값으로 고정했고, SPLADE 질의 최대 길이 256과 저장 상위 토큰 256개도 유지했다. 법령 질문 149개를 사용했다.

## 결과

|---:|---:|---:|---:|---:|---:|---:|

512는 256보다 근거 회수가 컷오프 0.7에서 1문항, 0.95에서 3문항 높았다. 대응 질문 기준 bootstrap 구간은 차이에 0을 포함하므로 개선 신호는 작고 불확실하다. 1024는 512보다 나아지지 않았다.

인코딩 범위 안에 완전히 들어오는 청크는 256에서 4,534/6,503(69.7%), 512에서 6,243/6,503(96.0%), 1024에서 6,470/6,503(99.5%)이었다. 길이를 512로 늘린 SPLADE 벡터를 만드는 데 이 코퍼스에서 약 297초가 걸렸다.

## 판단과 한계

이 비교에서는 512를 설정 기본값으로 채택했다. 결과는 같은 149문항 평가셋에서 얻었으며 독립 holdout 검증은 아니다. 법령·고시 외 카테고리의 효과와 운영 지연은 측정하지 않았다. 설정을 바꾸는 것만으로 기존 인덱스의 벡터가 갱신되지는 않으므로 해당 카테고리를 다시 색인해야 한다.
