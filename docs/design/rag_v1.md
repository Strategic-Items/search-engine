# RAG v1 기록 (2026-09-16)

Spring AI 구현에서 질의 압축, 검색, 가드레일, 스트리밍만 이식했다. STT·PII 마스킹·상담카드
같은 콜센터 파이프라인은 범위 밖이다.

## 결정

RAG는 별도 FastAPI가 아니라 `search_engine` 앱의 `POST /v1/rag/stream`으로 합쳤다.
리트리버는 자신의 `/v1/search`를 HTTP로 왕복하지 않고 `search_all()`을 프로세스 안에서
호출한다. 따라서 `uvicorn search_engine.api:app` 한 대만 실행하며, 내부 요청에 API 키를
전달할 필요도 없다. OpenSearch의 동기 전송은 `anyio.to_thread.run_sync`로 옮겨 이벤트
루프를 막지 않는다.

SSE는 EventSource의 GET 대신 POST를 쓴다. 클라이언트는 `fetch`의 응답 스트림을 읽어야
한다. API 키 인증은 현재 사용하지 않는다.

가드레일은 근거가 없으면 모델을 호출하지 않고 안내문만 낸다. 근거가 있는 경우에도 확정
판정을 하지 않고 yesTrade 전문판정 신청을 안내한다. 색인의 사람이 읽는 `source_type`을
그대로 프롬프트에 넣어, 기존의 `law/knowledge/case` 라벨 불일치로 모든 자료가 “검색 자료”가
되던 문제를 없앴다. 제목·시행일·출처와 대체 문서 ID도 함께 넣는다.

후속 질문 압축 프롬프트에는 예시(few-shot)를 넣지 않는다. Spring 원본은 예시 두 개를
들고 있었고 이식할 때도 함께 옮겼으나, qwen2.5:3b에서는 히스토리가 길어지면 모델이 실제
대화 대신 예시의 주어를 베껴 왔다 — 자가판정 답변 뒤의 "그거 연장은 어떻게 해?"가
"도서관 회원증 연장 방법"으로 압축되어 검색이 0건이 됐다. 예시를 도메인 안팎 어느 쪽으로
바꿔도 베끼는 대상만 달라졌다. 예시를 모두 빼고 "대화의 주어를 반드시 포함하라"는 규칙을
직접 쓰면 같은 히스토리에서 3/3으로 주어가 유지된다. 안전망으로, 압축 결과가 히스토리와
단어를 하나도 공유하지 않으면 지어낸 것으로 보고 원본 질의로 되돌린다.

검색 실패는 스트림 헤더 전에 일어나므로 503을 반환한다. Ollama 실패는 헤더가 이미 나간
뒤일 수 있어 `event: error` SSE 프레임으로 알리고 `event: done`을 보내지 않는다. 부분
답변이 난 실패 턴은 메모리에 저장하지 않는다.

## 알려진 한계

세션 메모리는 프로세스 내부의 제한된 LRU이며 재시작 시 사라지고 여러 worker 사이에서
공유되지 않는다. `session_id`에 대한 별도 인증도 없으므로, 신뢰 경계 밖에 API를 노출할
때는 인증과 서버 측 세션 키를 추가해야 한다. 수평 확장 시 Redis가 필요하다.
색인 본문은 프롬프트 인젝션 입력 경로이며 템플릿만으로 방어되지 않는다. 검색과 RAG가 각각
`date.today()`를 호출하는 점은 장기적으로 공용 기준일 헬퍼로 묶을 수 있다.
