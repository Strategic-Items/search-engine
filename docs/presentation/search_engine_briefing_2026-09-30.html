검색 과정 설명

지난 발표는 결과 수치를 앞에 두었습니다. 이번에는 질문이 들어와서 답변 근거가 될 청크가 되기까지의 경로를 먼저 보여 드립니다. 수치는 그 경로가 맞는지 확인하는 뒷받침으로 뒤에 둡니다.

이번 과제의 범위. 2차년도는 비정형 문서(RAG용)를 특정 도메인에서 검색할 수 있는지 사전 점검하는 단계입니다. 통합 검색과 최종 요약 레이어는 3차년도 사업입니다.
말하기피드백 두 가지를 순서에 반영했습니다. 구조도를 먼저, 그다음 한 질문의 이동 경로.
전체 구조

RAG 전체 구조: 판정 LLM은 검색 뒤, 답변 앞에 있다

키워드 검색벡터 검색LLM 판정(선택 단계)
리랭킹이 아닙니다. 판정 LLM은 최종 청크를 읽고 "질문이 요구하는 사실이 적혀 있는가"를 예/아니오로만 답합니다. 순서를 바꾸지 않고, 아니오이면 결과를 비웁니다. 이 저장소에서 판정 LLM, 청크 관련도 필터, 청크 재정렬은 모두 기본값 꺼짐입니다.
말하기이 그림에서 주황 점선 상자만 LLM이고 나머지는 모델 없이 계산입니다.
용어 정리

벡터 검색이라고 부르던 것을 dense와 sparse로 나눈다

dense 벡터 (벡터 검색)
문장 하나를 고정 길이 실수 벡터로 바꾼 것입니다. 모든 칸에 값이 있고, 의미가 비슷하면 가깝습니다(코사인). 우리 벡터 검색이 이것입니다(BGE-m3-ko).
키워드 검색 (BM25)
벡터가 아닙니다. nori로 쪼갠 단어가 청크에 있는지 역색인에서 찾고, 단어 빈도와 희소성으로 점수를 냅니다. 벡터를 만들거나 저장하지 않습니다. 어휘 기반이라 정보검색에서 sparse 방식이라 부르기도 하지만, 우리 구현에서는 벡터 검색이 아닙니다.
sparse 벡터
어휘 사전의 칸마다 가중치를 두고 대부분이 0인 벡터입니다. 우리 시스템에는 아직 없고, SPLADE가 이것을 만들어 저장합니다.
learned sparse (SPLADE)
신경망이 어휘 가중치와 확장 어휘를 학습하는 sparse입니다. SPLADE는 sparse 벡터를 신경망이 만들어 저장하므로 도메인으로 재학습할 수 있습니다. BM25는 학습 대상이 아닙니다. 그래서 "SPLADE+벡터"가 아니라 "SPLADE(learned sparse) + dense"라고 부릅니다.
하이브리드
현재 운영은 BM25(키워드) + dense(벡터)이고, 점수가 아니라 순위로 합칩니다(RRF, 6장).
말하기앞으로 "키워드 검색"은 BM25(벡터 아님), "벡터 검색"은 dense로만 부릅니다.
문항별 경로

질문마다 어떤 경로로 그 결과가 나왔는지 본다

docs 정답형 135문항을 실제 클러스터에서 지금 운영 설정(문서 우선, 판정 LLM 끔)으로 다시 돌린 결과입니다. 앞선 95% 청크 컷오프 실험과는 설정이 달라 수치가 다릅니다. 노란 표시는 키워드 검색이 실제로 맞춘 단어입니다.

말하기대표 사례 3건(A 벡터가 살림, B 키워드가 살림, C 컷오프가 자름)부터 보여 주고, 나머지는 질문을 받아서 목록에서 고릅니다.
처리 방식

키워드는 잘게 쪼개서, 벡터는 청크째로

키워드 검색 (BM25)

  • 질문을 nori 형태소 분석기로 쪼갭니다. 조사와 어미는 버립니다(예: "쓰지 않는" → "쓸").
  • 도메인 동의어 사전을 검색 시점에 적용합니다.
  • 제목과 본문 두 필드의 점수를 더합니다(제목 가중치 1).
  • 점수는 색인 전체 통계로 계산합니다(두 색인을 함께 읽을 때 dfs 사용).
  • 단위는 청크이고, 후보는 25개입니다.

벡터 검색 (dense)

  • 문서를 통으로 넣지 않습니다. 파서가 자른 청크마다 제목과 본문을 합쳐 임베딩해 저장합니다.
  • 질문은 통째로 한 번 임베딩합니다.
  • 청크 벡터와의 코사인 유사도가 높은 청크 50개를 가져옵니다.
  • 어휘가 달라도 뜻이 같으면 잡힙니다. 번호와 코드는 약합니다.
말하기두 검색기 모두 청크가 단위이고, 문서 순위는 그 뒤에 부모 문서로 묶어서 만듭니다.
하이브리드 합산

두 목록은 점수가 아니라 순위로 합친다

  1. 1. 트림각 목록을 자기 1위 점수 대비 비율로 자릅니다. BM25 90%, 벡터 97%.
  2. 2. RRF부모 문서마다 목록별 순위를 1/(60+순위)로 바꿔 더합니다.
  3. 3. 컷오프합친 점수가 뒤처진 문서를 버립니다. 각 목록의 1위 문서는 살립니다.
  4. 4. 문서 안 청크 순서첫 청크는 벡터가 고른 것, 나머지는 두 목록의 청크 순위를 RRF로 합쳐 채웁니다.
점수(문서) = Σ 1 / (60 + 순위목록)    목록 = BM25, 벡터
동점이면 벡터 순위가 앞선 문서가 위
"최종 순위를 벡터 기준으로 다시 정렬했다"의 정확한 뜻. 문서 순위는 RRF가 정합니다. 벡터 순위가 관여하는 곳은 둘입니다. 동점일 때의 순서, 그리고 문서 안에서 어떤 청크를 첫 번째로 보여 줄지. 리랭킹은 하지 않았습니다.
사례 A로 보는 계산. 정답 문서의 BM25 점수 15.5는 1위 17.7의 88%라서 트림(90%)에서 BM25 목록을 빠져나갔습니다. 남은 것은 벡터 1위 한 표이고, 최종 점수 0.0164는 1/(60+1)과 같습니다.
말하기점수를 그대로 더하지 않는 이유는 BM25 점수와 코사인 값의 단위가 다르기 때문입니다.

다음 설계 · 설계안

비정형 문서 검색에 맞게 앞단을 다시 설계한다

core는 FAQ, 법령, 공지를 한 통에 넣은 통합 검색 성격이라 이번 타겟(비정형 문서 검색)에 맞지 않습니다. 원천 DB가 더러워지면 컷오프와 판정 LLM 같은 안전장치도 무력해집니다.

  1. 문서 카테고리 판별비정형 문서 범주에 드는가
  2. 정제범주 밖과 중복을 제외
  3. 청킹유진 씨와 기준 협의
  4. 메타데이터 부착카탈로그·분류체계: 문서 유형(규정, 지침, 사업계획서 등)
  5. 색인·필터 검색유형 필터로 후보를 먼저 좁힘
  • 색인에는 시행일과 폐지일 필드가 이미 있고 검색 시점에 필터로 쓰입니다. 문서 유형 필드는 새로 추가해야 합니다.
  • SPLADE 도메인 확장: 전략물자 어휘로 확장·재학습할 수 있는지 확인합니다. CPU 학습은 약 16시간으로 예상(세부 조건 불명확)되어 증분 학습, 별도 학습 서버, 주 1회 학습을 검토합니다.
말하기이 장은 설계안입니다. 구현된 것이 아닙니다.
